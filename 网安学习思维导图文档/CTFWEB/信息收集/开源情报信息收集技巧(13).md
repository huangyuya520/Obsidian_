1. ==微信“搜一搜”定向语法与关键词拓扑==

微信搜一搜对小程序支持模糊匹配与前缀索引，但默认算法倾向于推送高日活、完成微信认证的正式服务。针对网络安全分析，需要主动构造关键词拓扑来突破推荐算法限制。



精准分类与层级检索

- **锁定垂直分类**：在搜索主界面明确点击“小程序”标签栏，剔除朋友圈、文章、视频号等噪点数据。
    
- **主体衍生与地理维度挖掘**：大型企事业单位、高校和金融机构通常由各地方分局、子公司或院系独立采购系统。
    
    - _语法结构_：`[目标简称/全称] + [地名/分支机构]`（如：`XX集团 浙江`、`XX银行 信用卡中心`、`XX大学 学院/后勤`）。




影子资产与内部系统特征词库

企业开发者常将内部协同、现场运维或早期测试系统托管在微信端，这类资产通常不会在官网公开，但名称往往带有强规律性后缀：

|**资产类型**|**核心挖掘词缀组合**|
|---|---|
|**协同与办公**|`[目标] + 协同` / `打卡` / `审批` / `OA` / `移动端` / `助手` / `工作台`|
|**运维与管理**|`[目标] + 管理` / `后台` / `运维` / `看板` / `监控` / `数据中心` / `CRM`|
|**测试与开发**|`[目标] + 测试` / `体验` / `预发` / `demo` / `dev` / `test` / `beta` / `试运行`|
|**供应链与招采**|`[目标] + 供应商` / `招采` / `渠道` / `服务商` / `商户版` / `仓储`|


2. ==公众号与矩阵资产的“以号探端”技术==
微信生态中，服务号/订阅号与小程序天然具备主体绑定与业务导流机制，通过公众号挖掘小程序是发现核心与衍生资产的关键路径。



公众号资料页的“相关小程序”

进入目标认证公众号的资料页面（点击头像进入主页 -> 点击“全部消息”旁的“...”或直接查看主体简介），微信会直接列出该账号关联展示的**相关小程序列表**。这是官方授权展示的最直接关联资产集合。





历史推文与废弃资产嗅探

部分测试版小程序或早期业务系统可能仅在公众号早期的宣传推文中发布过体验二维码或链接，后期因业务调整虽不再推广，但后端 API 仍未下线。

- 在公众号主页的“搜索历史文章”功能中，输入关键词：`小程序`、`扫码体验`、`抢先体验`、`上线试运行`、`内测`。
    
- 重点关注发布于 2–3 年前的早期推文，提取文中的小程序卡片或太阳码（小程序码）。





自定义菜单与回复规则分析

- 逐级排查公众号底部的一级与二级自定义菜单，大量业务入口直接封装为小程序唤起行为（`miniprogram` 动作类型）。
    
- 尝试在公众号对话框中发送关键词触发自动回复（如回复：`客服`、`系统`、`入口`、`登录`、`打卡`），有时会自动推送非公开小程序的卡片。



3. ==微信后台“穿透式”检索技巧（高价值盲区挖掘）==
在常规微信客户端搜索时，算法会根据搜索热度和小程序设置进行过滤，导致很多未公开或未认证的小程序不可见。**利用微信公众平台管理后台的反查功能，可以直接突破该限制。**


利用公众号后台的“关联小程序”接口

1. 注册并登录任意一个个体或企业微信公众号后台（`mp.weixin.qq.com`）。
    
2. 进入 **广告与服务** 或 **小程序管理** -> **关联小程序**。
    
3. 在弹出的检索框中输入**目标企业的全称**或**营业执照注册名称**。
    
4. **效果**：该接口具有极高的系统级检索权限，能够按主体维度直接检索出该主体名下已提交注册的多个小程序名称及部分基本信息，甚至包括在客户端搜索框中排名极低、未开通搜索服务或名字非常晦涩的内部系统。



图文消息嵌入搜索

在微信公众号后台的“图文编辑”界面，选择插入“小程序卡片”，在此输入目标的 **AppID**、**小程序名称** 或 **关键词**，系统会以联想列表的形式展示匹配结果，是验证小程序是否存在及其精确名称的高效途径。




4. ==主体资质穿透与全网资产联动==

提取主体信息进行反向股权穿透

在微信端打开任何一个小程序：

1. 点击右上角“...” -> 点击小程序名称（查看关于该小程序） -> **服务及主体信息**。
    
2. 提取其 **主体名称**（企业/组织法人全称）。
    
3. 将此主体名称带入商业情报工具（天眼查、企查查、爱企查、小蓝本）的“知识产权 -> 微信小程序”模块，进行双向验证。
    
4. 查看该企业是否有其他全资子公司、控股控股平台，再将子公司名称带回微信进行二次搜索循环。




AppID 资产指纹映射

在逆向或抓包过程中如果拿到小程序的 `AppID`（格式为 `wx` 开头的 18 位字符串，如 `wx1234567890abcdef`）：

- 使用 Google、Bing 或网络空间搜索引擎（FOFA、Hunter）进行跨平台特征检索：
    
    - `body="wx1234567890abcdef"`
        
    - `site:github.com "wx1234567890abcdef"`
        
- 往往能顺藤摸瓜检索出开发者的开源前端项目、微信开放平台配置文件或配置在外部 Web 站点的鉴权接口。




5. ==小程序收集阶段的关键要素梳理==

在完成微信搜索与收集后，需要为每个目标资产建立情报档案：

- **基础属性**：小程序名称、原始 ID（`gh_` 开头）、AppID（`wx` 开头）、主体所属公司、认证状态、类目类型。
    
- **业务边界**：是面向公众的业务（C端），还是面向企业内部/员工（B端/E端）。
    
- **技术特征预判**：是否基于微信云开发（CloudBase）、是否存在三方 SaaS 代开发标记（如显示服务商资质），以便评估后续流量抓包或 PC 端解包审计的切入路径。

## 黑暗浏览器
在网络安全与开源情报（OSINT）分析中，常被俗称为“黑暗浏览器”或“黑暗搜索引擎”的工具，在专业领域内通常指代**网络空间测绘引擎（Cyberspace Search Engines）**（如 FOFA、Shodan、Hunter、ZoomEye、Censys 等）。与索引网页超文本内容的传统搜索引擎不同，网络空间测绘引擎持续抓取全球 IPv4/IPv6 协议栈的端口响应、服务指纹及加密证书，==是进行被动子域名探测与影子资产（Shadow IT）发现的高价值渠道。==



1. ==核心挖掘维度与检索逻辑==

通过空间测绘引擎收集子域名的核心逻辑在于：**利用服务协议中残留的域名引用（如 SSL/TLS 证书、HTTP 标头、页面跳转规则等），反向聚合属于同一目标组织的所有解析记录。**



维度一：SSL/TLS 证书扩展字段（SAN）穿透

现代 Web 架构中，证书通常包含使用者备用名称（Subject Alternative Name, SAN）。当企业申请一张多域名或通配符证书时，该证书对应的所有子域通常会完整记录在 SAN 属性中。

- **检索原理**：搜索证书中颁发给目标根域名的全部资产。
    
- **常用语法示例**：
    
    - **FOFA**：`cert="example.com"` 或 `cert.subject="example.com"`
        
    - **Hunter (鹰图)**：`cert.subject="example.com"` 或 `cert="example.com"`
        
    - **Shodan**：`ssl.cert.subject.CN:"example.com"` 或 `ssl:"example.com"`
        
    - **Censys**：`services.tls.certificates.leaf_data.names: "example.com"`
        
- **优势**：不仅能挖掘当前存活的子域名，还能发现配置了相同证书但解析在内网、云端测试环境或非标端口上的影子子域。




维度二：Host 标头与 DNS 映射

测绘节点在发起探测时，会记录 HTTP 请求返回的 Host 信息以及服务所绑定的域名解析关系。

- **检索原理**：过滤特定主域下的所有 Hostname。
    
- **常用语法示例**：
    
    - **FOFA**：`domain="example.com"` 或 `host="example.com"`
        
    - **Hunter**：`domain="example.com"`
        
    - **Shodan**：`hostname:"example.com"`

- **排噪技巧**：使用布尔逻辑剔除已知高频资产，让边缘未纳管资产浮出水面：
    
    - `domain="example.com" && host!="[www.example.com](https://www.example.com)" && host!="api.example.com"`




2. ==基于系统指纹的“同源”反向推导==

除了直接匹配域名字符串，通过系统特征哈希与环境指纹同样能够反推出属于目标机构但未在常规 DNS 字典中的子域名。


Favicon 图标哈希聚合（Icon Hash）

企业旗下不同业务线的子系统（如 OA、单点登录 SSO、Gitlab、VPN 网关）常使用带有统一企业标识的 favicon 图标。

1. **提取 Hash**：获取目标主站或已知子站的 `favicon.ico`，通过 MurmurHash3 算法计算其 Hash 值。
    
2. **全局搜索**：
    
    - **FOFA**：`icon_hash="-123456789"`
        
    - **Shodan**：`http.favicon.hash:-123456789`
        
    - **Hunter**：`web.icon=="-123456789"`

3. **效果**：能够迅速检索出全网部署了该图标的所有子域名和 IP 资产，尤其适用于穿透使用了 CDN 隐藏的子系统。



特征响应头与 HTML 结构追踪

部分内部测试子域可能未绑定主域名证书，但在源码中引用了主站资源或返回了特有的响应标头。


|**检索特征**|**场景说明**|**语法构建策略**|
|---|---|---|
|**Set-Cookie 域作用域**|身份认证系统下发的 Cookie 通常将 `domain` 设置为根域|`header="Set-Cookie: .example.com"`|
|**跨域与资源引用**|页面加载了主域静态资源或配置了跨域策略|`body="static.example.com"` 或 `header="Access-Control-Allow-Origin: *example.com"`|
|**特定产品标识**|内部自研系统特定的版权声明或技术框架标记|`body="© 2026 Example Corp" && body="Subsystem"`|




3. ==高级探测策略与多引擎交叉验证==

探测非常规端口与协议

传统的 DNS 爆破仅验证子域名是否存在，无法直接获知业务开放端口。空间测绘平台能够直接呈现子域绑定的非标准 Web 端口及私有协议：

- **重点关注端口**：`8080-8090`（开发测试环境）、`8443`（备用 HTTPS）、`9000`（内部服务）、`3000`（Grafana/前端调试）、`8888`（宝塔/面板管理）。
    
- **语法示例**：`domain="example.com" && port!="80" && port!="443"`。




历史数据比对与失效资产识别

部分测绘平台（如 Censys、Shodan）保留历史时间序列数据：

- **废弃系统识别**：检索历史存在但当前解析到公有云 CNAME（如 AWS S3、GitHub Pages、CloudFront 等）的子域名，排查是否存在子域名接管（Subdomain Takeover）风险。
    
- **历史 IP 反查**：通过历史快照定位该子域名在未使用 CDN 前的源站真实 IP。




4. ==防御与资产收敛建议（攻击面管理）==
在防御视角下，安全团队应利用上述测绘逻辑进行主动资产盘点：

- **证书暴露面管控**：避免在通配符或全局证书的 SAN 列表中写入敏感内部系统命名（如 `stg-pay.internal.example.com`），内部业务建议使用专用内网 CA 签发证书。
    
- **废弃 DNS 记录清理**：定期对公网 DNS 解析进行自动化扫描，对不再使用的子域名执行彻底注销，防止因指向失效第三方服务造成资产劫持。
    
- **外网访问控制**：将测试、预发（Staging）、管理后台类子域名收敛至内网或零信任（Zero Trust）网关之后，禁止暴露在公网 IP 端口。

# ICON 信息收集
在网络情报信息收集（OSINT）与外部攻击面管理（EASM）中，==**ICON（Favicon）信息收集**是一种基于 Web 应用程序图标指纹进行资产聚合与溯源的高效技术。==

由于企业往往会在内网系统、云上测试环境、各分公司业务系统中使用相同或相似的品牌图标，而许多通用中间件、开源框架以及 C2 基础设施也自带默认的图标指纹，Icon Hash 可以绕过域名解析与常规关键字限制，实现“同源”资产的大规模穿透。


1. ==核心计算原理与哈希机制==

网络空间测绘引擎对图标建立索引时，通常不直接存储图像文件，而是将图像数据处理为固定长度的哈希值。


MurmurHash3 算法规范（FOFA / Shodan）

空间测绘引擎（如 Shodan、FOFA）主要采用 **MurmurHash3 (32-bit signed)** 算法。其标准化处理流程包含关键的数据格式化要求：

1. 获取原始 `favicon.ico` 文件的二进制数据。
    
2. 将二进制数据进行标准 **Base64** 编码。
    
3. **关键细节**：遵循 RFC 2045 规范，每 76 个字符后必须追加一个换行符 `\n`（这是许多自定义脚本因哈希值不匹配而失效的根本原因）。
    
4. 对添加了换行符的 Base64 字符串计算 32 位有符号 MurmurHash3 值（数值范围：$-2^{31}$ 至 $2^{31}-1$）。


除了 MurmurHash3，部分引擎（如 360 Quake、Hunter）同时支持基于文件内容的原始 **MD5** 或 **SHA256** 哈希。



2. ==主流空间测绘引擎查询语法对照==

获取图标的 Hash 值后，可将其代入各大网络空间测绘平台进行全局资产拓扑扩展：

| **平台**          | **语法格式**                                            | **说明**              |
| --------------- | --------------------------------------------------- | ------------------- |
| **FOFA**        | `icon_hash="-1541334860"`                           | 支持负数有符号 MurmurHash3 |
| **Shodan**      | `http.favicon.hash:-1541334860`                     | 标准 MurmurHash3 语法   |
| **Hunter (鹰图)** | `web.icon=="-1541334860"` 或 `web.icon_md5=="<MD5>"` | 支持 MurmurHash 与 MD5 |
| **360 Quake**   | `favicon:"<MD5>"`                                   | 默认采用图标内容的原始 MD5     |
| **ZoomEye**     | `iconhash:"<Hash>"`                                 | 支持图标指纹检索            |


3. ==四大核心实战应用场景==

场景一：穿透 CDN / WAF 定位源站真实 IP

- **技术痛点**：目标主站启用了 Cloudflare、Akamai 等 CDN 或高防 WAF，导致无法直接获取源站服务器 IP。
    
- **收集手法**：
    
    1. 下载主站被 CDN 缓存的 `favicon.ico` 并计算 Hash。
        
    2. 在测绘引擎中直接搜索该 Hash，过滤掉已知 CDN 服务商的自治系统号（ASN）：
        
        - `icon_hash="<Hash>" && asn!="13335"`（排除 Cloudflare）
            
    3. 检索结果中返回的独立公网 IP，极大概率是直接对外开放了 Web 服务的真实源站、备用节点或历史开发服务器。


场景二：挖掘影子资产（Shadow IT）与分支机构系统

- **特征沉淀**：大型集团企业下属分支机构、各业务条线（如 OA、CRM、ERP、招投标平台、开发环境）通常沿用统一的 UI 规范，使用带有企业企业标识的图标。
    
- **收集手法**：
    
    - 使用图标 Hash 配合否定语法剔除已知的主域名，使隐蔽资产浮出水面：
        
        - `icon_hash="<Hash>" && domain!="target.com"`
            
    - 这样可以定位到直接使用公网 IP 绑定的内部管理后台、挂载在云服务商二级域名（如 `*.aliyuncs.com`、`*.s3.amazonaws.com`）上的边缘资产。




场景三：中间件与标准框架指纹识别

大量开源应用与企业级系统在交付或部署时，管理员未替换默认的 Favicon。通过这些默认图标的 Hash，能直接锁定特定软件系统：

|**典型组件 / 框架**|**默认图标特征**|**典型暴露面**|
|---|---|---|
|**Spring Boot**|标志性的“绿叶”图标|默认暴露的 Actuator 监控端点|
|**Apache Shiro**|特定的蓝色/白色标志|身份认证模块与反序列化组件|
|**若依 (RuoYi) 管理系统**|默认的 RY 标志|登录入口、通用后台框架|
|**Nacos**|阿里云 Nacos 默认图标|微服务注册中心与配置中心|
|**Jenkins**|经典管家图标|CI/CD 持续集成构建平台|



场景四：威胁情报与恶意资产基础设施追踪

- **红队 C2 追踪**：Cobalt Strike、Metasploit 等在配置特定 Listener 或伪装 Web 页面时，有时使用固定的默认模板图标。
    
- **钓鱼攻击排查**：监控攻击者针对企业品牌搭建的钓鱼网站。将企业官方图标 Hash 作为监控规则，全网匹配与官方域名、备案不符的新增 IP，即可提前捕获正在筹备中的钓鱼站点。



4. ==图标发现与资产提取工作流==

在目标站点中定位图标路径时，不能仅依赖于根目录的 `/favicon.ico`，现代单页应用（SPA）与微前端通常有更复杂的引用机制：

1. **HTML 标签解析**：检查页面源代码中的 `<head>` 区块，匹配以下标签：
    
    - `<link rel="icon" href="...">`
        
    - `<link rel="shortcut icon" href="...">`
        
    - `<link rel="apple-touch-icon" href="...">`
        
2. **多级目录探测**：
    
    - `/favicon.ico`（根路径）
        
    - `/static/favicon.ico` 或 `/assets/icon.png`
        
    - 后台登录接口路径下的专属图标（如 `/admin/login/favicon.ico`）
        
3. **自动化提取工具**：
    
    - **FavFreak**：通过管道接收子域名列表，批量探测各站点的 Favicon 并自动去重聚类。
        
    - **浏览器插件**：利用 FOFA Pro View、Shodan 插件直接在访问页面时一键提取并跳转搜索。

---

5. ==局限性与对抗防御建议==

- **哈希碰撞风险**：极简单的纯色小图标（如 16x16 纯白图标）或完全透明的 PNG 可能会引起全网大规模误报。使用前先验证基线结果数量。
    
- **防御侧配置建议**：
    
    - **统一自定义图标**：将所有外网暴露系统的默认中间件图标替换为无辨识度的空白占位符或企业标准且已做混淆的图标。
        
    - **动态加载或移除内网图标**：内部协同办公、预发环境禁止部署与公网主站完全一致的高清矢量图标，切断指纹聚合链条。
        
    - **源站严格回源**：在真实源站前部署 CDN/WAF 后，严格配置安全组规则，禁止源站对外响应任意非 CDN 来源的直接 IP 请求。

## 补：网盘信息收集
在网络空间安全与开源网络情报（OSINT）分析中，网盘信息收集的核心逻辑在于：挖掘内部人员在非合规协作、远程办公或跨端传输时，==通过公网网盘共享产生的未加密、弱受控或长期有效的公开链接，从中提取敏感凭证、系统资产及业务数据。==


==一、 核心收集途径与检索技巧==
1. 搜索引擎高级语法（Search Engine Dorking）

搜索引擎爬虫常会收录大量公开的网盘分享页面。通过针对特定网盘服务商的域名特征与敏感内容特征组合查询，能够快速定位泄露入口。

- **主流网盘特征语法组合：**
    
    - 百度网盘：`site:pan.baidu.com intext:"目标企业名称" ("密码" | "提取码" | "内部" | "配置")`
        
    - 阿里云盘：`site:alipan.com intext:"目标域名" ("备份" | "vpn" | "密钥")`
        
    - 腾讯微云：`site:share.weiyun.com intext:"目标关键词"`
        
    - 海外网盘（Google Drive / OneDrive）：`site:[drive.google.com/drive/folders](https://drive.google.com/drive/folders) "目标组织" filetype:xls` 或 `site:onedrive.live.com "内部资料"`

- **拓展文件类型限制：** 利用 `filetype:zip`、`filetype:sql`、`filetype:ovpn`、`filetype:docx`、`filetype:xlsx` 针对性过滤压缩包、数据库转储、VPN配置文件及表格。




2. 第三方网盘聚合引擎与快照平台

由于官方网盘通常具有一定的反爬与索引限制，专门针对网盘链接进行长期抓取与存储的第三方聚合平台是重要的情报源：

- **聚合爬虫引擎：** 各类专门收录百度网盘、夸克、迅雷、阿里网盘的第三方索引站。这些站点常带有全网共享文件的抓取记录。
    
- **历史快照检索：** 使用网络历史档案馆（如 Wayback Machine）查询目标企业已失效但曾被归档的网盘链接页面，常能恢复被撤销分享的文件名、目录层级甚至元数据。






3. 代码托管与协作平台的暗连挖掘

大量网盘链接并非直接公开在网盘首页，而是附带提取码被写入各类代码与文档协作平台：

- **代码仓库检索：** 在 GitHub、Gitee、GitLab 中搜索 `目标域名 "pan.baidu.com" "提取码"` 或 `目标关键词 "alipan.com"`。开发人员常将超大依赖包、脱敏测试库、离线补丁打包放在网盘，并在 README 或 Commit 备注中公开链接与密码。
    
- **知识库与文库：** 语雀、飞书公开文档、Notion 页面、CSDN、博客园等，常有离职员工或供应商留下的项目资料分享链接。




4. 共享“云端密码库”机制与客户端插件

部分网盘助手类浏览器插件（采用类似“Wi-Fi万能钥匙”的众包共享逻辑），在用户输入提取码打开网盘时，会将提取码同步至插件服务商的云端数据库。在分析受密码保护的链接时，部分专业情报分析工具可通过调用此类众包数据库接口，检索对应链接的历史已知提取码。



==二、 重点情报字段与敏感数据分类==

获取到网盘链接后，情报梳理应重点围绕以下四类高价值数据展开：

|**数据类别**|**典型文件特征**|**情报价值与潜在风险**|
|---|---|---|
|**接入凭据类**|`.ovpn`、`.rdp`、`passwords.xlsx`、`token.txt`|直接获取企业 VPN、堡垒机、内网系统的访问身份|
|**架构与配置类**|`拓扑图.vsdx`、`nginx.conf`、`application.yml`|暴露内部 IP 段分布、中间件版本、云服务 AccessKey|
|**系统备份与源码**|`backup_2026.sql`、`dist.zip`、`src.tar.gz`|获取全量业务逻辑、未修补漏洞、脱机离线审计条件|
|**人员与组织信息**|`通讯录.xlsx`、`排班表.docx`、`考勤记录.pdf`|收集高管/运维邮箱、手机号及部门归属，用于社工与钓鱼画像|





==三、 关联分析与反向追踪（Profiling）==

找到单个网盘文件仅是起点，利用 OSINT 思维进行链式扩展往往能扩大战果：

1. **分享者主页拓扑挖掘：** 点击分享者的网盘主页，查看其“全部公开分享”，通常同一个人会上传同一项目的多个批次数据或个人日常文件。
    
2. **用户名/ID 跨平台关联：** 提取网盘所有者的昵称、数字 ID 或个性域名，在各大社交平台、技术论坛（V2EX、知乎、贴吧）检索同名账户，反向定位该员工在企业内部的真实岗位与技术方向。
    
3. **文档元数据（Metadata/EXIF）取证：** 下载 Office 或 PDF 文件后，读取其内置属性中的 `Author`、`Company`、`Last Modified By` 以及软件版本号，能够补充目标内部环境使用的办公软件版本和员工姓名拼音。







==四、 企业防范与数据防泄漏（DLP）治理建议==

针对上述情报收集手法的防御，需在组织内部建立严格的数据流转机制：

- **网络出口管控：** 在内网防火墙、网络网关侧阻断未授权的个人网盘（如百度网盘、夸克等）的上传流量，仅开放已过白名单的企业级云协同网盘。
    
- **分享权限强制约束：** 企业云盘须强制设置分享有效期限（如最长 7 天）、随机高强度提取码，并禁用“全网公开免密访问”。
    
- **主动泄漏情报监控：** 安全团队应建立自动化关键词监控任务，定期使用 Dork 语法及网盘聚合接口对企业品牌名、核心系统名、员工常用格式进行轮询排查，发现泄露立即向服务商申请下线封禁。

# EDU 挖掘信息收集
在教育行业漏洞响应平台（EDU SRC）的资产收集与情报整理中，高校及教育机构的网络环境具有**资产体量庞大、层级分散、历史遗留系统多、外包/科研项目独立性高**等显著特征。

==构建清晰的资产攻击面地图（Attack Surface Mapping），通常遵循以下核心流程与方法。==



==一、 明确边界：组织架构与从属机构梳理==

教育机构通常不仅仅包含主校区域名，还往往拥有大量直接挂靠或间接关联的机构。在收集前需明确测试范围，理清产权与运维归属：

1. **多级机构下钻：**
    
    - **二级学院与研究所：** 计算机系、物理所、重点实验室等，通常拥有独立的服务器与二级域名，甚至自行搭建了未纳管的科研平台。
        
    - **附属机构：** 附属中小学、附属医院、校办企业、后勤集团、校友会。各附属单位的 IT 资产可能完全独立部署。
        
    - **异地校区与分校：** 许多高校在不同城市设有分校区或研究生院，其网络出口与 IP 资产通常独立。

2. **资产归属查询工具：**
    
    - 通过学校官网的“机构设置”、“院系设置”、“产学研合作”页面获取官方实体名单。
        
    - 通过国家企业信用信息公示系统或商业信用平台，查询学校出资控股的企业与社会组织。



==二、 域名与网络拓扑测绘==

高校域名多以 `.edu.cn` 结尾，其命名规则往往具有高度的规范性与继承性。

1. 多级子域名扩展

高校的子域名层级普遍较深（常达 3~5 级，如 `*.lab.cs.xxx.edu.cn`）：

- **证书透明度（CT Logs）：** 查询历史与现存 SSL/TLS 证书（如 crt.sh），获取大量已停用但未下线内网映射的主机名。
    
- **DNS 字典爆破与递归解析：** 针对教育网命名习惯设计字典（如 `jw`、`cwc`、`lib`、`cas`、`vpn`、`mail`、`yjs` 等常用缩写），并对二级域名开展下一级域名的递归爆破。
    
- **历史解析记录：** 通过公开 DNS 数据集与威胁情报平台检索历史 A 记录，发掘迁出或边缘资产。


2. IP 段与自治系统（ASN）归属

大多数公立高校作为中国教育和科研计算机网（CERNET）的接入单位，拥有连续的独立公网 IP 地址段：

- **Whois 与 ASN 查询：** 检索高校的英文简称或 CERNET 分配记录，提取高校名下的整段 Class B 或 Class C 地址（如 `/16` 或 `/24` 掩码段）。
    
- **出口 IP 确认：** 观察高校核心官网、邮件服务器及权威 DNS 的 IP 分布，验证核心 IP 网段范围。
    
- **旁站与反向解析：** 对确认归属于学校的 IP 地址段进行全端口与存活 Web 服务探测，排除 CDN 干扰，直接定位源站与边缘设备。



==三、 网络空间测绘与指纹识别==

通过网络空间测绘引擎（如 FOFA、Hunter、Quake、Shodan 等），可以批量聚合目标学校的 Web 与网络设施。

常用检索语法构建维度：

- **主体单位与证书：** `cert="高校名称"` 或 `cert="xxx.edu.cn"`
    
- **主域聚类：** `domain="xxx.edu.cn"`
    
- **标题与图标特征：** `title="xx大学"` 或 `icon_hash="xxxx"`（针对统一身份认证 CAS、门户站点的 Favicon 计算哈希）
    
- **正文版权特征：** `body="版权所有 © xx大学"` 或 `body="备案号"`



==四、 敏感信息与外部泄露源检索==

教育网络运维人员更迭频繁，项目多由学生团队或短期外包维护，因此在外部代码与公共文档平台中常有配置泄露。

1. **代码托管平台泄露（GitHub / Gitee）：**
    
    - 搜索学校简称、统一身份认证域名、教务系统关键字。
        
    - 重点监控：数据库配置文件、测试用账号密码、API 接入密钥、学籍/排课脚本。

2. **文库与公网网盘检索：**
    
    - 检索网络中心或信息化办公室上传的“VPN配置手册.pdf”、“新教职工上网指南.docx”、“统一身份认证对接方案.pdf”。
        
    - 此类文档往往直接披露了内网网段划分、初始密码规则（如身份证后六位）、测试账号甚至网络拓扑图。

3. **开源软件与通用 CMS 指纹识别：**
    
    - 高校网站多采用站群系统（如苏迪、博达、捷成等定制 CMS）或开源教学管理系统（如 Moodle、Canvas）。
        
    - 识别出特定的站群架构后，可通过同版本特征进行横向资产聚类。




==五、 典型 EDU 资产分布与信息特征==

|**资产类型**|**典型域名/端口特征**|**情报收集价值与关注点**|
|---|---|---|
|**统一身份认证 (CAS/SSO)**|`cas.*`、`auth.*`、`sso.*`|全校单点登录入口，关注密码找回逻辑、默认弱口令策略及接口设计|
|**教务与教学管理系统**|`jw.*`、`jwc.*`、`aao.*`|包含大量师生档案与成绩数据，通常为成熟商业系统，关注历史版本与补丁情况|
|**财务与招标采购平台**|`cwc.*`、`cw.*`、`gzc.*`|涉及资金结算、票据打印，常部署较老的专用中间件|
|**网络基础设施与网关**|`vpn.*`、`portal.*`、`ras.*`|SSL-VPN、深信服/天融信网关、上网认证 Portal 页，关注未授权接口与补丁更新状态|
|**边缘科研与实验室站点**|`*.lab.*`、独立 IP 绑定非标端口|通常缺乏专业安全运维，易存在测试接口、Debug 页面暴露、历史备份未清理等问题|


==六、 合规准则与 SRC 漏洞挖掘边界==

在参与 EDU SRC 及教育系统安全响应时，应始终恪守白帽合规红线：

- **遵循最小必要原则：** 仅验证漏洞的存在性（Proof of Concept），严禁越权脱库、读取师生敏感个人信息或下载涉及国家安全的科研数据。
    
- **业务不可中断：** 严禁使用高并发压测工具、拒绝服务（DoS）或未经验证的破坏性 Exp 对教务抢选课、高考招生、财务等关键生产系统造成干扰。
    
- **规范提报流程：** 发现问题后，通过官方教育行业漏洞报告平台或机构官方 SRC 提报，严禁私自公开漏洞细节、买卖数据或利用其牟利。

# CNVD 证书信息收集
CNVD（国家信息安全漏洞共享平台）的信息收集与常规企业 SRC 或教育 SRC 存在本质差异。CNVD 的漏洞审核高度依赖“收录准则”**，==主要分为两大路径：** 通用型软件漏洞 **（要求具有通用性、影响范围广、厂商注册资本等符合标准）与**事件型重点单位漏洞（要求目标具备重要行业属性、骨干单位或注册资本达到门槛）。==

==因此，CNVD 的情报收集必须紧扣其收录标准，将资产挖掘与合规资质审查深度结合。==



==一、 资质与边界核查（前置情报过滤）==

在投入技术探测前，必须先确认目标实体是否满足 CNVD 的收录门槛，避免无效挖掘：

1. **企业规模与注册资本核验：**
    
    - **准则要求：** 厂商或涉事单位通常要求**注册资金在 5000 万人民币以上**（重要行业如党政机关、大型央企、金融能源机构不受此限）。
        
    - **核查渠道：** 国家企业信用信息公示系统、天眼查、企查查、爱企查。
        
    - **关键信息提取：** 注册资本、实缴资本、法定代表人、分支机构、100%控股子公司、软件著作权（软著）。

2. **软件著作权与知识产权分析（通用型专用）：**
    
    - 查询软件厂商的“软件著作权登记列表”，确认系统确系该厂商独立研发，而非二次打包开源产品。
        
    - 获取软件的官方全称、简称、版本命名规则（如 `XX协同办公管理平台 V8.0`），这直接决定了提报时漏洞命名的准确性。

3. **ICP 备案与主办单位确认（事件型专用）：**
    
    - 通过工信部 ICP/IP 地址/域名信息备案管理系统或综合查询工具，确认资产的域名主办单位与目标机构法人一致，排除关联外包商自建系统的干扰。



==二、 通用型漏洞（Product-Type）资产收集与全网指纹测绘==

通用型漏洞审核的核心在于**证明其影响的广泛性**（CNVD 通常要求提供至少 10 个以上互联网可访问的独立真实应用案例证明通用性）。

1. 软件特征指纹（Fingerprint）提炼

若要批量定位通用软件的实例，必须首先提取其独特的静态指纹：

- **Favicon Hash：** 计算系统登录页小图标的 MurmurHash 值，网络空间测绘引擎对此类特征识别率极高。
    
- **特定静态路径与特征文件名：** 厂商自研框架特有的 JS/CSS 路径（如 `/resource/js/core.js`、`/ui/login/login.css`）、API 接口（如 `/api/sys/version`）、特定页面标题（Title）模式。
    
- **响应标头与 Cookie 名称：** 特定中间件或系统框架设置的私有 HTTP Header 或 Session 标识符（如 `JSESSIONID_XXX`）。
    
- **页面版权与技术支持声明：** HTML 源码底部的 `Powered by XXX`、`技术支持：某某科技有限公司`、`软件版本号`。




2. 空间测绘语法构建与实例聚合

利用网络空间测绘引擎（FOFA、Hunter、Quake、Shodan、ZoomEye）构建组合语法，精准检索满足案例数量要求的真实应用：

例：
```
# 结合厂商版权与特征路径
body="北京某某科技有限公司" && body="/custom/login.jsp"

# 结合 Favicon 散列与专属系统标题
icon_hash="-192837465" && title="协同办公平台"

# 过滤 CDN 与无效节点，锁定独立 IP 与真实服务
app="某某OA" && country="CN" && status_code="200"
```


3. 安装包、文档与演示环境获取

为了完成漏洞分析与报告编写，需要获取目标系统的运行机制或代码实现：

- **官方演示站（Demo）：** 厂商官网常提供 `demo.vendor.com`、`test.vendor.com` 供潜在客户试用，通常开放了完整的管理端界面与最新补丁环境。
    
- **实施文档与操作手册：** 利用 Google Dorking 搜索 `filetype:pdf "系统部署手册" "目标软件名"` 或 `filetype:docx "默认初始密码" "目标软件名"`，获取系统架构、默认后台路径、初始弱口令规则。
    
- **客户端安装包逆向与固件解包：** 从官网服务支持中心、公网共享驱动库中下载客户端升级包、离线更新补丁或 IoT 固件（`.bin`），提取其嵌入的前端代码、接口规范或二进制组件。



==三、 事件型漏洞（Event-Type）资产攻击面收集==

事件型漏洞侧重于党政机关、省部级单位、关键信息基础设施（关基）、行业龙头企业的网络边界。

1. 组织股权穿透与资产聚合

- **纵向穿透：** 集团公司 → 全资子公司（100% 控股）→ 控股子公司（>51% 控股）。通常全资或绝对控股企业的核心业务资产认可度高。
    
- **横向梳理：** 集团下属的各业务线支撑系统、财务结算平台、数据共享平台、人力资源管理系统。


2. IP 骨干段与 ASN 归属测绘

- 大型机构（如国家电网、三大电信运营商、国有商业银行）拥有独立的自治系统号（ASN）和连续的 BGP IP 段。
    
- 查询其 ASN 编号下声明的全部 IPv4/IPv6 前缀网段，结合历史 DNS 反向解析（PTR 记录），直接定位不挂载域名、仅以 IP:Port 形式裸露在公网的核心业务系统与网络管理设施。


3. 供应链与第三方接入点情报

- 目标机构自身防护严密时，往往会因第三方供应商的运维暴露通道成为突破口。
    
- 重点检索带有目标特征的泛外联入口：
    
    - **远程接入点：** `vpn.target.com`、`portal.target.com`、堡垒机入口。
        
    - **外包项目测试环境：** `test.*`、`dev.*`、`staging.*`，此类子域常部署于公网云主机且缺乏安全防护。
        
    - **员工办公协同系统：** 邮箱系统、电子签章平台、视频会议系统网关。



==四、 情报整理与提报要素对比==

|**挖掘类型**|**核心收集侧重点**|**准入门槛验证指标**|**CNVD 报告必要情报要素**|
|---|---|---|---|
|**通用型漏洞**|系统指纹、特征全网分布、软件著作权归属|软件厂商实缴/注册资金（≥5000万）；软件为自主研发通用产品|1. 软件官方全称及精确版本号<br><br>  <br><br>2. 厂商官网与资质截图<br><br>  <br><br>3. 至少 10 个互联网独立活体案例（URL/IP）<br><br>  <br><br>4. 完整无害化复现 PoC 与修复建议|
|**事件型漏洞**|产权归属、组织架构层级、关键资产权重|涉事单位级别（党政机关/央企/重要行业/注资≥5000万企业）|1. 涉事单位全称及所属行业<br><br>  <br><br>2. 股权关系或 ICP 归属证明<br><br>  <br><br>3. 漏洞影响系统名称及具体 URL/IP<br><br>  <br><br>4. 证明漏洞存在且不涉及破坏的 PoC|



==五、 合规约束与测试边界==

CNVD 严格遵守国家漏洞管理规定，任何信息收集与漏洞复现行为必须恪守底线：

- **严禁越界探测与数据截留：** 验证存在性时，以打印系统版本、返回固定哈希或只读轻量系统配置为界，严禁拖取业务数据、读取用户敏感个人信息。
    
- **严禁破坏性验证：** 禁止针对生产环境使用自动化漏洞扫描器发起高并发攻击，禁止写入后门（Webshell）、篡改页面或实施任何可能导致系统拒绝服务的测试。
    
- **闭环披露原则：** 发现资产风险后应严格通过 CNVD 官方渠道提交并跟进厂商修复，严禁在第三方漏洞交易平台、社群或公开社交网络提前披露未修补细节。
