
# 开源情报常用搜索语法详解(1)

## 补：Dorking介绍
**Google Dorking**（通常简称为 **Dorking** 或 **Google Hacking**）是一种利用搜索引擎的高级搜索运算符与过滤语法，在公开索引的互联网数据中精准定位敏感信息、配置缺陷、暴露资产及潜在漏洞的技术。

在网络安全渗透测试与红蓝对抗中，Dorking 属于**被动信息收集（Passive Reconnaissance / OSINT）** 的核心手段之一。其最大特点是**不向目标服务器直接发送请求**，所有的查询均由攻击者或测试人员发往搜索引擎服务器，完全规避了目标端的入侵检测系统（IDS/WAF）告警。

==信息收集六大实战场景==

在渗透测试与授权信息收集阶段，Dorking 主要围绕资产测绘、暴露面发现和数据泄露探测展开：

1. 资产与子域名挖掘（Subdomain Enumeration）

通过排除主站或已知站点，快速发现组织未登记、被遗忘或测试性质的二级、三级子域：

例：
```
site:target.com -site:www.target.com -site:m.target.com
```



2. 目录遍历漏洞（Directory Listing）

当 Web 服务器（如 Apache/Nginx）开启了目录索引功能，攻击面即可直接暴露。利用默认标题语法快速检索：

例：
```
site:target.com intitle:"Index of /"
site:target.com intitle:"Index of /" "parent directory"
```



3. 配置文件与敏感凭据泄露

开发者或运维人员失误将包含数据库账号、API 密钥或私钥的配置文件放置在公网目录：

例：
```
site:target.com filetype:env "DB_PASSWORD"
site:target.com filetype:sql ("password" | "pass" | "passwd")
site:target.com ext:yml | ext:yaml intext:"api_key"
```



4. 源码与备份文件暴露

网站更新或备份时留下的临时压缩包、代码仓库元数据未做访问限制：

例：
```
site:target.com ext:bak | ext:old | ext:backup | ext:zip
site:target.com inurl:.git/config
```


5. 后台管理与未授权接口探测

搜寻未经有效边界防护的登录门户、管理后台与 API 文档界面：

例：
```
site:target.com inurl:login | inurl:admin | inurl:manage
site:target.com inurl:swagger-ui.html | inurl:v2/api-docs
```


6. 异常报错与日志分析

通过应用程序堆栈报错（Debug Trace）逆向探测网站后端架构、中间件版本甚至绝对路径：

例：
```
site:target.com intext:"SQL syntax error" | intext:"Warning: mysql_connect()"
site:target.com filetype:log intext:"exception"
```








==自动化工具与 GHDB 知识库==

- **GHDB（Google Hacking Database）**
    
    - 由安全专家 Johnny Long 发起，现由 Exploit-DB 维护。
        
    - 它是全球最大的公开 Dork 索引库，细分为十余个安全类别（如 _Sensitive Directories_、_Files Containing Passwords_、_Vulnerable Servers_ 等），是构造高质量侦察语法的标准参考源。

- **跨引擎扩展（Engine Diversity）**
    
    - Dorking 不局限于 Google。**Bing**、**DuckDuckGo**、**Baidu** 同样支持部分语法，且因各家抓取策略不同，互补使用往往能发现被单一引擎过滤的目标。
        
    - _注：_ 类似于 FOFA、Shodan、Censys、Quake 的网络空间测绘引擎，属于**端口与协议级空间测绘**，虽然也是通过语法过滤，但底层数据来自全网端口主动扫描，与基于 Web 内容抓取的传统 Dorking 存在本质架构区别。

- **自动化采集**
    
    - 手动批量执行容易触发搜索引擎验证码（CAPTCHA）或 IP 封锁，实践中通常搭配自动化脚本（如 `Pagodo`、`Katana`）结合代理池与 API 进行合规资产测绘




==防御与治理方案（蓝队视角）==

消除 Dorking 暴露风险的核心在于**阻断收录**与**收敛暴露面**：

- **避免依赖隐藏 URL：** 严禁通过“无人知晓的隐蔽 URL”来代替权限控制，核心后台必须配置强制认证或白名单机制。
    
- **合理配置 `robots.txt`：** `robots.txt` 仅能约束合规爬虫，**不能用于隐藏敏感路径**。在 `robots.txt` 中写入 `/secret-admin/` 反而会成为攻击者最直接的情报源。
    
- **利用 Meta 标签与 HTTP 响应头：** 对私有页面返回 `X-Robots-Tag: noindex, nofollow` 标头，或在 HTML 中加入 `<meta name="robots" content="noindex">`。
    
- **搜索引擎清理：** 发生意外泄露时，使用各大搜索引擎提供的站长工具（如 Google Search Console URL Removal Tool）第一时间提交临时下线请求并清理快照缓存。
    
- **CI/CD 与资产巡检：** 在构建发布流程中加入敏感文件过滤规则，并定期在自动化资产清点中运行 organization-specific 的 Dork 巡检脚本




## 补：什么是搜索引擎
搜索引擎是==一种用于在互联网上查找和获取信息的软件系统或服务==。

### 核心工作原理

搜索引擎通过后台程序在互联网上自动采集信息，建立庞大的索引数据库。当用户输入关键词时，它会快速检索并按相关性排序展示结果。 [[1](https://baike.baidu.com/item/%E6%90%9C%E7%B4%A2%E5%BC%95%E6%93%8E/104812), [2](https://datawhalechina.github.io/easy-vibe/zh-cn/appendix/4-server-and-backend/search-engines), [3](https://developer.volcengine.com/articles/7420331601172627493)]

- **数据采集**：用特定程序（网络爬虫）抓取网页内容。

- **建立索引**：对抓取的内容进行分词和组织，存入数据库。

- **相关性排序**：根据算法计算匹配度，把最有用、最准确的结果排在最前面。


1. ==网络爬虫 / 蜘蛛（Spider / Crawler）==

爬虫是搜索引擎获取原始数据的触角。

- **发现与调度：** 爬虫从一组种子 URL（Seed URLs）出发，解析网页中的 `<a>` 标签、Sitemap 网站地图以及外部引荐链接，建立待爬取队列（URL Frontier）。
    
- **协议与渲染：** 爬虫发起 HTTP/HTTPS 请求拉取资源，现代高级爬虫（如 Googlebot）还内置了无头浏览器（Headless Chrome）内核，用于执行 JavaScript 动态渲染 SPA（单页应用）。
    
- **行为边界：** 爬虫默认受目标站点根目录下的 `robots.txt` 协议约束。但需注意：**`robots.txt` 是君子协定，无法起到任何实质性访问控制作用**，甚至常被安全人员反向利用来提取敏感路径。


2. ==预处理与倒排索引（Indexer & Parser）==

爬虫抓取回来的海量原始 HTML/JSON/文本无法直接被毫秒级检索，必须经过深度提炼：

- **结构化清洗：** 去除 HTML 标签噪声，分离出 `<title>`、Meta 标签、请求头特征（Headers）、正文文本、URL 路径以及文件元数据（EXIF、作者信息等）。
    
- **倒排索引（Inverted Index）：** 核心数据结构。传统索引记录的是“文档 A 包含单词 X、Y、Z”；而倒排索引记录的是“单词 X 出现在文档 A、C、F 的第几行第几个字符”。这使得数十亿网页的高级语法匹配能在几十毫秒内完成。


3. ==检索与排序引擎（Query Processor & Ranking）==

- 接收用户输入的关键词或运算符（Operators），经过自然语言处理（NLP）分词与布尔逻辑解析后，在倒排索引中做交集/并集运算。
    
- 结合链接图谱分析（如 PageRank）、语义关联度（Vector/Embedding 检索）以及权重算法，输出相关性最高的结果序列。



4. ==快照与缓存系统（Cache / Archive）==

- 搜索引擎在抓取网页时，会在自己的数据中心保存该网页在特定时刻的完整副本（Web Cache）。
    
- 即使源站宕机、文件被删除或目录被二次加密，安全分析人员依然可以通过搜索引擎快照回溯历史信息。







==常见分类==

- **通用搜索引擎**：面向全网，搜索范围广。比如 Google 搜索和百度。

- **垂直搜索引擎**：针对特定行业或领域。比如电商平台的商品搜索、本地生活服务搜索等。


==搜索引擎与浏览器的区别==

- **浏览器**：是用来打开和浏览网页的工具软件（如 `Chrome、Edge、Safari`）。

- **搜索引擎**：是运行在浏览器里的一个特定网站或服务，用来帮你找到你想去的网站（如百度、Bing）

### 为什么要使用Google Dorking
使用Google Dorking，我们还可以帮助google更好地了解我们希望对google得到什么样的搜索结果，从而帮助用户快速找到敏感信息，减少搜案结果中的不必要信息，提高搜索效率。

对于网络安全：
1、减少渗透测试的范围，加强渗透的针对性
2、能使渗透过程简洁高效，避免做一些无关的测试
3、提高渗透效率，扩展渗透思路和方法

### Google Dorhing搜索案例

典型用法：

1、找管理后台地址：

```
site:xxx.com intext:管理|后台|登录|用户名|密码|系统|账号
site:xxx.com inrul:login/admin/manage/manager/admin_login/system
site:xxx.com intitle:管理|后台|登录
```


2、找上传类漏洞地址：

```
site:xxx.com inurl:file
site:xxx.com inurl:upload
```

3、找注入页面：

```
site:xxx.com inurl:php?id=
```

4、找编辑器页面

```
site:xxx.com inurl:ewebeditor
```

5、查找网站中的在线文件夹

```
intitle:index of xxx
```




6、在网站中查找人员相关的信息

```
https://wwgoogle.com/search?q="michael+bazzell" "&tbs-cdr:1,cd min:
1/1/0"
```
`&tbs=:`     这个部分指示了搜索参数的开始。
`cdr:1`       这个部分代表”自定义日期范围“的意思，其中1表示启动自定义日期范围。这意味着你正在搜索一个特定的日期范围而不是搜索全部时间段的结果。

`cd min:1/1/0`     这个部分指定了开始日期，其格式是”年/月/日“
