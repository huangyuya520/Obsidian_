
# Twitter（X）情报收集
Twitter 是一种社交网络和微博服务，将大多数帖子限制为280 个字符。Twitter 报告称，2022 年，每天发布的 Twitter 帖子或“推文”超过5 亿条。推特被马斯克收购后，目前跟脸书类似，需要登录才可以进行检索。

在社交网络上拥有一个空的个人资料可能足以进行调查。然而，对于开源情报调查人员来说，你的调查账号缺乏个人详细信息可能会显得可疑。==众所周知，脸书会暂停不包含个人信息的账户，你的目标可能会在你开始狩猎后对你的公开信息进行反向 OSINT 研究。对于大多数情况，认为你应该在你的调查账号中填充最少的虚假细节。你永远不应该提供任何可能与你的真实身份有关的东西，比如兴趣、职业或地点。正因为如此，会很大程度上依赖于随机生成和人工智能生成的内容。==



开展 Twitter 情报收集，核心技术体系分为以下五个维度：

1. ==高级检索与布尔语法（Search Dorking）==
X 内置了强大的检索解析器，熟练组合操作符能从海量杂讯中精准过滤高价值线索：


| **操作符 / 语法**                     | **功能与说明**                   | **情报收集实战示例**                                 |
| -------------------------------- | --------------------------- | -------------------------------------------- |
| `"keyword"`                      | 精确词组匹配，不触发拼写自动校正            | `"remote code execution" "proof of concept"` |
| `from:user` / `to:user`          | 指定发推用户 / 定向回复的用户            | `to:TargetCompany "vulnerability" OR "leak"` |
| `@user -from:user`               | 收集所有提及该目标、但非本人发布的讨论         | `@target_analyst -from:target_analyst`       |
| `since:` / `until:`              | 精确时间段约束（格式严格为 `YYYY-MM-DD`） | `CVE-2026 since:2026-01-01 until:2026-03-01` |
| `url:domain.com`                 | 检索推文中包含的链接域名                | `url:github.com ("exploit" OR "0day")`       |
| `filter:links -filter:replies`   | 筛选含外部链接的原创推文（过滤杂乱回复）        | `APT41 filter:links -filter:replies`         |
| `min_retweets:N` / `min_faves:N` | 设定转发/喜欢下限，用于滤除机器刷屏噪声        | `Ransomware min_retweets:20`                 |
| `geocode:lat,long,dist`          | 地理围栏搜索（经度、纬度、半径）            | `geocode:48.8566,2.3522,5km "protest"`       |


**常用威胁情报组合范式：**

- **PoC 与漏洞早期预警：** `(CVE-2026 OR "0day" OR "RCE") (url:github.com OR url:pastebin.com) -filter:replies`
    
- **数据泄露/勒索软件认领监测：** `("ransomware" OR "leak site" OR "data breach") filter:links min_faves:10`
    
- **目标历史言论排查：** `from:TargetAccount (password OR internal OR vpn OR key OR token)`

2. ==目标实体画像与元数据取证==
针对具体嫌疑人员或特定机构账号，不能只看当前的展示名称（Display Name）和用户名（Handle），需穿透到底层标识符与数字足迹：

- **锁定底层 Snowflake ID：** 用户名（`@handle`）可以随时更改，但 Twitter 为每个账号分配的数字 User ID（基于 Snowflake 算法生成）终生不变。通过工具（如 TweeterID、X API 或开发者控制台网络抓包）提取目标的数字 ID。后续目标即便改名、换头像，只要通过 ID 查询即可持续追踪。
    
- **客户端发布源分析（Source Attribution）：** 查看推文元数据中的来源客户端（如 `X for iPhone`、`X Web App`、`Buffer`、`Hootsuite` 或自定义 Python/Go 脚本）。如果出现特定开发者 API 名称，说明目标在运行自动化推文脚本或使用特定社媒调度平台。
    
- **作息节律推断（Chronological Profiling）：** 批量提取目标历史发推、回复和点赞的时间戳（精确到秒的 UTC 时间），统计 24 小时活跃时段分布。人类的发推频率会呈现明显的睡眠休眠期与活跃峰值，据此可高度推断目标所在的真实时区（UTC 偏移量）。
    
- **快照与历史还原：** 目标删除推文或修改个人简介（Bio）后，可通过 Wayback Machine、Archive.today、Google Cache 以及第三方聚合收录站检索历史快照，还原历史背景、早年公开过的邮箱前缀或社交账号关联。


3. ==社交图谱与协同行为分析（Network & SOCMINT）==
分析社交网络结构有助于定位隐藏资产、判断团伙关联或识别虚假信息放大网络（Disinformation Campaigns）：

- **List（公开列表）双向挖掘：**
    
    - 检查目标创建或订阅的 List，了解其重点关注的情报源与行业圈子。
        
    - 重点检查“包含该目标的 List”（Lists member of）。其他用户对该账号的归类往往会暴露出目标在现实生活中的真实职业、技术方向或所属组织。

- **交互网络与小圈子识别：**
    
    - 使用 `to:TargetAccount` 与 `from:TargetAccount` 交叉对比，梳理出与其回复频率最高的核心联系人。
        
    - 共同关注（Mutual Follows）与共同被关注分析：通过图分析定位目标在特定小圈子（如逆向工程、暗网交易、特定黑客论坛）内的核心枢纽人物。

- **水军与协同网络（Sybil/Botnet）研判：**
    
    - 注册时间集中（如某一批账号均注册于同一周内）。
        
    - 账号命名符合特定规律（如名字后带大量随机数字）。
        
    - 内容高度同步：短时间内集体转发相同推文，且缺少独立的原创观点与个性化互动。



4. ==自动化监测与数据流构建==
面对大规模或长周期的情报需求，人工手动检索效率受限，需搭建自动化监控链：

- **自动化监听与数据抓取：** 鉴于官方 API 的阶梯式计费策略，情报分析人员通常使用无头浏览器（Headless Browser）、基于 Cookie 会话的异步抓取库（如 `twscrape`、`tweet-harvest`）或自建分布式采集端，实现对指定关键词与资产账号的定时拉取。
    
- **聚合与实时推送告警：** 将关注的核心白帽黑客、APT 追踪组织及特定 CVE 语法保存为检索流，结合自动化流程工具（如 n8n、Webhook）把监控到的推文直接流式推送到内部 SIEM、MISP（开源威胁情报平台）或通讯频道。
    
- **可视化关系建模：** 导出账号互关、转发、引用关系的 CSV/JSON 数据，导入 **Gephi** 或 **Maltego**，运行 Louvain 社团划分算法或 PageRank 中心度计算，将扁平的关注列表转化为直观的拓扑图谱，快速找出幕后关键节点。



5. ==操作安全规范（OPSEC）与反追踪==
在社交媒体开展情报活动时，若缺乏操作安全意识，极易导致调查意图泄露或情报账号（Sock Puppet）报废：

- **人偶账号（Sock Puppet）隔离：** 绝不可使用与个人真实身份有任何关联的手机号、邮箱、硬件设备进行注册。为账号建立符合逻辑的掩护身份（Persona），包括真实的个人履历背景、渐进式的发推与关注习惯，避免使用刚注册的空白白号直接高频检索目标。
    
- **防范算法被动关联：** 商业社交平台的推荐算法极其敏感。如果在非隔离环境下频繁搜索、浏览目标，平台可能会在“你可能认识的人”或“推荐关注”中将你的调查账号推荐给目标本人，引发警觉。
    
- **网络与环境隔离：** 调查全程在专用虚拟机（如 TSI/Whonix/Remnux 环境）内进行，搭配反指纹浏览器，并确保出口 IP 与目标关注的地理环境匹配，切断浏览器 Canvas、WebRTC 及硬件指纹跨会话追踪链。

## 3. 推特检索技术
Twitter作为一个比较火的国外社交媒体平台，每天发布的Twitter 帖子或“推文”超过 5 亿条，==这些内容具备很强的实时性，在开源情报调查过程中具有发现被调查对象蛛丝马迹的优越性。下面介绍的使用推特进行开源情报调查按照检索方式分为图形化操作和命令检索两种。==


### 推特检索 5 个标签的介绍

- 顶部（Top）：该标签下面将展示与开源情报调查人员的查询匹配的热门推文。 

- 最新（Latest）：该标签下面将展示与开源情报调查人员的查询匹配的内容，该内容按时间倒序排列的数据列表。它始终从最新的帖子开始并向后追溯。

- 人物（People）：该标签下面将展示与开源情报调查人员的查询匹配的推特用户。您可以查看照片图标和简短描述来识别您的目标。单击用户名将打开用户的 Twitter 个人资料，其中包含更多信息。这是通过真实姓名或用户名搜索的最佳选择。 

- 媒体（Media）：该标签下面将展示与开源情报调查人员的查询匹配的媒体文件，包括照片或者视频。 

- 照片（Photo）：这将搜索与您的查 OSINT网空情报分析询匹配的任何照片。当尝试识别由匿分析报分析 OSINT网空情报分析 OSINT网空情报分析 OSINTOSIN 名者发布并提及您的目标名字的图像时，这非常有用。

- 视频（Videos）：这将搜索与您的查询匹配的任何视频。与前面的示例类似，这通常会找到与您的目标相关的视频。 

- 列表（Lists）：这将搜索与您的查询匹配推特列表。


### 推特人物检索
使用==“关键字”检索==推特用户的情景在开源情报调查活动中经常遇到，这里推荐使用两种方式进行推特人物检索。 

==第一种方法是通过“关键字”检索，在“People”标签的下方通过人工查看关联推特账户的个人资料，然后筛选出你正在调查的目标用户。==

第二种方法是通过推特移动端提供的功能进行调查。推特默认是不允许我们通过提供电子邮件地址来检索对应的推特用户的，但是我们可以利用推特作为社交媒体平台的特点，大多数的社交媒体平台的移动端都会默认获取用户的通讯录，然后用来匹配你可能认识的人，例如 Telegram 就是如此。我们可以构建一个安卓虚拟机，然后安装推特客户端，并将我们需要调查的电子邮箱或者电话号码保存到我们的安卓虚拟机的通讯录中。在推特的“隐私和安全”菜单中，将“可发现性和联系人”选项打开，然后在弹窗中选择“允许推特将您的安卓数据联系人同步到他们的服务”，上述操作之后，推特会使用我们提供的通讯录信息去匹配我们可能认识的用户，从而弹出与我们提供的通信录关联的用户的推特账户。




### 图像化推文检索
推特跟百度、谷歌等搜索引擎一样，提供高级检索的页面来方便用户进行检索 ， 我把该功能称为图形化检索。 ==检索页面URL为： https://twitter.com/search-advanced== ；该页面目前需要登录推特账户才可以使用，在开源情报的调查过程中使用图形化推文检索功能的次数较少。


#### 图形化推文检索的字段介绍
1. 关键字检索：
- 所有这些单词（All of these words）：此处输入开源情报调查者想要检索的字符串“关键字”，这些“关键字”不受输入前后顺序的影响。检索结果为包含这个字符串中所有“关键字”的推文（这些关键词可以不连续）。

- 这个确切的短语（This exact phrase）：此处输入开源情报调查者想要进行精确检索的“关键字”，类似于谷歌语法中的双引号的功能。检索结果为包含这个确切“关键字”的推文。

- 没有这些单词（None of these words）：此处输入开源情报调查者想要在检索结果中排除掉包含此处“关键字”的推文。检索结果为不包含该“关键字”的推文

- 这些单词中的任何一个（Any of these words）：此处输入开源情报调查者想要进行“与”运算的多个“关键字”。检索结果为包含这些“关键字”其中一个或者全部的推文


2. 主题进行检索
- 这些主题标签（These Hashtags）：此处输入开源情报调查者想要调查的某个类别的推文，推特平台的推文在作者发表的时候可能会自定义该推文的自定义标签，在发表之后推特平台也会使用自身的人工智能技术对用户发布的推文进行智能分析，然后输出相应的推特平台的主题标签。这允许开源情报调查者在不知道提交消息的用户的用户名的情况下关注某些主题，比如我们的调查对象是某一个类具体的事项而不是某个人或者组织的时候，使用该功能检索推文会比较便利。


3. 特定账户检索
- 回复这些账户（To these accounts）：此处输入开源情报调查者已经拿到了具体的目标的推特账户之后，检索回复特定用户的推文。

- 来自这些用户（From these accounts）：此处输入开源情报调查者已经拿到了具体的目标的推特账户之后，检索该用户发布的推文的方法。

- 提及这些账户（Mentioning these accounts）：此处输入开源情报调查者用于查找提及特定推特用户的推文。 

- 特定语言检索 

- 语言（Language）：推特支持对特定语言的推文进行检索。


4. 特定范围检索
- 过滤器（Replipes）：过滤器用来过滤掉某些特定条件的推文，例如Includereplies and original Tweets（包括原创和回复的推文）Only show replies（仅仅展示回复的推文）、Include Tweets with links（包括链接的推文）、Only showTweets with likns（仅仅展示包含链接的推文）

- 最小回复数达到一定量的推文（Minimum replies）：此处输入数字，用来返回最小回复数达到该数值的推文。 

- 最小点赞数达到一定量的推文（Minimum Likes）：此处输入数字，用来返回最小点赞数达到一定量的推文。 

- 最小转发数达到一定量的推文（Minimum Retweets）：此处输入数字，用来返回最小转发数达到一定量的推文。 

- 日期（Dates）：此处输入时间范围，用于检索某个时间段范围内的推文。

#### 推特检索运算符
与前面章节中提到的搜索引擎使用运算符的方式类似，==Twitter 有自己的一组搜索运算符，这将大大提高您有效搜索 Twitter 的能力。==


##### ==“from”与“to”运算符==
“from”与“to”运算符后面紧跟推特用户名，“from”运算符的主要功能是检索该用户发布的推文。“to”运算符的主要功能是检索该用户回复的推文。“from”和“to”运算符组合使用的主要功能是，检索从A 用户发出，B用户回复的推文。

- 语法：
1. `from:` 运算符
`from:<用户名>`

2. `to:` 运算符
`to:<用户名>`


##### ==“filter”运算符==
“filter”运算符主要功能是显示仅包含“filter”运算符包含的某些操作的推文 。 例 如 “ from:IntelTechniques filter:replie ” 语 句的功能是只会显示“IntelTechniques”对其他人推文的回复推文。而“from:IntelTechniques -filter:replie”语句的功能是不包括回复推文。

- 语法：
`filter:<属性>`   只显示xxx内容
或
`-filter:<属性>`   排除xxx内容



##### ==“since”和“until”运算符==
==“since”和“until”运算符是与日期检索相关的推特检索运算符。==“since”运算符后面紧跟时间区间的起始日期，"until”运算符后面紧跟时间区间的终止日期。


- **`since:`**：只返回**某个日期之后**（包含当天或从其开始）发布的推文。
- **`until:`**：只返回**某个日期之前**（截至当天结束）发布的推文。


> (==注==：
> - **日期格式**：必须严格遵循 `YYYY-MM-DD`（年-月-日）的标准格式。
> - **语法规则**：运算符名称后紧跟英文冒号 `:`，冒号后直接写日期，**中间不能有空格**。通常直接输入到平台的标准搜索框中即可使用。
> )
> 


- 语法：
`<xxx> since:<2024>-<01>-<01>`
或
`<xxx> since:<2025>-<01>-<01> until:<2025>-<12>-<31>`




##### ==“geocode”运算符(不实用)==
“geocode”运算符是与地理位置相关的运算符，后面紧跟地理位置的经纬度，和该经纬度的范围，经纬度与范围用“逗号”隔开。


- 语法：
`geocode:<latitude>,<longitude>,<radius>`

- **`latitude`**：目标地点的纬度。
- **`longitude`**：目标地点的经度。
- **`radius`**：搜索半径，支持公里（`km`）或英里（`mi`）。
- **注意**：冒号后以及各项参数之间**绝对不能有空格**（例如：`geocode:40.7128,-74.0060,10mi`）。

##### near within 运算符
`near` 和 `within` 是==用于**基于地理位置精准检索推文**的高级搜索运算符==

- **`near:`** 指定一个城市、地区或地标名称，用来查找该地点附近发布的推文。
- **`within:`** 配合 `near` 使用，用来设定距离该地点的最大半径范围（支持英里 `mi` 或公里 `km`）。


- 语法：
`<关键词> near:<地名> within:<距离>`
