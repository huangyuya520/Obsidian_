
# 补：PHP文件包含机制介绍
PHP文件包含机制==允许开发者在程序运行期间将外部代码动态引入并合并执行==

==核心函数==

PHP 主要通过四个函数来实现文件包含：

- **`include`**：当代码执行到该处时才加载文件；若文件不存在或出错，会发出警告（`E_WARNING`），脚本继续运行。
- **`require`**：通常在脚本执行前预先加载；若文件出错，会发出致命错误（`E_ERROR`）并终止脚本。
- **`include_once`** / **`require_once`**：功能与上面两个相同，但在包含前会检查文件是否已被加载过，如果已加载则不会重复包含，常用于防止函数重定义或类冲突。 [[1](https://www.runoob.com/php/php-includes.html)]


==变量作用域与执行机制==

- **作用域继承**：当一个文件被包含时，被包含文件内的代码会继承调用行处可用的**变量范围**。
- **代码解析**：被包含文件的代码会作为 PHP 代码执行，如果文件中包含 HTML/文本内容，会直接输出，遇到 `<?php ... ?>` 标签则按 PHP 语法解析


==安全风险：文件包含漏洞==

如果包含的路径由用户输入控制且没有经过严格过滤，就会导致**文件包含漏洞**（File Inclusion）。 [[1](https://github.com/xidaner/Freed0m/blob/master/%E7%AC%94%E8%AE%B0/%E5%AE%89%E5%85%A8/Web%E6%B8%97%E9%80%8F/PHP%E6%96%87%E7%AB%A0/PHP%E6%96%87%E4%BB%B6%E5%8C%85%E5%90%AB/php%E6%96%87%E4%BB%B6%E5%8C%85%E5%90%AB%E6%BC%8F%E6%B4%9E%E5%88%A9%E7%94%A8%E5%B0%8F%E7%BB%93.md)]

- **本地文件包含（LFI）**：攻击者可读取服务器上的敏感文件（如 `/etc/passwd`）。
- **远程文件包含（RFI）**：如果 PHP 配置中开启了 `allow_url_include`，攻击者可加载远程服务器上的恶意脚本执行

	- 用于在一个PHP脚本中引入或嵌入==另一个文件的内容==
	- 另一个文件：PHP脚本（开发中最常见）或者其他任何类型的文件

## php文件机制存在的意义
PHP文件包含功能的主要意义在于==**实现代码复用、提高开发效率以及便于网站的后期维护**==

==核心意义==

- **结构清晰**：可以将复杂的程序按功能模块拆分成多个小文件，使代码结构更清晰，易于团队协作和管理

	- 意义3：==性能优化==
		- 复用的代码可以避免重复加载，提升性能

# 补：php文件包含常用函数

## include函数简介
PHP 的 `include` 是一个==用于在脚本执行期间包含并运行指定文件的语言结构==

- 语法：
```
include '<filename>'; 
// 或者使用括号 
include('<filename.php>');
```
参数 `'<filename>'` 是要包含的文件路径


==核心功能与特点==

- **引入代码**：将目标文件的内容复制并嵌入到当前位置。
- ==**错误处理**：如果文件不存在或出错，`include` 只会发出一条**警告（Warning）**，脚本会**继续运行**。==
- **变量作用域**：被包含的文件会继承 `include` 所在行的变量范围。
- **执行时机**：代码运行到该行时才会加载文件，常用于流程控制语句中



## require函数介绍
PHP 的 `require` 是一个语言结构，==用于在脚本执行时导入并运行指定的外部文件==

- 语法：
```
require '<filename>'; 
// 或者使用括号 
require('<filename>');
```
参数 `'<filename>'` 是要包含的文件路径


==基本介绍==

- **作用**：将目标文件的内容读入并合并到当前的 PHP 脚本中。
- **位置**：通常放在 PHP 文件的最顶部，在脚本执行前预先加载必要的代码或配置。
- **错误处理**：如果找不到或无法加载指定文件，`require` 会产生一个致命错误（Fatal Error）并立即终止整个脚本的运行


![](f413e2ae23465344290503a653bd8a6b_720.jpg)


## include_once函数介绍
`include_once` 是 PHP 中用于在脚本执行期间包含并运行指定文件的语言结构，其核心特点是==**确保文件只被包含一次**==，引入成功返回 `1`，失败（如文件不存在）时会发出警告（Warning），但**不会中断**整个脚本的执行


-  语法：
```
include_once '<filename>'; 
// 或使用圆括号 
include_once('<filename>');
```
参数 `'<filename>'` 是要包含的文件路径


==核心功能==

- **包含文件**：它会在代码运行到该处时引入并执行外部文件。
- **防止重复包含**：它会先检查文件是否已经被包含过。如果已经包含，则**不会再次引入**。
- **避免冲突**：这能有效防止因重复定义函数、类或重新赋值变量而导致的错误


==与 `include` 的区别==

- `include` 每次调用都会直接引入文件，如果同一个文件被调用多次，可能会报“函数重复定义”的错误。
- `include_once` 会自动做去重检查，确保文件只被加载一次



## require_once函数介绍
`require_once` 是 PHP 中用来导入外部文件的关键字，它会确保文件在脚本执行期间只被加载一次


- 语法：
```
require_once '<filename.php>'; // 推荐使用的语句形式 
require_once('<filename.php>'); // 函数调用形式
```


==主要功能与特点==

- **只加载一次**：如果一个文件已经被包含过了，PHP 不会再次加载它，这能防止函数重定义或变量被重复赋值。
- **加载失败会报错**：如果找不到目标文件，`require_once` 会发出致命错误（Fatal Error）并停止整个程序的运行。
- **与 require 的区别**：普通 `require` 只要被调用就会重复加载文件；而 `require_once` 会先检查是否加载过。
- **与 include_once 的区别**：`include_once` 载入文件失败时只产生警告且程序继续运行，`require_once` 则会直接中断程序


==常见使用场景==

- 引入核心类库（Class）
- 引入自定义函数文件
- 引入数据库配置文件

## 补：include_path配置选项介绍
PHP 的 `include_path` 是一个==用来指定文件搜索路径的选项，能让 `include`、`require`、`fopen()` 等函数在引入或打开文件时自动去这些目录中查找==


- 包含`include_path`函数相关语法：
```
set_include_path(<$new_include_path>)    //设置路径，函数返回布尔值

get_include_path()     //获取路径，返回当前 `include_path` 的字符串，如果失败则返回 false
```


==核心作用==

- **简化路径书写**：设置后，引入文件时无需写冗长的相对或绝对路径，直接写文件名即可。
- **集中管理代码库**：把公共类库或框架路径加入其中，方便统一调用。
- **支持多路径**：可以配置多个目录，系统会按顺序依次查找


==查找规则==

当你在代码中使用 `include 'file.php'` 时，PHP 的查找顺序如下：

- **忽略情况**：如果文件名带有绝对路径（如 `/etc/php`、`C:\`）或明确的相对路径（如 `./`、`../`），`include_path` 会被完全忽略。
- **优先查找**：如果在代码中没写具体路径（仅文件名），PHP 会优先从 `include_path` 指定的目录中搜索。
- **回退查找**：如果 `include_path` 中未找到，最后会在当前调用脚本所在的目录和当前工作目录下寻找



==常见操作方法==

1. 修改配置文件 (`php.ini`)

在全局的 `php.ini` 文件中找到 `include_path` 进行修改。 [[1](https://modelers.csdn.net/69aa2ab27bbde9200ba00ce9.html)]

- ==Windows 系统多个路径用分号 (`;`) 分隔。==
- ==Linux/Unix 系统多个路径用冒号 (`:`) 分隔==

## allow_url_include配置选项介绍
`allow_url_include` 是 PHP 的一个配置选项，==用于控制是否允许通过 URL（如 HTTP 或 FTP）包含和执行外部文件==

- allow_url_include配置项相关命令：
```
allow_url_include = Off   //关闭（默认值）。禁止包含远程 URL 文件

allow_url_include = On    //开启。允许包含远程 URL 文件
```


==基本介绍==

- **作用**：决定 `include`、`include_once`、`require` 和 `require_once` 函数是否能接收 URL 形式的参数来加载远程代码。
- **默认值**：官方默认设置为 `Off`（即 `0`），以防止安全风险。
- **修改范围**：属于 `INI_SYSTEM` 级别，只能在 `php.ini` 或服务器全局配置文件中修改。
- **废弃状态**：自 **PHP 7.4.0** 起，该选项已被官方**废弃**（Deprecated），计划在未来版本中移除


==安全风险==

开启 `allow_url_include = On` 会带来巨大的安全隐患，极易引发 **远程文件包含漏洞（RFI）**。 [[1](https://cloud.baidu.com/article/2831498), [2](https://juejin.cn/post/7454883455001739290)]

- 如果代码中存在未经过滤的动态包含变量（如 `include($_GET['page']);`），攻击者可以传入他们自己远程服务器上的恶意脚本，从而直接获取网站权限或执行系统命令。
- 即使 `allow_url_include` 关闭，如果开启了 `allow_url_fopen`，也仅能使用文件读取类函数，而不能通过包含函数执行远程代码

## 伪协议介绍
PHP伪协议（PHP Wrappers）是==PHP中用于访问、读取或操作不同数据源的一种特殊URL语法机制==


==机制原理==

- **核心概念**：它们不是真正的网络协议，而是PHP内部实现的流（Streams）封装器。
- **工作方式**：当使用 `include`、`file_get_contents`、`readfile` 等文件操作函数时，可以通过类似URL的格式直接传入数据流。
- **主要作用**：==允许开发者或安全人员绕过传统物理文件路径的限制，对本地文件、原始POST数据、标准输入输出等进行过滤或执行==

		- 网络
		- 输入输出流
		- 压缩文件

## `file://`伪协议介绍
PHP 的 `file://` 伪协议==用于访问本地文件系统，是 PHP 默认的的文件封装协议==

它允许程序在诸如 `include()`、`fopen()`、`file_get_contents()` 等文件系统函数中直接读取和加载目标文件


- 语法：
```
file://<文件绝对路径>

file://<文件相对路径>

也可以直接简写为文件名（因为它是默认协议），例如 file:///etc/passwd 和直接写 /etc/passwd 效果相同

```



==核心特点==

- **默认开启**：`file://` 协议不需要开启特殊的配置指令（不受 `allow_url_fopen` 或 `allow_url_include` 的严格限制影响），在任何 PHP 环境中默认均可使用。
- **路径支持**：支持**绝对路径**、**相对路径**以及网络共享/UNC路径。
    - 相对路径：起始目录为当前执行脚本所在的目录。
    - 绝对路径：如 Linux 下的 `/etc/passwd` 或 Windows 下的 `C:/windows/win.ini`


- `file`：//协议

## `php://`伪协议介绍
`php://` 是 ==PHP 提供的一套用于访问各个输入/输出流（I/O streams）的特殊 URL 封装协议==

它可以让开发者直接操作 PHP 的输入输出流、内存、以及通过过滤器处理数据，常用于文件包含、读取源码 和数据传输

==核心子协议分类与介绍==

`php://` 包含多种功能各异的子协议，常见的主要有：

- ==**`php://input==`**
    - **作用**：允许读取**POST**请求的原始数据。
    - **特点**：在 `enctype="multipart/form-data"` 时无效。常用于代码执行或在文件包含漏洞中传入并执行代码。 [[1](https://blog.annevi.cn/security/%E5%AE%89%E5%85%A8%E6%8A%80%E6%9C%AF/php%E4%BC%AA%E5%8D%8F%E8%AE%AE%E5%AD%A6%E4%B9%A0%E6%80%BB%E7%BB%93.html)]

- ==**`php://filter==`**
    - **作用**：一种元封装器，设计用于数据流打开时的**筛选和过滤**应用。
    - **特点**：常与 `base64` 编码过滤器（`convert.base64-encode`）结合，在安全审计或 CTF 中用于读取无法直接显现的 PHP 源代码（防止文件被服务器直接解析执行）。 [[1](https://blog.csdn.net/IDHALASHAO/article/details/130368938)]

- php://协议之php://filter（重点）
	- 是一种元封装器
	- ==用于在文件系统操作中对数据进行流过滤处理==
	- ==可以在读取或写入数据时应用特定的过滤器==

```
php://filter/read=<过滤器名称>/resource=<文件路径>
php://filter/write=<过滤器名称>/resource=<文件路径>
```

- **`php://stdin`、`php://stdout`、`php://stderr`**

- **数据流过滤**：通过过滤器链在读取或写入数据时进行实时转换（如转码、压缩）

	 - 用于访问各个输入/输出流（i/o streams）

### `php://`协议之`php://filter`详介（重点）
`php://filter` 是 PHP 提供的一种元封装器（伪协议），==用于在数据流（文件读写）打开时对数据执行过滤和转换==。它常用于在不修改原始文件的情况下，对文件内容进行编码、解码或其他逻辑处理

- 语法：
```
php://filter/<过滤器链>/resource=<目标文件>
```
- **resource**（必须参数）：指定要过滤的数据流或文件路径。
- **过滤器链**：可以指定一个或多个过滤器，多个过滤器之间用管道符 `|` 连接

==常用参数与过滤器==

你可以组合使用多种内置过滤器：

- **字符串过滤器（String Filters）**：
    - `string.rot13`：进行 ROT13 转换。
    - ==`string.toupper`：转为大写。==
    - ==`string.tolower`：转为小写。==
    - `string.strip_tags`：去除 HTML/XML 标签。

- **转换与编码过滤器（Conversion Filters）**：
    - ==`convert.base64-encode`：进行 Base64 编码。==
    - ==`convert.base64-decode`：进行 Base64 解码。==
    - `convert.quoted-printable-encode` / `decode`。
    - `convert.iconv.*`：字符集转换（如 `convert.iconv.UTF-8.GBK`）
    
```
convert.quoted-printable-encode    对数据进行quoted-printable编码。
convert.quoted-printable-decode    对quoted-printable编码的数据进行解码
zlib.inflate    解压数据
zlib.deflate    压缩数据
```



==核心作用与使用场景==

- **防止源码直接执行（读取源码防解析）**  
    当文件包含漏洞（如 `include`）存在，但目标是一个 `.php` 文件，直接包含会导致代码被执行。使用 `php://filter/convert.base64-encode/resource=index.php` 可以将源码 Base64 编码后读取，避免代码执行并暴露出原本的内容。

- **链式处理数据**  
    支持串联多个过滤器。例如 `php://filter/read=string.rot13|convert.base64-encode/resource=index.php` 会先进行 ROT13，再进行 Base64 编码

## `data://`伪协议介绍
PHP 的 `data://` 伪协议是==一种数据流封装器，允许在支持文件流操作的函数中直接嵌入和执行小块数据==

- 语法：
```
data://text/plain,<数据内容>
data://text/plain;base64,<Base64编码的数据内容>
```



==核心配置条件==

要正常使用 `data://` 伪协议，PHP 配置文件（`php.ini`）中必须开启以下两个选项： [[1](https://a1andns.github.io/post/PHP%E4%BC%AA%E5%8D%8F%E8%AE%AE)]

- `allow_url_fopen = On`（允许打开 URL 文件流）
- `allow_url_include = On`（允许包含 URL 文件流，**仅在执行文件包含如 `include`/`require`**


==支持的函数==

`data://` 适用于大多数支持 URL/文件流操作的函数，例如： [[1](https://juejin.cn/post/7163831572158742535)]

- `include()` / `include_once()`
- `require()` / `require_once()`
- `file_get_contents()`
- `readfile()`


- `data://协议`
	- 用于传递相应格式的数据
	- 需要满足以下配置
		- `allow_url_fopen`为`On`
		- `allow_url_include`为`On`

## `zip://`等压缩文件读取伪协议介绍
PHP 的 `zip://`、`phar://`、`compress.bzip2://` 和 `compress.zlib://` 是内置的**压缩流伪协议**，==常用于文件包含（LFI）或文件读取场景==

它们==允许 PHP 直接读取压缩包内部的文件，且**对压缩包的后缀名没有限制**==


1. 常用压缩伪协议介绍

| 协议名称                    | 语法格式                      | 核心特点与要求                             |
| ----------------------- | ------------------------- | ----------------------------------- |
| **`zip://`**            | `zip://<绝对路径># <内部文件>`    | 必须使用**绝对路径**；`#` 需 URL 编码为 `%23`。   |
| **`phar://`**           | `phar://<绝对或相对路径>/<内部文件>` | PHP 版本需 \(\ge 5.3.0\)；不限制后缀，支持相对路径。 |
| **`compress.bzip2://`** | `compress.bzip2://<文件路径>` | 用于读取 `.bz2` 压缩单文件。                  |
| **`compress.zlib://`**  | `compress.zlib://<文件路径>`  | 用于读取 `.gz` 压缩单文件                    |

2. `zip://` 协议详解与利用方式

- 基本原理
`zip://` 可以访问 ZIP 压缩包当中的子文件。配合文件包含函数（如 `include`、`file_get_contents` 等），==如果网站允许上传 zip 文件（或者改名为白名单后缀如 `.jpg`、`.png`），就可以把恶意 PHP 代码或敏感文件打包并上传，随后触发包含==


2. 构造与使用方法

- **准备文件**：将写有 PHP 代码的文件（例如 `shell.php`）压缩成一个 ZIP 文件，命名为 `archive.zip`。 [[1](https://www.anquanke.com/post/id/248627)]
- **后缀绕过**：如果上传点限制了后缀，可将 `archive.zip` 重命名为 `avatar.jpg` 后台上传。 [[1](https://www.anquanke.com/post/id/248627), [2](https://zhuanlan.zhihu.com/p/686151790)]
