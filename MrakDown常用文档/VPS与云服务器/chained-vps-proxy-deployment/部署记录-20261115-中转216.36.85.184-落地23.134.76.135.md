# 二级代理（中转 → 落地）重建记录

- 日期：2026-11-15（Asia/Shanghai）
- 目标：用中转机 216.36.85.184 作为美国入口，落地机 23.134.76.135（纽约家宽）作为最终出口，修复“时好时坏”的问题，实现稳定可用的链式海外代理。

## 1. 最终拓扑

```text
客户端(V2rayN/xray)
   │  VLESS + Reality + Vision (TCP)
   ▼
中转机 216.36.85.184:24065 (备用 24051)   x-ui / xray 入站
   │  VLESS(明文, 无TLS) 转发到 127.0.0.1:24099
   ▼
SSH 隧道 land-tunnel.service  (relay → landing:53930)   自动保活/断线重连
   │  127.0.0.1:24099 ↔ 落地 127.0.0.1:24099
   ▼
落地机 23.134.76.135  sing-box 入站 vless(明文, 仅127.0.0.1)
   │  direct 出站
   ▼
Internet  —— 最终出口 IP = 23.134.76.135（美国 纽约 Yonkers, AS27284 Fourplex Telecom LLC，家宽属性）
```

为什么这样设计：
- 落地机 23.134.76.135 的 IPv4 对国内被墙、且面板只映射了 `53930→22` 一个端口，中转机无法直连落地的代理端口；用 **SSH 反向可达的本地转发隧道**把落地 sing-box 暴露在中转机 `127.0.0.1:24099`，无需在落地面板加端口映射。
- SSH 隧道内置 `ServerAliveInterval=15 / CountMax=3` + systemd `Restart=always`，掉线 3 秒内自动重连，这是消除“有时可用有时不可用”的关键。
- 客户端入口用 **VLESS-Reality-Vision**，抗主动探测、握手更像正常 TLS，适合跨境长期使用。

## 6. 原“时好时坏”根因定位

1. **旧落地已失效**：旧配置出站指向 `216.36.90.16:44300`（旧落地 trojan），与实际落地 23.134.76.135 不一致，链路经常不可达。
2. **双套服务冲突**：中转同时跑 x-ui/xray 与 hy2chain(sing-box hysteria2/tuic)，且 nft 把 udp 24060-24065 重定向到 24051，与 xray 的 24051 混用，UDP/TCP 端口语义混乱。
3. **无自动重连**：旧链路依赖一次性连接，落地/隧道抖动后不自动恢复。

本次已针对性消除：单一路径（Reality→VLESS→SSH隧道→sing-box）、停用冲突服务、清空旧 nft 重定向、SSH 隧道 systemd 自动保活。

## 7. 回滚方法

中转机：
```bash
systemctl stop land-tunnel && systemctl disable land-tunnel
# 恢复出站到变更前（示例，按需选择备份）
cp /root/rebuild-backup-20261115T055423Z/xray-generated.before /usr/local/x-ui/bin/config.json
cp /root/rebuild-backup-20261115T055423Z/control-db.before /etc/x-ui-yg/x-ui-yg.db
systemctl restart x-ui
# 如需恢复旧 hy2：systemctl enable --now hy2chain
```
落地机：
```bash
systemctl disable --now sing-box
rm -f /etc/systemd/system/sing-box.service /etc/sing-box/config.json
systemctl daemon-reload
```
