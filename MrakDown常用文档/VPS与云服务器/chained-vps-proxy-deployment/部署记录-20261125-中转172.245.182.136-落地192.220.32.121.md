# 二级代理部署记录（中转 172.245.182.136 → 落地 192.220.32.121）

- 日期：2026-11-25（Asia/Shanghai）
- 目标：中转机 `172.245.182.136`（美国亚特兰大 KVM，Ubuntu 24.04，2TB/月）作为客户端入口，落地机 `192.220.32.121`（美国洛杉矶 住宅双ISP家宽云 NAT 容器，Alpine，160GB/月，入口TCP 54321）作为最终出口，搭建低延迟、Reality 伪装、纯净出口 IP 的链式代理。

## 1. 最终拓扑

```text
客户端(V2rayN/xray/sing-box)
   │ ① VLESS-Reality-Vision (TCP 443)  主链路 → 出口=落地家宽
   │ ② VLESS-Reality-Vision (TCP 8443) 备用:中转直连 → 出口=中转
   ▼
中转机 172.245.182.136   Xray 26.11.9（systemd: xray-chain, Restart=always）
   │ 入站 client-main-443 / client-direct-8443（Reality, dest=www.microsoft.com）
   │ 出站 chain-landing：VLESS-Reality-Vision → 192.220.32.121:54321（sockopt: TFO+keepalive+tcpNoDelay）
   ▼
落地机 192.220.32.121   sing-box 1.14.4 (musl)（OpenRC: sing-box, 开机自启）
   │ 入站 vless-reality 0.0.0.0:54321（Reality 握手 www.microsoft.com）
   │ 出站 direct
   ▼
Internet —— 最终出口 IP = 192.220.32.121
（Los Angeles, NTT America AS2914；ip-api: hosting=false / proxy=false / mobile=false；
  scamalytics 风控 7/100 low，无黑名单/代理标记；注意 scamalytics 将其归类为 Server 型商用线路，非严格意义住宅 ISP）
```

**设计说明**
- 中转→落地为美国境内（RTT 48ms），Reality 伪装 TLS 到 www.microsoft.com，抗主动探测；
- TCP+Vision 流控降低 TLS-in-TLS 特征，配 BBR+fq+TFO（中转 KVM 内核已启用），流量形态平滑，降低运营商对"短时大流量"的 QoS 敏感度；
- 中转机原有 S-Box（sing-box 多协议节点）与 WARP(wireproxy) 完全未动，443/8443 为空闲端口新增；
- 落地 NAT 面板仅映射了 TCP 54321，故主链路为 TCP Reality；客户端 UDP（DNS 等）经 VLESS 链路中继到落地后由落地直接出站，可用；
- 落地容器 CapEff 全开但宿主内核 BBR 已开，无需容器内调整。

## 6. 已知问题：落地机上游带宽拥塞（非链路问题）

分项实测（UTC ~09:20-10:05）：
- 中转机直连 Cloudflare：**48.9MB/s（~392Mbps）**——中转自身健康（1Gbps 口）
- 落地机直连 Cloudflare：~267KB/s；直连 cachefly ~103KB/s（落地在 LAX、到 CF 仅数 ms RTT，可排除内核/窗口问题 → 商家上游拥塞/共享限速；面板标称 276Mbps）
- 链式单流 10MB：~300KB/s ≈ 落地直连 → **链路本身（Reality+Vision+BBR+TFO）无额外瓶颈**
- 链式 4 并发（4×5MB）：合计 ~310KB/s ≈ 单流 → 落地上游为**总量型限速/拥塞，多线程无法聚合，IDM/aria2 多线程无效**

缓解建议（修订）：
- 纯净 IP 场景（AI/API/注册/网页）走主链路 443；
- 大流量下载走 8443 中转直连（出口=中转，本机直连实测 ~392Mbps 量级，跨境实际速度取决于中国↔亚特兰大线路）；
- 若必须走家宽出口大流量：向商家（独角鲸云面板）反馈上游拥塞或换时段；服务端无可调空间。
（原 S-Box/WARP 分流选项已移除，见 §10。）

## 13. 诊断：链路慢的根因 = 落地机上行方向被商家上游限速/丢包（2026-11-25 UTC 10:00-10:30）

现象：V2rayN 主链路延迟 -1/539ms、请求每秒重试。三段式排查：
- 跨境段(本机→中转)：TCP 稳定 230ms、零丢包 ✅
- 中转段：本机出站 45ms、8443 直连 0.12s、relay↔landing ping 48ms 零丢包 ✅
- **落地上行方向：❌** 判定性实测——落地→中转灌 20MB 只通过 312KB(**≈10KB/s**)；落地→中转 1400B ping 丢 33%；链路下载因此只剩 6-8KB/s
- 落地"下行"方向正常(relay→landing 1500B 无损、landing→gstatic 小响应 0.03s 假象正常)
- 今晨基线上行 ~300KB/s → 此时 ~10KB/s，数小时内恶化 30 倍 → 商家共享家宽上游时段性拥塞/限速，非配置问题
- 附注：busybox ping 不支持 -M do，早前"landing→relay MTU 全丢"的探测无效，已用原始 TCP 灌包法重新实锤
- MTU 排除：relay→landing 全尺寸 1500 通过
