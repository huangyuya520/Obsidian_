

# AAA


![](Pasted%20image%2020261124124134.png)




## 概述
**AAA** 是==认证（Authentication）、授权（Authorization）和计费（Accounting）的简称==

它是网络访问控制的安全管理框架，用于验证用户身份、分配访问权限并记录使用情况


==三大核心要素==

- **认证（Authentication）**：识别并验证用户身份是否合法。常见凭据包括用户名和密码、动态令牌或数字证书。

- **授权（Authorization）**：根据身份和策略分配操作或访问权限，通常遵循最小特权原则。

- **计费（Accounting）**：记录用户接入时长、服务类型、数据流量和关键操作日志，用于计费与安全审计


==工作架构与通信机制==

AAA 通常采用客户端/服务器（C/S）架构： [[1](https://developer.aliyun.com/article/499418)]

- **用户发起连接**：用户向网络接入服务器（NAS）或网关发起登录或网络接入请求。

- **凭据转发**：NAS 作为 AAA 客户端，将用户凭据转发给后端 AAA 服务器。

- **决策与执行**：AAA 服务器校验身份并返回授权策略；NAS 依据结果放行或拒绝访问，并在会话期间上报计费信息。


==常见通信协议==

- ==**RADIUS**：将认证与授权合并处理==，常用于宽带接入、Wi-Fi 与企业网络准入。

- ==**TACACS / TACACS+**：将认证、授权与计费分离==，对设备管理命令提供细粒度控制，多见于网络设备运维。

- ==**Diameter**：RADIUS 的演进协议，具备更强的扩展性与可靠性==，广泛用于移动通信与核心网场景。

- 认证（Authentication）：验证用户是否可以获得访问权，确定哪些用户可以访问网络。
- 授权（Authorization）：授权用户可以使用哪些服务。
- 计费（Accounting）：记录用户使用网络资源的情况。
- 网络运营商（ISP）需要验证家庭宽带用户的账号密码之后才允许其上网，并记录用户的上网时长或上网流量等内容，这就是AAA技术最常见的应用场景。








## AAA基本架构及原理
AAA 采用典型的 **客户端/服务器（C/S）** 架构，包含三个核心角色：

1. **用户（User / Client）**：发起网络接入或设备登录请求的终端主机、无线客户端或运维人员。
    
2. **NAS（Network Access Server，网络接入服务器）**：位于用户与核心资源之间的网络设备（如企业接入/核心交换机、路由器、无线控制器 AC、防火墙或运营商 BRAS）。NAS 对用户而言是接入网关，对后台服务器而言则是 **AAA 客户端**，负责收集请求并按协议转发。
    
3. **AAA 服务器（AAA Server）**：集中存储用户信息、权限策略并接收审计日志的后台系统（如华为 iMaster NCE-Campus、Cisco ISE、FreeRADIUS 等）。


下方的典型 AAA 网络架构展示了用户终端、NAS 与 AAA 服务器之间的连接关系，重点留意用户登录名中的 `@Domain` 后缀以及 NAS 侧通过“域”关联不同 AAA 方案的逻辑：


![](Pasted%20image%2020261124125832.png)

在数通设备（尤其是华为、华三等企业级设备）的实际配置中，**域（Domain）** 是串联整个 AAA 逻辑的核心枢纽：

- **基于域的策略隔离**：用户登录时通常携带域名（格式为 `username@domain`，例如 `admin@manage` 或 `guest@wifi`）。NAS 根据域名将用户归入对应的管理域，并调用该域绑定的**认证方案、授权方案和计费方案**。如果用户未输入域名，则自动归入设备的默认域（Default Domain）。
    
- **高可用逃生机制（Fallback）**：工程部署中严禁只配置单一远端认证而不留退路。标准做法是将认证顺序设为“先远端、后本地”（例如先走 HWTACACS/RADIUS，仅当远端服务器不可达或超时无响应时才降级为 Local 认证），防止因核心链路故障或 AAA 服务器宕机导致管理员无法登录设备排障

### 认证
- **认证（Authentication）—— 验证身份合法性** 确认试图接入网络或登录设备的用户是否合法（例如核对用户名、密码、数字证书或动态令牌）。设备端通常支持三种实现方式：
    
    - **不认证（None）**：完全信任用户，不校验身份（生产环境极少使用）。
        
    - **本地认证（Local）**：将用户信息直接保存在网络设备本地。处理速度快、无额外服务器开销，但容量受限，且在多台设备间维护账号极难同步。
        
    - **远端认证（Remote）**：网络设备作为代理，将凭证转发给专门的 AAA 服务器进行集中校验，适合中大型企业网与运营商网络。














### 授权
- **授权（Authorization）—— 分配访问权限** 在认证通过后，决定用户可以使用哪些网络资源或执行哪些操作。常见授权内容包括下发用户权限级别（如设备的命令行级别 Level 0 至 Level 15）、动态分配 IP 地址、下发 VLAN、ACL 过滤规则或 QoS 限速策略。授权同样支持**不授权**、**本地授权**和**远端授权**（也可配置为仅在认证通过后授权）。





### 计费
- **计费（Accounting）—— 记录资源使用与行为审计** 监控并记录用户访问网络的起止时间、在线时长、上下行流量以及在设备上执行过的操作命令。在运营商网络中，计费主要用于**按量/按时收费**；而在企业内网中，计费的核心价值在于**安全审计与事后溯源**（例如追踪某台核心交换机的错误配置是由哪位运维人员在何时敲入的）。计费通常采用**远端计费**或**不计费**。
