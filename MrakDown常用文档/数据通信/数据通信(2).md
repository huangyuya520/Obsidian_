### 冲突域
**冲突域（Collision Domain）** 是指在共享物理通信介质上，所有能够==产生**物理电信号冲突**的网络节点所构成的集合。==当该集合内的任意两台设备在同一物理信道上同时发送信号时，电磁波在传输介质上会发生波形叠加畸变，导致比特流损毁，==这一物理覆盖范围即为一个冲突域。==


![](Pasted%20image%2020261014182129.png)





==网络设备与冲突域的边界关系==

不同层级的网络设备对冲突域的物理界限有完全不同的处理方式：

|**设备类型**|**工作层级**|**处理单位**|**对冲突域的影响**|**典型工作模式**|
|---|---|---|---|---|
|**中继器 (Repeater) / 集线器 (Hub)**|物理层 (L1)|比特 (Bit)|**不隔离**，机械放大并转发电平信号，**扩大**冲突域范围|半双工 (Half-Duplex)|
|**网桥 (Bridge) / 二层交换机 (Switch)**|数据链路层 (L2)|数据帧 (Frame)|**隔离**冲突域，每个端口为一个独立冲突域（微网段化）|全双工 / 半双工自协商|
|**三层交换机 / 路由器 (Router)**|网络层 (L3)|数据包 (Packet)|**隔离**冲突域，同时隔离广播域|全双工点对点|


==现代网络中冲突域的演进与终结==


1. 有线以太网：全双工（Full-Duplex）彻底消除冲突

现代以太网（100BASE-TX、1000BASE-T 及光纤网络）通过物理介质的独立通道终结了电气冲突：

- **双绞线/光纤的物理通道分离**：采用独立的收发链路（双绞线中使用不同线对，如 1/2 号脚发送、3/6 号脚接收；光纤使用 TX/RX 独立纤芯或双向波分复用）。
    
- **CSMA/CD 停用**：在交换机端口配置为全双工（Full-Duplex）后，每个网口与对端设备构成专用的点对点通道，物理层退化为无竞争的单播信道，**冲突域在工程意义上缩小至零**。



2. 无线局域网（Wi-Fi）：空口物理冲突域的延续

在 802.11 无线网络中，空气作为共享物理介质再次面临冲突问题：

- 无线射频信道无法同时进行同频收发（发送功率远大于接收微弱信号，导致自身盲区），本质仍属于**半双工物理冲突域**。
    
- Wi-Fi 在物理层和 MAC 层采用 **CSMA/CA** 机制替代 CSMA/CD，利用物理载波侦听（Clear Channel Assessment, CCA）与虚拟载波侦听（NAV 计时器）配合 RTS/CTS 握手，规避空间中的电磁波重叠。
    
- Wi-Fi 6/7 引入的 **OFDMA**（正交频分多址）与 **MU-MIMO**（多用户多输入多输出）技术，在频域和空间域上对物理信道进行细分切片，进一步压缩了空口冲突域对传输效率的损耗。

## 补：数据链路层

### 广播域(二层广播域)
广播域（Broadcast Domain）**是指在计算机网络中，==任意一个节点发送广播报文时，所有能够接收并处理该报文的节点所构成的逻辑网络范围。==在 TCP/IP 体系中，广播域由**数据链路层（二层）**的泛洪机制维系，并由**网络层（三层）设备或三层逻辑接口完成物理与逻辑隔离。


==TCP/IP 协议栈视角下的广播机制与报文封装==

在 TCP/IP 协议栈中，广播的传递涉及二层与三层的报文协同：

例：
![](Pasted%20image%2020261014184022.png)



1. 数据链路层（Layer 2）广播

以太网帧的目的 MAC 地址为固定的全 1 地址：`FF-FF-FF-FF-FF-FF`。

- **交换机转发行为**：二层交换机维护 MAC 地址表。当收到目的 MAC 为广播地址的数据帧时，硬件 ASIC 芯片无条件将该帧复制并从**相同 VLAN 内除接收端口外的所有其他端口**发送出去（即泛洪，Flooding）。
    
- **网卡处理行为**：广播域内的所有网卡（NIC）在硬件层均会匹配并接收该 MAC 地址，随后触发硬件中断，将数据帧递交至操作系统内核的网络协议栈。



2. 网络层（Layer 3）广播

IPv4 定义了两种主要的广播地址类型：

- **受限广播（Limited Broadcast）**：目的地址固定为 `255.255.255.255`。该地址用于本地链路未完成网络配置时的通信（如主机刚开机请求 IP）。任何符合规范的路由器或三层设备在默认情况下**绝对禁止转发**该报文，直接将其限制在当前物理/逻辑网段内。
    
- **直接广播（Directed Broadcast / Subnet Broadcast）**：目的地址的主机位全为 1（例如在 `192.168.10.0/24` 子网中，广播地址为 `192.168.10.255`）。早期的路由器允许跨网段转发此类报文，但因容易被恶意攻击者用于放大 DDoS 攻击（如经典的 Smurf 攻击），现代网络操作系统（如 Cisco IOS、Huawei VRP）默认全局禁用跨三层接口转发直接广播。


依赖广播的典型 TCP/IP 协议及演进

许多核心的 TCP/IP 基础服务依赖广播域进行初始节点发现与地址协商：

- **ARP（地址解析协议）**：当节点已知目标 IPv4 地址但缺乏二层目的 MAC 时，发送 ARP Request 报文（以太网目的地址为 `FF-FF-FF-FF-FF-FF`）。广播域内的所有主机协议栈都要解析该 ARP 请求，仅拥有对应 IP 的主机以单播方式回复 ARP Reply。
    
- **DHCP（动态主机配置协议）**：客户端在未获取到有效 IP 地址前，通过发送 DHCP Discover / Request 广播报文（源 IP `0.0.0.0`，目的 IP `255.255.255.255`）寻找局域网中的 DHCP 服务器；若服务器位于其他广播域，则依赖DHCP 中继代理（DHCP Relay）将二层广播转换为单播跨网段路由。
    
- **IPv6 的根本性变革（彻底终结广播）**：IPv6 在协议架构设计中**彻底废除了广播（Broadcast）** 概念，全量改用**组播（Multicast）** 与 **任播（Anycast）**。例如，IPv6 使用基于 ICMPv6 的邻居发现协议（NDP）替代 ARP，解析地址时向特定的被请求节点组播地址（Solicited-Node Multicast Address）发包，只有特定散列匹配的主机网卡硬件才会过滤接收，避免无关节点承受无谓的中断损耗。




==广播域与冲突域的核心差异==


| **比较维度**   | **冲突域 (Collision Domain)** | **广播域 (Broadcast Domain)**   |
| ---------- | -------------------------- | ---------------------------- |
| **关注核心**   | 物理层电信号的重叠与介质争用             | 数据链路层与网络层寻址逻辑与报文泛洪           |
| **工作层级**   | 物理层（L1）                    | 数据链路层（L2）与网络层（L3）            |
| **边界隔离设备** | 网桥、二层交换机（每个端口为一个独立冲突域）     | 路由器、三层交换机 VLANIF/SVI、防火墙安全区域 |
| **共享设备影响** | 集线器（Hub）将所有端口置于同一冲突域       | 未划分 VLAN 的交换机将所有端口置于同一广播域    |
| **性能损耗形式** | 介质碰撞导致电气重传、延迟上升            | 频繁触发全网所有主机 CPU 软中断、消耗总线与端口带宽 |




==广播域的工程隐患与隔离控制技术==

1. 广播域过大的工程隐患

- **广播风暴（Broadcast Storm）**：当网络存在二层物理环路且生成树协议（STP）失效或配置错误时，广播帧在交换网络中无限制死循环复制，短时间内打满千兆/万兆上行链路，打死交换机背板与 CPU 控制平面。
    
- **内网安全威胁**：恶意节点在同一广播域内可随意发动 ARP 欺骗（中间人截获流量）、伪造 Rogue DHCP Server、或通过发送广播报文进行内网资产存活探测。
    
- **终端算力浪费**：广播报文每秒超过一定阈值（通常每秒几百个广播包）时，老旧工控机、物联网设备或高负荷服务器的 CPU 会因大量上下文切换而性能明显下降。


2. 现代网络工程隔离方案

- **VLAN（IEEE 802.1Q 虚拟局域网）**：在交换机芯片内部通过打上 12-bit 的 VLAN Tag（支持 1~4094 个标识），逻辑切分交换矩阵，**1 个 VLAN = 1 个独立广播域 = 1 个独立 IPv4 子网**。跨 VLAN 互访必须经过三层网关（如单臂路由或核心交换机 VLANIF 虚接口）。
    
- **端口隔离 / 私有 VLAN（PVLAN）**：在同一个 VLAN/子网内部进一步做细粒度控制。通过将端口划分为隔离端口（Isolated）和混杂端口（Promiscuous），使得处于同一广播域的终端之间连二层广播与单播都无法互通，阻断横向移动。
    
- **VXLAN / EVPN Overlay 网络**：在数据中心 Spine-Leaf 架构中，物理底座为纯三层 Underlay 网络（消除大范围 STP 环路），通过引入 24-bit 的 VNI 逻辑标识，将二层广播域封装在 UDP 报文内穿越 L3 网络，并使用 EVPN 控制平面的 BGP 路由学习抑制 ARP 广播泛洪。

### MAC地址构成及分类



![](Pasted%20image%2020261015160151.png)





- ==一个制造商在生产制造网卡之前，必须先向IEEE注册，以获取一个长度为24bit (3字节)的厂商代码，也称为OUI。==
- ==后24bit由厂商自行分派，是各个厂商制造的所有网卡的唯一编号。==
- ==MAC地址可以分为3种类型：==

	- 单播MAC地址==（第八位为零；看MAC地址的第二个数字，如果为偶数则为单播MAC地址）==：也称物理MAC地址，这种类型的MAC地址唯一的标识了以太网上的一个终端，该地址为全球唯一的硬件地址。

		- 单播MAC地址用于标识链路上的一个单一节点。
		- 目的MAC地址为单播MAC地址的帧发往一个单一的节点。
		- 单播MAC地址可以作为源或目的地址。
		- 注意：单播MAC地址具有全球唯一性，当一个二层网络中接入了两台具有相同MAC地址的终端时（例如误操作等），将会引发通信故障（例如这两台终端无法相互通信），且其他设备与它们之间的通信也会存在问题。

	- 广播MAC地址==（全为一；MAC地址全为F）==：全1的MAC地址（FF-FF-FF-FF-FF-FF），用来表示局域网上的所有终端设备。

		- 广播MAC地址可以理解为一种特殊的组播MAC地址。
		- 其具体格式为：FFFF-FFFF-FFFF。
		- 目的MAC地址为广播MAC地址的帧发往链路上的所有节点。

	- 组播MAC地址==（第八位为一；看MAC地址的第二个数字，如果为奇数则为单播MAC地址）==：除广播地址外，第7bit为1的MAC地址为组播MAC地址（例如01-00-00-00-00-00），用来代表局域网上的一组终端。

		- 组播MAC地址用于标识链路上的一组节点。
		- 目的MAC地址为组播MAC地址的帧发往一组节点。
		- 组播MAC地址不能作为源地址，只能作为目的地址。

#### 补：子网掩码

==核心作用==

- **区分网段**：通过将IP地址与子网掩码进行按位“与”（AND）逻辑运算，路由器可以识别出该IP地址属于**本地局域网**还是**远程网络**。
- **优化网络**：将大型网络划分为多个较小的子网，减少广播风暴，提升数据传输效率。
- **确定通信方式**：同一子网内的设备可以直接通信；不同子网的设备通信必须通过**网关**（路由器）转发。

#### 补：网络地址(网段) 


==计算网络地址（Network Address）==

- **方法**：将 IP 地址与子网掩码进行**按位“与”（AND）** 逻辑运算。 [[1](https://blog.csdn.net/w2009211777/article/details/123823562), [2](https://www.cnblogs.com/wj-1314/p/8302473.html)]
- **规则**：`1 AND 1 = 1`，其余组合均等于 `0`。
- **结果**：
	- 例：
	    - IP：`192.168.1.100` -> 二进制转换后与掩码运算
	    - 网络地址：`192.168.1.0`（代表该网段本身）




==计算广播地址（Broadcast Address）==

- **方法**：先得到网络地址，然后把该网段中的**所有主机位全换成 1**。 [[1](https://zhuanlan.zhihu.com/p/97740009)]
- **结果**：
    - 广播地址：`192.168.1.255`（用于向该网段内所有设备发送广播包）

#### 补：子网划分

==核心概念==

- **IP 地址**：由 32 位二进制数组成（通常写成 4 个十进制数字，如 `192.168.1.1`），分为**网络位**和**主机位**两部分。
- **子网掩码（Subnet Mask）**：一个 32 位的二进制数，用连续的 `1` 表示网络部分、用 `0` 表示主机部分，用来帮助路由器识别一个 IP 地址哪部分是网络、哪部分是主机。
- **借位原理**：==子网划分的核心是从 IP 地址的**主机位**借出若干位作为**子网位**，从而把一个大网拆成多个小网。==


==常用计算公式与方法==

- ==**子网数量**：若借用 n 位主机位作子网位，则可以划分出的子网数为 \(2^{n}\)。==

- ==**可用主机数**：若**剩余 h 位作为主机位**，则每个子网的有效主机数为 \(2^h - 2\)（需扣除全为 0 的**网络地址**和全为 1 的**广播地址**）。==




#### 补：CIDR(无类域间路由)

==CIDR 的核心机制==

CIDR 打破了传统的 A、B、C 类僵化边界，引入了两个核心概念：

- **变长子网掩码（VLSM，Variable-Length Subnet Masking）**：
    - 网络前缀的长度可以任意设定，不再局限于 8、16 或 24 位。

- **CIDR 表示法（斜线记法）**：
    - 格式为：`IP地址 / 前缀长度`（例如：`192.0.2.0/24`）。
    - 斜杠后面的数字（如 `/24`）表示 IP 地址中前面有多少位代表**网络位**，剩下的位数代表**主机位**。
    - 例如 `192.0.2.0/24` 表示前 24 位是网络地址，后 8 位（2⁸ - 2 = 254个）可分配给主机



==CIDR 的主要优势==

- **灵活分配 IP**：可以按需精确划分网段（如 `/27`、`/28`），大幅减少 IPv4 地址的浪费。 [[1](https://blog.csdn.net/lopowh/article/details/136235064), [2](https://aws.amazon.com/cn/what-is/cidr/), [3](https://aws.amazon.com/tw/what-is/cidr/)]
- **路由聚合（Supernetting / 超网）**：
    - 路由器可以把多个连续的小网段“聚合”成一个大的 CIDR 块进行通告（例如把多个 `/24` 聚合为一个 `/20`）。
    - 这大幅缩减了互联网核心路由器的**路由表条目数量**，提升了数据转发效率。 [[1](https://aws.amazon.com/cn/what-is/cidr/), [2](https://zh.wikipedia.org/zh-tw/%E6%97%A0%E7%B1%BB%E5%88%AB%E5%9F%9F%E9%97%B4%E8%B7%AF%E7%94%B1)]
- **云上网络构建**：在现代云计算（如 Amazon VPC）中，创建私有网络必须指定 CIDR 块（例如 `10.0.0.0/16`）来规划子网和实例通信。





### 补：ICMP

==主要作用与功能==

- **错误报告**：当路由器或目标主机无法传递 IP 数据包时（例如：数据包过大无法分片、目标不可达、超时等），会生成一条 ICMP 错误消息发回给源主机。
- **网络诊断与测试**：
    - **Ping 命令**：使用 ICMP 的**回显请求（Echo Request）**与**回显应答（Echo Reply）**消息，来测试目标主机的连通性及往返延迟（RTT）。


![](Pasted%20image%2020261017223322.png)




- **Tracert / Traceroute 命令**：利用 ICMP 超时消息来追踪数据包从源到目标所经过的路由路径和跃点数。

![](Pasted%20image%2020261017223347.png)


==基本工作特点==

- **依附于 IP 协议**：ICMP 报文会被封装在 IP 数据包中进行传输（协议号为 `1`），它本身并不是独立传输的。
- **无连接协议**：发送 ICMP 消息前不需要在通信双发之间建立类似 TCP 的连接。
- **不可靠传输**：ICMP 不保证消息一定能到达目的地，它只负责传递状态与错误信息






![](Pasted%20image%2020261020165640.png)


- ICMP重定向过程：

1. `主机A`希望发送报文到`服务器A`，于是根据配置的默认网关地址向`网关RTB`发送报文。

2. `网关RTB`收到报文后，检查报文信息，发现报文应该转发到与源主机在同一网段的另一个`网关设备RTA`，此转发路径是更优的路径，所以`RTB`会向主机发送一个Redirect消息，通知主机直接向另一个`网关RTA`发送该报文。

3. 主机收到`Redirect`消息后，会向`RTA`发送报文，然后`RTA`会将该报文再转发给服务器A。
