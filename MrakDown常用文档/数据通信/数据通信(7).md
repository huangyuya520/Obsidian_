
# OSPF
OSPF（**Open Shortest Path First**，开放最短路径优先）是==一种基于链路状态的内部网关协议（IGP），用于在同一个自治系统（AS）内进行路由决策和数据包转发==

**OSPF工作在 IP 层之上，协议号为 89**。与基于距离矢量（Distance-Vector）的协议（如 RIP）不同，OSPF 路由器之间交互的不是路由表，而是**链路状态通告（LSA，Link State Advertisement）**。


==核心特点与机制==

- **协议类型**：无类别链路状态路由协议，直接运行在 IP 层（**协议号 89**），使用组播地址 `224.0.0.5`（所有 OSPF 路由器）和 `224.0.0.6`（DR/BDR）进行通信。 [[1](https://zhuanlan.zhihu.com/p/342844788), [2](https://blog.csdn.net/qq_40005416/article/details/124568265)]

- **核心算法**：采用**最短路径优先（SPF / Dijkstra）算法**，以“开销（Cost）”作为度量值来计算最短路径树



- ==**版本分类**：==

- **OSPFv2**：支持 IPv4。
- **OSPFv3**：支持 IPv6


- **数据包类型**：主要使用 5 种类型的分组：Hello、DD（数据库描述）、LSR（链路状态请求）、LSU（链路状态更新）和 LSAck（链路状态确认）。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/OSPF.html)]


- ==**运行状态**==：邻居建立到路由同步经历 `Down` → `Init` → `2-Way` → `Exstart` → `Exchange` → `Loading` → `Full` 等状态




==结构与优化设计==

- **区域划分（Area）**：支持分层设计，将大型网络划分为不同的区域以减少 LSA 泛洪范围。其中必须存在一个**骨干区域（Area 0）**。特殊区域包括：Stub（末梢区域）、Totally Stub、NSSA 等。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/OSPF.html), [2](https://zh.wikipedia.org/zh-cn/%E5%BC%80%E6%94%BE%E5%BC%8F%E6%9C%80%E7%9F%AD%E8%B7%AF%E5%BE%84%E4%BC%98%E5%85%88), [3](https://zhuanlan.zhihu.com/p/342844788)]

- **DR 与 BDR**：在广播型（Broadcast）或 NBMA 网络中，为了避免每台路由器之间两两建立邻接关系造成流量爆炸，会选举出指定路由器（DR）和备份指定路由器（BDR），所有非 DR/BDR 路由器只与 DR/BDR 交换信息。 [[1](https://blog.csdn.net/qq_40005416/article/details/124568265), [2](https://zh.wikipedia.org/zh-cn/%E5%BC%80%E6%94%BE%E5%BC%8F%E6%9C%80%E7%9F%AD%E8%B7%AF%E5%BE%84%E4%BC%98%E5%85%88)]

- **优势**：收敛速度快、无路由自环、支持大型网络及区域汇总

## OSPF 的核心工作原理

==OSPF 的核心设计与基础概念==

- **Router ID（RID）：** 32 位无符号整数（表现为点分十进制形式），用于在自治系统内唯一标识一台 OSPF 路由器。==可通过手动配置（推荐）或按规则自动选举（优先 Loopback 接口最高 IP，其次物理接口最高 IP）==。
    
- **层次化区域划分（Area）：** 为减少 LSDB 规模、降低 SPF 计算开销和控制 LSA 泛洪范围，OSPF 采用两层区域结构：
    
    - **骨干区域（Backbone Area / Area 0）：** 核心区域，所有非骨干区域必须直接（或通过虚链路）与骨干区域相连。
        
    - **非骨干区域（Standard/Stub/Totally Stub/NSSA）：** 负责本区域内部路由传递及聚合。

- **路由器角色分类：**
    
    - **IR（Internal Router）：** 所有接口都在同一区域内。
        
    - **ABR（Area Border Router）：** 接口跨越多个区域（至少连接一个骨干区域和一个非骨干区域）。
        
    - **ASBR（Autonomous System Boundary Router）：** 引入其他路由协议（如 BGP、静态路由）或不同 OSPF 进程的边界路由器





==五种协议报文==

OSPF 定义了 5 种不同的报文类型来完成邻居发现、关系协商与数据同步：

| **报文类型**   | **报文名称**                       | **功能与作用**                                          |
| ---------- | ------------------------------ | -------------------------------------------------- |
| **Type 1** | **Hello**                      | 周期性发送（广播网络默认 10s），用于发现、建立与维持邻居关系，并在广播网络中选举 DR/BDR。 |
| **Type 2** | **DBD (Database Description)** | 包含本地 LSDB 中各 LSA 的摘要信息（LSA Header），用于数据库同步前的目录比对。  |
| **Type 3** | **LSR (Link State Request)**   | 对比 DBD 后，向对端请求本地缺少或较旧的完整 LSA。                      |
| **Type 4** | **LSU (Link State Update)**    | 真正携带完整 LSA 详细信息的报文，用于响应 LSR 或主动泛洪拓扑变更。             |
| **Type 5** | **LSAck (Link State Ack)**     | 对接收到的 LSU 进行显式确认（可靠传输机制）。                          |




==OSPF 的工作过程可以大致分为以下几个核心阶段：==

1. ==建立邻居关系（Neighbor）==

路由器启动后，通过接口向外发送 **Hello 报文**，发现并建立邻居关系。Hello 报文用于参数协商（如区域 ID、Hello/Dead 时间间隔、认证等）和保活。 [[1](https://www.cnblogs.com/zylSec/p/15640660.html), [2](https://info.support.huawei.com/info-finder/encyclopedia/zh/OSPF.html)]





==邻居建立与状态机流转==

两台直连的 OSPF 路由器从物理连接到形成完全邻接（Adjacency）关系，会经历 7 个主要状态：

```
[Down] ──> [Init] ──> [2-Way] ──> [ExStart] ──> [Exchange] ──> [Loading] ──> [Full]
```

1. **Down：** ==初始状态==，未收到任何对端发来的 Hello 包。
    
2. **Init：** ==收到对端的 Hello 包==，但包内的“Active Neighbor”列表中尚未包含自己的 RID（说明单向连通）。
    
3. **==2-Way==：** 收到对端发送的 Hello 包，且在“Active Neighbor”列表中看到了自己的 RID（双向通信确认）。
    
    - _关键动作：_ 在广播（Broadcast）或 NBMA 网络中，此阶段完成 **DR（Designated Router）/ BDR（Backup Designated Router）** 的选举。如果双方是普通的 DROther 路由器，两者之间的关系将永久保持在 2-Way 状态。

4. **ExStart：** 确定主从（Master/Slave）关系与初始化 DD 序列号。此时发送空的 DBD 报文，==Router ID 较大者成为 Master==，由 Master 决定后续交互的序列号以保证报文传输的有序与可靠。
    
5. **Exchange：** 相互发送携带 LSA 摘要信息的 DBD 报文，彼此比对自身 LSDB 缺少哪些 LSA。
    
6. **Loading：** 针对比对中缺失或落后的 LSA，发送 **LSR** 请求；对端回应 **LSU**；收到后回送 **LSAck** 进行确认。
    
7. **==Full==：** 双方的 LSDB 完全一致，邻接关系（Adjacency）建立完成。

2. ==同步链路状态数据库（LSDB）==

- 邻居关系建立后，路由器之间开始交换 **LSA（Link State Advertisement，链路状态通告）**。

- 双方通过交互 DD（数据库描述）、LSR（链路状态请求）、LSU（链路状态更新）和 LSAck（确认）报文，确保彼此的 **LSDB（链路状态数据库）** 完全一致。

- 整个 AS 或区域内的每台路由器都拥有同一份结构一致的 LSDB。 [[1](https://support.huawei.com/enterprise/zh/doc/EDOC1100278975/c1083833), [2](https://info.support.huawei.com/info-finder/encyclopedia/zh/OSPF.html)]




==网络类型与 DR/BDR 选举机制==
在以太网等多路访问（Multi-Access）网络中，若 $n$ 台路由器互建邻接关系，邻接总数为 $\frac{n(n-1)}{2}$，将导致巨大的重复泛洪开销。

在OSPF（开放式最短路径优先）协议中，**DR（Designated Router，指定路由器）** 和 **BDR（Backup Designated Router，备份指定路由器）** 是==用于优化多路访问网络（如广播型以太网）中路由信息交互的核心角色==



- **DR 与 BDR 的角色：**
    
    - 所有普通路由器（DROther）仅与 DR 和 BDR 建立 **Full** 邻接关系；==DROther 之间保持 **2-Way** 状态==。
        
    - 邻接数从 $\frac{n(n-1)}{2}$ 缩减至 $2n-2$。

- **==组播地址分工==：**
    
    - `224.0.0.5`：所有运行 OSPF 的路由器均监听。
        
    - `224.0.0.6`：仅 DR 和 BDR 监听。DROther 产生拓扑变化时，向 `224.0.0.6` 发送 LSU；DR 收到后再向 `224.0.0.5` 泛洪给其他所有路由器。

- ==**选举规则（非抢占式）：**==
    
    1. 比较接口优先级（Priority，范围 0-255，默认为 1；0 表示不参与选举）。
        
    2. 若优先级相同，比较 Router ID，数值大者优先。
        
    3. 当 DR 失效时，BDR 立即升为 DR，并重新选举新的 BDR
    4. DR 和 BDR 是**基于网段（Segment）** 逐个选举的，选举过程主要依据以下标准： [[1](https://www.zhihu.com/question/522230201)]

	- **Hello 报文触发**：在网络接口进入 2-Way 状态后开始选举。 [[1](https://www.cnblogs.com/zhaojianwang/p/10854365.html)]

	- **等待时间（Wait Time）**：通常默认为 40 秒，给网段内所有路由器留出发送 Hello 报文参与选举的时间。 [[1](https://blog.csdn.net/qq_62311779/article/details/122889602)]

	- **比较优先级（Priority）**：
	    - 范围通常为 `0 ~ 255`（默认为 `1`）。
	    - **优先级为 `0`** 的路由器放弃参与 DR/BDR 选举（永远只能是 DROther）。
	    - 优先级数值**越大越优先**。 [[1](https://blog.csdn.net/qq_62311779/article/details/122889602)]

	- **比较 Router ID（RID）**：
	    - 如果优先级相同，则比较路由器的 Router ID，数值**越大越优先**。
	    - （RID 生成规则：手动配置优先；若无手动配置，则取 Loopback 接口中 IP 地址最大的；若无 Loopback，则取物理接口中 IP 地址最大的）。 [[1](https://blog.csdn.net/qq_62311779/article/details/122889602)]

	- **非抢占性（No Preemption）**：
	    - OSPF 的 DR/BDR **具有非抢占性**。也就是说，当一个 DR 已经被选出后，即使后来接入了一台优先级更高或 RID 更大的新路由器，它也不会马上抢占现任 DR 或 BDR 的位置，除非现任 DR/BDR 挂掉或重启


- **DR（指定路由器）**
    - **作用**：作为该网段内所有路由器的**中心枢纽**。
    - **工作方式**：网段内的所有其他路由器（称为 **DROther**）只与 DR 建立**全连接（Full 状态）**并交换路由信息。当拓扑变化时，DROther 把更新发给 DR，由 DR 统一向网段内的其他路由器同步 LSA。

- **BDR（备份指定路由器）**
    - **作用**：DR 的“替补队员”。
    - **工作方式**：BDR 与网段内的所有路由器也建立 Full 状态的邻接关系，并实时监控 DR 的状态。一旦 DR 发生故障宕机，BDR 会**立刻顶替**成为新的 DR，从而保证网络的快速收敛与稳定性。

- **DROther（其他路由器）**
    - **关系**：既不是 DR 也不是 BDR 的路由器。
    - **状态**：它们与 DR、BDR 保持 Full 状态，但**彼此之间不建立邻接关系**（停留在 2-Way 状态），从而大大减少了网段内的流量和连接数

3. ==运行 SPF 算法计算路由==

每台路由器以自己为根，使用 **Dijkstra 算法** 对 LSDB 中的拓扑进行计算，得出到达所有目的网段的最短路径树，并把最优路由加载到**路由表**中。 [[1](https://developer.aliyun.com/article/1638524), [2](https://www.juniper.net/documentation/cn/zh/software/junos/ospf/topics/topic-map/ospf-overview.html)]

4. ==路由收敛与维护==

- 拓扑发生变化时（如某条链路断开），受影响的路由器会产生新的 LSA 泛洪给邻居。

- 邻居更新各自的 LSDB，并重新运行 SPF 算法，实现快速收敛

![](Pasted%20image%2020261107151900.png)






![](Pasted%20image%2020261107151446.png)


- 链路状态路由协议有四个步骤：

	- 第一步是建立相邻路由器之间的邻居关系。
	- 第二步是邻居之间交互链路状态信息和同步LSDB。
	- 第三步是进行优选路径计算。
	- 第四步是根据最短路径树生成路由表项加载到路由表。





## OSPF专业术语

### 区域
**区域（Area）** 是将自治系统（AS）内的路由器及其互联链路进行逻辑分组的边界单位，其本质目的是构建**层次化的网络拓扑结构**，以解决大规模网络中链路状态数据库（LSDB）过大及路由计算开销过高的问题

1. ==为什么需要划分区域==

OSPF 属于链路状态协议（Link-State Protocol）。在扁平（单一区域）的网络结构中，网络规模扩大会带来三个显著瓶颈：

- **LSDB 内存开销过大：** 区域内每台路由器都必须存储全网拓扑的 1 类和 2 类 LSA，路由器数量增加会导致 LSDB 呈几何级数膨胀。
    
- **SPF 计算消耗过高：** 任何一条链路发生震荡（Flap），都会触发区域内所有路由器重新运行 Dijkstra 算法重新计算最短路径树（SPF Tree）。
    
- **拓扑震荡无法隔离：** 局部链路的故障会引发全网范围的 LSA 泛洪，消耗大量带宽与 CPU 资源。
    

**划分区域的核心逻辑：** 将完整的拓扑切分为多个自治的逻辑单元。**区域内部**运行完整的 SPF 算法以感知详细的拓扑连通性；**区域之间**则通过路由汇总（Distance-Vector 方式）传递网段可达性信息。局部链路变化仅在区域内部重新运行 SPF，其他区域只需进行开销极低的部分路由计算（PRC，Partial Route Calculation）



![](20261107_152808.jpg)





2. ==区域的层次化架构与标识==

OSPF 区域通过一个 32 位的数字进行唯一标识（**Area ID**），可以用十进制整数表示（如 `0`、`1`），也可以使用点分十进制表示（如 `0.0.0.0`、`0.0.0.1`）。

OSPF 严格遵循双层分层结构：
![](Pasted%20image%2020261107153003.png)


骨干区域（Backbone Area / Area 0）

- 标识必须固定为 **`Area 0`**（或 `0.0.0.0`）。
    
- 自治系统内的核心枢纽，负责在所有非骨干区域之间中转区域间流量。
    
- 骨干区域本身必须保持物理或逻辑上的连续性。
    

非骨干区域（Non-Backbone Area）

- 除 Area 0 以外的所有区域（如 Area 1、Area 10 等）。
    
- 主要承载本区域内部的局部流量以及接入用户/终端网段。

### 度量值(cost开销)
**度量值（Metric）** 被称为**开销（Cost）**，用于衡量数据流经某条链路或路径的综合代价，**Cost 值越小代表路径越优**。

OSPF 基于接口的链路带宽动态计算单段链路的 Cost，并通过沿途累加所有出接口的 Cost 来选出到达目标网段的最短路径树（SPF Tree）


1. ==接口 Cost 的计算公式与默认行为==

OSPF 路由器默认根据接口的协商速率/配置带宽自动计算链路 Cost，计算公式如下：

$$\text{Cost} = \frac{\text{参考带宽（Reference Bandwidth）}}{\text{接口实际带宽（Interface Bandwidth）}}$$

- **参考带宽（Reference Bandwidth）：** RFC 2328 默认定义的参考带宽通常为 **$100\text{ Mbps}$（即 $10^8\text{ bps}$）**。
    
- **计算取整规则：** 计算结果向下取整，但若计算值小于 1，则**强制取最小值 1**（Cost 必须为正整数，范围为 $1 \sim 65535$）。
    

在默认 $100\text{ Mbps}$ 参考带宽下，各常见介质的默认开销如下：

| **接口类型**                      | **接口速率**           | **计算过程**                               | **最终 Cost 值**                             |
| ----------------------------- | ------------------ | -------------------------------------- | ----------------------------------------- |
| **Serial / T1**               | 1.544 Mbps         | $100 / 1.544 \approx 64.76$            | **64**                                    |
| **Ethernet**                  | 10 Mbps            | $100 / 10 = 10$                        | **10**                                    |
| **FastEthernet (FE)**         | 100 Mbps           | $100 / 100 = 1$                        | **1**                                     |
| **GigabitEthernet (GE)**      | 1 Gbps (1000 Mbps) | $100 / 1000 = 0.1 \rightarrow$ 取最小整数   | **1**                                     |
| **10-GigabitEthernet (10GE)** | 10 Gbps            | $100 / 10000 = 0.01 \rightarrow$ 取最小整数 | **1**                                     |
| **Loopback 接口**               | 逻辑接口               | 协议硬性固定                                 | **0 或 1**（不同厂商实现略有差异，Cisco 默认为 1，华为默认为 0） |

### 邻居关系和邻接关系
**邻居关系（Neighbor）** 与**邻接关系（Adjacency）** 是两个不同深度、处于不同交互阶段的逻辑关联。两者的核心分水岭在于**是否同步了链路状态数据库（LSDB）**

1. ==核心定义与本质区别==

- **邻居关系（Neighbor Relationship）：**
    
    - **定义：** 两台直连的 OSPF 路由器通过互发 **Hello 报文**，发现并确认了彼此的存在，且基础参数（Area ID、Hello/Dead 间隔、认证信息、掩码、特殊区域标识等）完全匹配。
        
    - **最终状态：** 稳定在 **`2-Way`** 状态。
        
    - **本质：** 仅建立了**双向通信能力（Bidirectional Communication）**，证明物理和数据链路层连通且参数兼容，但**不交换 LSA，不同步拓扑数据**。

- **邻接关系（Adjacency Relationship）：**
    
    - **定义：** 在形成邻居关系的基础上，双方进一步交互 DBD、LSR、LSU 和 LSAck 报文，完成链路状态数据库的彻底比对与同步。
        
    - **最终状态：** 稳定在 **`Full`** 状态。
        
    - **本质：** 形成了**完全的拓扑同步**。只有建立邻接关系的路由器之间才会持续泛洪 LSA，并作为 Dijkstra 算法计算最短路径树（SPF Tree）的直接拓扑依据

### 网络类型
**网络类型（Network Type）** 是接口级别的属性，它决定了路由器在该链路上**如何发送协议报文（组播还是单播）**、**是否选举 DR/BDR**，以及**两台路由器之间最终形成何种层级的连接状态（是仅停留在 2-Way 邻居状态，还是推进到 Full 邻接状态）**


==一、 四大核心网络类型与邻居/邻接行为==

OSPF 会根据接口底层的二层数据链路协议自动设定默认的网络类型，工程师也可以在接口视图下通过命令手动更改（如在以太网接口上配置 `ospf network-type p2p`）。



1. ==广播类型（Broadcast）==

- **典型介质：** Ethernet、FDDI 等支持广播/组播的多路访问链路。
    
- **DR/BDR 选举：** **强制选举**。
    
- **报文发送方式：**
    
    - 组播发送。所有路由器监听 `224.0.0.5`；DR/BDR 额外监听 `224.0.0.6`。
        
- **邻居与邻接行为：**
    
    - **DROther ↔ DROther：** 仅建立并保持**邻居关系（2-Way 状态）**。双方仅通过 Hello 报文维持保活与参数感知，绝不同步 LSDB。
        
    - **DROther ↔ DR / BDR：** 建立完全的**邻接关系（Full 状态）**，完成 DBD、LSR、LSU 的交互与数据库同步。
        
    - **DR ↔ BDR：** 双方同样建立**邻接关系（Full 状态）**。



2. ==点到点类型（P2P, Point-to-Point）==

- **典型介质：** PPP、HDLC 链路，或在单对单光纤互联的以太网接口上手动配置。
    
- **DR/BDR 选举：** **不选举**。链路两端只有两台设备，不存在第三方广播竞争。
    
- **报文发送方式：**
    
    - 组播发送（固定发往 `224.0.0.5`）。
        
- **邻居与邻接行为：**
    
    - 只要两端 Hello 报文协商成功，邻居状态会**无条件越过 2-Way**，直接进入 ExStart、Exchange、Loading，最终达成完全的**邻接关系（Full 状态）**。
        
    - 不存在仅维持在 2-Way 状态的可能。



3. ==非广播多路访问类型（NBMA, Non-Broadcast Multi-Access）==

- **典型介质：** Frame Relay、ATM、X.25，或部分 Hub-and-Spoke 拓扑。
    
- **DR/BDR 选举：** **强制选举**（通常必须将 Hub 端设为 DR，Spoke 端优先级设为 0 以放弃竞选）。
    
- **报文发送方式：**
    
    - **单播发送**。因为底层介质不支持广播或组播，无法自动发现邻居，必须在 OSPF 进程下通过 `peer <IP>` 手动指定对端 IP。
        
- **邻居与邻接行为：**
    
    - 与广播类型一致：**DROther ↔ DROther** 保持 **2-Way 邻居关系**；**DROther ↔ DR/BDR** 推进至 **Full 邻接关系**。



4. ==点到多点类型（P2MP, Point-to-Multipoint）==

- **典型介质：** 通常不由二层封装默认指定，而是工程师针对不完全互联（Partial Mesh）的 NBMA 或 Hub-and-Spoke 网络手动配置的改良模式。
    
- **DR/BDR 选举：** **不选举**。它将一个物理上的多路访问网络逻辑解耦为多个独立的点到点链路集合。
    
- **报文发送方式：**
    
    - 组播发送（发往 `224.0.0.5`）。
        
- **邻居与邻接行为：**
    
    - 中心节点（Hub）与每一个能够直连的分支节点（Spoke）之间，直接跨越 2-Way 建立**邻接关系（Full 状态）**。
        
    - **路由特性：** 会自动为每个邻居接口生成一条 `/32` 的主机路由通告进 LSDB，以确保非全互联拓扑下的跨分支连通性。

### 路由器类型
**路由器类型**根据观察维度的不同可分为两类：一类是基于**区域分层拓扑架构**所承担的骨干/边界角色（IR、BR、ABR、ASBR），另一类是基于**多路访问链路（Broadcast / NBMA）** 内部选举的管理角色（DR、BDR、DROther）。这两组角色直接决定了路由器之间是仅仅维持保活的**邻居关系（Neighbor / 2-Way）**，还是进一步推进至同步链路状态数据库的**邻接关系（Adjacency / Full）**


1. ==OSPF 路由器类型的双重视角划分==

视角一：按分层区域拓扑角色划分（Area-Level Roles）

- **内部路由器（IR, Internal Router）：** 所有启用 OSPF 的接口完全属于同一个非骨干区域。
    
- **骨干路由器（BR, Backbone Router）：** 至少有一个接口位于骨干区域（Area 0）的路由器。
    
- **区域边界路由器（ABR, Area Border Router）：** 接口同时连接骨干区域（Area 0）与至少一个非骨干区域的设备。ABR 为连接的每个区域独立维护一份链路状态数据库（LSDB），并负责在区域间传递与生成 3 类 LSA（Network Summary LSA）。
    
- **自治系统边界路由器（ASBR, Autonomous System Boundary Router）：** 将外部路由（如静态路由、BGP、直连或其他 IGP 协议）重分布引入 OSPF 路由域的设备，负责始发 5 类 LSA（AS External LSA）或在 NSSA 区域始发 7 类 LSA。



视角二：按多路访问链路角色划分（Link-Level Roles）

在广播（Broadcast）或非广播多路访问（NBMA）链路中，为避免两两建立同步导致拓扑信息泛洪爆炸，各路由器接口会参与协商选举出三种角色：

- **指定路由器（DR, Designated Router）：** 负责代表该网段收集所有拓扑变化，向全网统一泛洪，并始发 2 类 LSA（Network LSA）描述该网段包含的邻接节点。
    
- **备份指定路由器（BDR, Backup Designated Router）：** 实时同步拓扑数据的备选节点。当 DR 故障时，BDR 立即升格为 DR，避免重新选举导致网络收敛震荡。
    
- **普通路由器（DROther）：** 未竞选上 DR 和 BDR 的其余路由器。



2. ==链路角色与“邻居” vs “邻接”的映射关系==

在多路访问网络中，路由器的接口角色直接决定了最终的状态机稳态：

| **交互双方角色**            | **最终稳定状态**  | **关系属性**            | **是否同步 LSDB** | **报文交互范围**                    |
| --------------------- | ----------- | ------------------- | ------------- | ----------------------------- |
| **DROther ↔ DROther** | **`2-Way`** | **邻居关系（Neighbor）**  | **否**         | 仅定期互发 Hello 报文，维持心跳与双向连通性感知。  |
| **DROther ↔ DR**      | **`Full`**  | **邻接关系（Adjacency）** | **是**         | 交互 DBD、LSR、LSU、LSAck，完全同步数据库。 |
| **DROther ↔ BDR**     | **`Full`**  | **邻接关系（Adjacency）** | **是**         | 完全同步数据库，确保 BDR 随时具备接管能力。      |
| **DR ↔ BDR**          | **`Full`**  | **邻接关系（Adjacency）** | **是**         | 完全同步数据库，时刻保持主备状态一致。           |

- 区域内路由器（Internal Router）：该类路由器的所有接口都属于同一个OSPF区域。
- 区域边界路由器ABR（Area Border Router）：该类路由器的接口同时属于两个以上的区域，但至少有一个接口属于骨干区域。
