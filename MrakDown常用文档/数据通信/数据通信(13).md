
# 实现VLAN间的通信


## 补：网关
**网关（Gateway）** 本质上是==连接两个不同网络或系统的“关口”或统一出入口，负责数据转发、协议转换或请求管理==

网关主要分为以下几类：

1. 网络网关（Network Gateway）

- **作用**：连接本地局域网（LAN）与外部网络（如广域网 WAN 或互联网），并在不同协议之间转换和转发数据包。

- **工作原理**：设备判断目标 IP 不在当前局域网内时，会把数据发给“默认网关”（常见如家庭路由器的 `192.168.1.1`），由网关向外转发。

- **常见形态**：路由器、三层交换机、防火墙、VPN 服务器或云端网关设备。 [[1](https://blog.csdn.net/biyifengfei/article/details/140637204), [2](https://www.zhihu.com/question/362842680), [3](https://baike.baidu.com/item/192.168.1.1/10856429), [4](https://info.support.huawei.com/info-finder/encyclopedia/zh/%E7%BD%91%E5%85%B3.html), [5](https://www.hpe.com/cn/zh/what-is/network-gateway.html)]

2. API 网关 / 微服务网关（API Gateway）

- **作用**：作为客户端与后端多个微服务之间的统一入口，降低前后端耦合。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/API%E7%BD%91%E5%85%B3.html), [2](https://www.ibm.com/cn-zh/think/topics/api-gateway)]

- **核心功能**：
    - **请求路由**：把外部请求分发到对应的后端服务。
    - **安全与鉴权**：统一校验身份、权限和防刷校验。
    - **流量控制**：实现限流、熔断和负载均衡，保护后端服务。
    - **协议与监控**：支持协议转换、日志记录与接口监控。 [[1](https://www.cnblogs.com/buchizicai/p/17093564.html), [2](https://info.support.huawei.com/info-finder/encyclopedia/zh/API%E7%BD%91%E5%85%B3.html), [3](https://www.ibm.com/cn-zh/think/topics/api-gateway)]

- **常见实现**：Spring Cloud Gateway、Kong、APISIX、Nginx 等。 [[1](https://blog.csdn.net/biyifengfei/article/details/140637204)]

3. 支付网关（Payment Gateway）

- **作用**：连接电商/商家系统与银行或支付机构，负责加密传输支付信息并处理交易授权

## 1. 使用路由器（物理接口、子接口）实现VLAN间通信


### 多臂路由
**多臂路由（Multi-arm Routing）**，在数据通信教材中也称为**传统 VLAN 间路由（Legacy Inter-VLAN Routing）**，是指利用路由器的**多个独立三层物理接口**分别连接二层交换机上属于不同 VLAN 的接口，从而实现跨 VLAN 通信的组网方案。它与“单臂路由（仅用一条物理链路配合子接口）”相对应——由于路由器向交换机伸出多条独立物理链路、形似多条“手臂”，因此得名多臂路由。



==一、组网架构与底层映射关系==

多臂路由的核心设计思想是“一个 VLAN 独享一条物理上行链路和一个路由器物理接口”。如下方拓扑所示，路由器与二层交换机之间通过多条并行线缆互联，并严格维护三张核心转发表项的协同


例：
![](Pasted%20image%2020261119170233.png)


结合上图，整个架构在二层与三层的职责边界非常清晰：
- **交换机侧（纯二层隔离）**：连接终端主机（端口 `1~6`）和连接路由器（端口 `7`、`8`）的接口**全部配置为 Access 模式**。端口 `7` 划入 VLAN 10（`PVID=10`），端口 `8` 划入 VLAN 20（`PVID=20`）。交换机维护的 MAC 地址表按 VLAN ID 严格隔离，路由器接口 `0` 的 MAC（`R-0`）仅出现在 VLAN 10 表项中，接口 `1` 的 MAC（`R-1`）仅出现在 VLAN 20 表项中。
    
- **路由器侧（纯三层转发）**：接口 `0` 配置 `192.168.1.254/24` 作为 VLAN 10 的默认网关，接口 `1` 配置 `192.168.2.254/24` 作为 VLAN 20 的默认网关。两个接口启用后，路由器自动在路由表中生成两条**直连路由（Direct）**，分别指向 `192.168.1.0/24` 和 `192.168.2.0/24`。
    
- **链路帧格式（全程无标签）**：由于互连端口均为 Access 模式，数据帧进入交换机内部时才会携带 802.1Q Tag；一旦从端口 `7` 或端口 `8` 发往路由器，标签即被剥离。因此**路由器完全无需感知 VLAN 的存在**，也不需要配置 802.1Q 终结功能







- 在二层交换机上配置VLAN，每个VLAN单独使用一个交换机接口与路由器互联。

- 路由器使用两个物理接口，分别作为VLAN 10及VLAN 20内PC的默认网关，使用路由器的物理接口实现VLAN之间的通信。

### 单臂路由
**单臂路由**（Router-on-a-Stick）是==通过路由器的单个物理接口创建多个逻辑子接口，并配合交换机的 Trunk 链路，实现不同 VLAN（虚拟局域网）之间三层通信的技术==。 [[1](https://blog.csdn.net/qq_62462797/article/details/125831350), [2](https://www.cnblogs.com/wbcde116/p/18779580), [3](https://zhuanlan.zhihu.com/p/574731791)]

==核心原理==

- **交换机侧**：连接终端的端口设为 Access 模式，归属对应 VLAN；连接路由器的端口设为 Trunk 模式，允许携带 VLAN 标签的数据帧通过。

- **路由器侧**：在单个物理接口下划分多个逻辑子接口（如 `G0/0/0.10`、`G0/0/0.20`），配置不同的 IP 地址作为各 VLAN 的网关。

- **报文转发**：通过 **802.1Q** 协议识别和剥离/封装 VLAN 标签，实现跨 VLAN 的路由转发。



==优缺点==

- **优点**：节省路由器物理接口和硬件成本，适合预算有限或小型网络场景。 [[1](https://www.bilibili.com/video/BV1QK411J7nv/), [2](https://zhuanlan.zhihu.com/p/574731791)]

- **缺点**：
    - **带宽瓶颈**：所有跨 VLAN 流量都集中在同一条物理链路上转发。
    - **单点故障**







==一、底层核心机制：子接口与 802.1Q 标签终结==

单臂路由能够用一根网线同时承载几十个 VLAN 的网关流量，核心依赖两个组件在数据链路层与网络层的严密配合：

1. **二层交换机 Trunk 链路（多 VLAN 透传）** 交换机连接路由器的接口必须配置为 **Trunk 模式**，并明确放行所有需要跨网段通信的 VLAN。数据帧离开 Trunk 口发往路由器时，必须携带 **IEEE 802.1Q VLAN Tag**，以便路由器区分该帧归属哪个广播域。
    
2. **路由器三层子接口（逻辑网关与 Tag 终结）** 路由器在一个物理接口（父接口，如 `GE0/0/0`）下创建多个逻辑子接口（如 `GE0/0/0.10`、`GE0/0/0.20`）。每个子接口都是独立的三层逻辑接口，各自拥有对应 VLAN 网段的 IP 地址（作为网关），并在路由表中生成独立的直连路由（Direct）



==二、端到端转发流程拆解（含 ARP 与二/三层字段演变）==

以典型场景为例：**PC1**（VLAN 10，`192.168.10.1/24`，MAC 为 `MAC-A`）向 **PC2**（VLAN 20，`192.168.20.1/24`，MAC 为 `MAC-B`）发送数据包。交换机 LSW1 通过 `GE0/0/1`（Trunk）连接路由器 R1 的 `GE0/0/0`（父接口硬件 MAC 为 `MAC-R`），R1 上配置了子接口 `GE0/0/0.10`（`192.168.10.254`）与 `GE0/0/0.20`（`192.168.20.254`）。

1. **跨网段判断与发往网关（无标签帧）** PC1 判断目标 IP `192.168.20.1` 与自身不在同一子网，封装标准以太网帧（`源MAC: MAC-A`，`目的MAC: MAC-R`，`源IP: 192.168.10.1`，`目的IP: 192.168.20.1`），经交换机 Access 口送入 LSW1。
    
2. **Access 入站打标与 Trunk 带标上送** LSW1 的 Access 口收到无标签帧，依据端口 PVID 打上 `VID=10` 的 802.1Q 标签；查询 VLAN 10 的 MAC 表命中 `MAC-R → GE0/0/1`。由于 `GE0/0/1` 是 Trunk 口且允许 VLAN 10 通过（且默认 PVID=1 不等于 10），该帧**保留 `VID=10` 标签**发往路由器 R1。
    
3. **子接口终结与三层路由查表** R1 的 `GE0/0/0` 识别到帧内 `VID=10`，上交给子接口 `GE0/0/0.10`。该子接口**剥离 `VID=10` 标签**并脱去二层头，将 IP 报文交由路由模块。R1 查询路由表，命中直连路由 `192.168.20.0/24 → GE0/0/0.20`。
    
4. **目标侧 ARP 解析与子接口重打标** 若 R1 本地无 `192.168.20.1` 的 ARP 缓存，子接口 `GE0/0/0.20` 会封装一个带有 `VID=20` 标签的 ARP 广播请求发回交换机，获取 PC2 的 `MAC-B`。随后 R1 保持三层 IP 头部不变（仅 TTL 减 1），重写二层帧头为 `源MAC: MAC-R`、`目的MAC: MAC-B`，由子接口 `GE0/0/0.20` **打上 `VID=20` 标签**，沿同一物理链路发回 LSW1。
    
5. **Trunk 接收与 Access 出站剥标交付** LSW1 的 Trunk 口 `GE0/0/1` 收到带 `VID=20` 标签的帧，在 VLAN 20 广播域内查 MAC 表找到 PC2 所在 Access 口，**剥离 `VID=20` 标签**后还原为标准无标签以太网帧，精准送达 PC2。



![](Pasted%20image%2020261120175115.png)

- R1使用一个物理接口（GE0/0/1）与交换机SW1对接，并基于该物理接口创建两个子接口：GE0/0/1.10及GE0/0/1.20，分别使用这两个子接口作为VLAN 10及VLAN 20的默认网关。

- 由于三层子接口不支持VLAN报文，当它收到VLAN报文时，会将VLAN报文当成是非法报文而丢弃。因此，需要在子接口上将VLAN Tag剥掉，也就是需要VLAN终结（VLAN Termination）。




![](20261120_180043.jpg)






![](Pasted%20image%2020261120180614.png)

- 子接口终结VLAN的实质包含两个方面：
	- 对接口接收到报文，剥除VLAN标签后进行三层转发或其他处理。
	- 对接口发出的报文，又将相应的VLAN标签添加到报文中后再发送。
