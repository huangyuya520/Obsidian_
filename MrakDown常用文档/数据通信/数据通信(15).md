## 概述
**访问控制列表（ACL，Access Control List）** 是==一种由按顺序排列的规则组成的权限或流量过滤清单，用于控制主体（用户、用户组、进程或网络流量）对客体（文件、目录、系统资源或网络节点）的访问==。

==主要应用场景==

- **网络设备（路由器、交换机、防火墙）**：充当报文过滤器，基于源/目的 IP、MAC 地址、协议类型、端口号或时间段等条件决定数据包是允许（`permit`）还是拒绝（`deny`），也常用于配合 NAT、QoS 和路由策略。 [[1](https://www.cnblogs.com/romin/p/15680566.html), [2](https://juejin.cn/post/7347668702039097398), [3](https://info.support.huawei.com/info-finder/encyclopedia/zh/ACL.html)]

- **操作系统与文件系统（如 Linux、Windows）**：在传统属主/属组/其他权限之外，为特定用户或用户组精细配置文件和目录的读写执行权限。 [[1](https://www.cnblogs.com/sparkdev/p/5536868.html), [2](https://learn.microsoft.com/zh-cn/windows-hardware/drivers/ifs/access-control-list)]

- **云存储与对象存储**：定义哪些账号、群组或公开范围可以对存储桶或对象执行读取、写入或管理操作


==核心工作机制==

- **顺序匹配**：网络 ACL 通常按规则编号从上到下逐条匹配，一旦命中某条规则即执行动作并停止后续匹配。

- **默认拒绝**：许多网络 ACL 在规则列表末尾隐含“拒绝所有未匹配流量”的默认策略。

- **作用方向**：网络接口上的 ACL 通常区分入站（`IN`）和出站（`OUT`）方向。


==常见网络 ACL 分类（以常见厂商为例）==

- **基本 ACL（如华为 2000–2999 / 思科标准 ACL）**：主要基于源 IP 地址进行匹配，通常建议尽量靠近目的端应用。

- **高级 ACL（如华为 3000–3999 / 思科扩展 ACL）**：支持源/目的 IP、协议、源/目的端口及时间段等多维度精细匹配，通常建议尽量靠近源端应用。

- **二层 ACL（如华为 4000–4999）**：基于源/目的 MAC 地址、以太网帧类型或 VLAN 等二层信息过滤

- **用户自定义 ACL**（5000 – 5999）：报文头偏移量 + 字符串掩码，匹配非标准协议或特定载荷特征的报文



![](Pasted%20image%2020261122155156.png)

- 通过ACL可以实现对网络中报文流的精确识别和控制，达到控制网络访问行为、防止网络攻击和提高网络带宽利用率的目的，从而切实保障网络环境的安全性和网络服务质量的可靠性。
	- ACL是由permit或deny语句组成的一系列有顺序的规则的集合；它通过匹配报文的相关字段实现对报文的分类。
	- ACL是能够匹配一个IP数据包中的源IP地址、目的IP地址、协议类型、源目的端口等元素的基础性工具；ACL还能够用于匹配路由条目。

- 主要通过流量过滤来介绍ACL。

## ACL的组成

- ACL的组成：
	- ACL编号：在网络设备上配置ACL时，==每个ACL都需要分配一个编号，称为ACL编号，用来标识ACL。不同分类的ACL编号范围不同==。
	- 规则：前面提到了，一个ACL通常由若干条“permit/deny”语句组成，每条语句就是该ACL的一条规则。
	- 规则编号：每条规则都有一个相应的编号，称为规则编号，用来标识ACL规则。可以自定义，也可以系统自动分配。==ACL规则的编号范围是0～4294967294，所有规则均按照规则编号从小到大进行排序==。
	- 动作：每条规则中的permit或deny，就是与这条规则相对应的处理动作。permit指“允许”，deny指“拒绝”，但是ACL一般是结合其他技术使用，不同的场景，处理动作的含义也有所不同。

- 比如：ACL如果与流量过滤技术结合使用（即流量过滤中调用ACL），permit就是“允许通行”的意思，deny就是“拒绝通行”的意思。
	- 匹配项：ACL定义了极其丰富的匹配项。例子中体现的源地址，ACL还支持很多其他规则匹配项。例如，二层以太网帧头信息（如源MAC、目的MAC、以太帧协议类型）、三层报文信息（如目的地址、协议类型）以及四层报文信息（如TCP/UDP端口号）等。




![](Pasted%20image%2020261122163006.png)





## 规则编号

- 规则编号和步长的概念： 

	- 规则编号：每条规则都有一个相应的编号，称为规则编号，用来标识ACL规则。可以自定义，也可以系统自动分配。
	- 步长：系统自动为ACL规则分配编号时，每个相邻规则编号之间会有一个差值，这个差值称为“步长”。缺省步长为5，所以规则编号就是5/10/15…以此类推。

- 如果手工指定了一条规则，但未指定规则编号，系统就会使用大于当前ACL内最大规则编号且是步长整数倍的最小整数作为规则编号。
- 步长可以调整，如果将步长改为2，系统则会自动从当前步长值开始重新排列规则编号，规则编号就变成2、4、6…。

## 通配符


- 当进行IP地址匹配的时候，后面会跟着32位掩码位，这32位称为通配符。
- 通配符，也是点分十进制格式，换算成二进制后，“0”表示“匹配”，“1”表示“不关心”。
- 具体看下这2条规则：
	- rule 5: 拒绝源IP地址为10.1.1.1报文通过——因为通配符为全0，所以每一位都要严格匹配，因此匹配的是主机IP地址10.1.1.1；
	- rule 15:允许源IP地址为10.1.1.0/24网段地址的报文通过——因为通配符：0.0.0.11111111，后8位为1，表示不关心，因此10.1.1.xxxxxxxx 的后8位可以为任意值，所以匹配的是10.1.1.0/24网段。



![](Pasted%20image%2020261122163400.png)



![](Pasted%20image%2020261122163512.png)


- 如果想匹配192.168.1.0/24网段中的奇数IP地址，通配符该怎么写呢？
	- 我们先来看一看，奇数IP地址都有哪些：192.168.1.1、192.168.1.5、192.168.1.11……
	- 后八位写成二进制：192.168.1.00000001、192.168.1.00000101、192.168.1.00001011……
	- 可以看出共同点：最后8位的高7位是任意值，最低位固定为1，因此答案是：192.168.1.1 0.0.0.254（0.0.0.11111110）

- 这就得出了通配符的一个特点：通配符中的1或者0是可以不连续的。

- 还有两个特殊的通配符：
	- ==当通配符全为0来匹配IP地址时，表示精确匹配某个IP地址；==
	- ==当通配符全为1来匹配0.0.0.0地址时，表示匹配了所有IP地址。==










## ACL的分类及其工作原理


![](Pasted%20image%2020261122161600.png)


- 基于ACL规则定义方式的划分，可分为：
	- 基本ACL、高级ACL、二层ACL、用户自定义ACL和用户ACL。

- 基于ACL标识方法的划分，则可分为：
	- 数字型ACL和命名型ACL。

- 注意：用户在创建ACL时可以为其指定编号，不同的编号对应不同类型的ACL。同时，为了便于记忆和识别，用户还可以创建命名型ACL，即在创建ACL时为其设置名称。命名型ACL，也可以是“名称 数字”的形式，即在定义命名型ACL时，同时指定ACL编号。如果不指定编号，系统则会自动为其分配一个数字型ACL的编号。

### 基本 ACL
基本 ACL（Basic ACL，思科体系中称为标准 ACL / Standard ACL）是数据通信中最轻量、处理开销最小的访问控制列表类型。==它在华为/H3C 设备上的编号范围为 **2000 – 2999**，在思科设备上为 **1 – 99**（扩展范围 **1300 – 1999**）==。

基本 ACL 最核心的特征是“只看来源，不问去处和内容”**——==它仅基于 IP 报文的**源 IP 地址（以及分片标志、生效时间段等少量辅助条件）做粗粒度匹配，完全不检查目的 IP、传输层协议类型（TCP/UDP/ICMP）或端口号。==

==一、 基本 ACL 的匹配要素与能力边界==

在配置一条基本 ACL 规则时，设备能够识别的报文字段非常聚焦，具体如下表所示：

| **匹配字段**                   | **说明与常见用法**                                                                                          | **典型价值**                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------- | -------------------------------------- |
| **源 IP 地址 + 通配符掩码**        | 最核心的匹配条件。支持精确匹配单台主机（通配符 `0` 或 `0.0.0.0`）、匹配整个子网（如 `0.0.0.255`）、非连续奇偶匹配（如 `0.0.0.254`）以及匹配任意源（`any`）。 | 区分不同部门、网段或特定管理终端的流量。                   |
| **分片信息（`fragment`）**       | 指定该规则仅对**非首片 IP 分片报文**生效。                                                                            | 防止攻击者利用分片报文绕过安全策略（非首片报文不包含四层端口号）。      |
| **生效时间段（`time-range`）**    | 关联预先定义的周期性或绝对时间范围。                                                                                   | 实现分时段管控，例如仅在工作时间 `09:00–18:00` 放行特定网段。 |
| **VPN 实例（`vpn-instance`）** | 指定规则仅作用于某个特定的三层 VPN 实例（VRF）。                                                                         | 在多租户或 MPLS VPN 环境中隔离重叠的私网地址空间。         |

**能力边界：** 如果需求涉及“禁止访问某个**特定目标服务器**”、“只禁 Web（80/443）不禁 Ping（ICMP）”或“限制特定 TCP 标志位”，基本 ACL 均无法胜任，必须切换为**高级 ACL（3000–3999）**。


![](Pasted%20image%2020261122162513.png)

- 基本ACL：
	- 主要针对IP报文的源IP地址进行匹配，基本ACL的编号范围是2000-2999。
	- 比如这个例子，创建的是acl 2000，就意味着创建的是基本ACL。





### 高级ACL
高级 ACL（Advanced ACL，思科体系中称为扩展 ACL / Extended ACL）是数据通信网络中功能最完备、现网使用频率最高的访问控制列表。==它在华为/H3C 设备上的编号范围为 **3000 – 3999**，在思科设备上为 **100 – 199**（扩展范围 **2000 – 2699**）==。

相比只看源 IP 的基本 ACL，==高级 ACL 具备**三层（网络层）与四层（传输层）联合深度识别能力**——它能基于经典的“五元组”（源 IP、目的 IP、协议类型、源端口、目的端口）以及报文标志位、服务质量优先级等字段，实现“允许谁、以何种协议、访问哪台服务器的哪个具体端口”的精细化控制==。


==一、 高级 ACL 的核心匹配要素==

一条高级 ACL 规则可以从协议栈的多个维度精准刻画数据流，主要匹配字段如下表所示：

|**层次 / 维度**|**可匹配的报文字段**|**工程用途与说明**|
|---|---|---|
|**网络层（L3）**|源 IP + 通配符、目的 IP + 通配符|精确锁定通信双方的单台主机、网段或奇偶地址集。|
|**承载协议**|`ip`、`tcp`、`udp`、`icmp`、`ospf`、`gre`、协议号等|`ip` 代表匹配所有三层 IP 流量（包含 TCP/UDP/ICMP）；若需进一步匹配端口号，必须先指定 `tcp` 或 `udp`。|
|**传输层端口（L4）**|源端口（`source-port`）、目的端口（`destination-port`）|支持六类比较运算符：`eq`（等于）、`neq`（不等于）、`gt`（大于）、`lt`（小于）、`range`（端口区间，如 `range 20 21`）。|
|**控制标志与报文类型**|TCP 标志位（`syn`、`ack`、`rst`、`fin`、`established`）；ICMP 类型与代码（`echo`、`echo-reply` 等）|实现无状态设备上的**单向访问控制**（如允许内网主动连外网，但禁止外网主动发起连接）。|
|**服务质量（QoS）**|DSCP 值、IP 优先级（`precedence`）、ToS 值|识别高优先级业务流（如语音 `EF`、视频 `AF41`），配合 QoS 策略做队列调度或重标记。|
|**辅助条件**|分片标志（`fragment`）、生效时间段（`time-range`）、VPN 实例（`vpn-instance`）|用于防范分片攻击、分时段办公管控或多租户 VRF 流量隔离。|




### 二层ACL
二层 ACL（Layer 2 ACL，思科体系中称为 MAC ACL）**是工作在 OSI 模型**数据链路层（第 2 层）的访问控制列表。==它在华为/H3C 设备上的编号范围为 **4000 – 4999**，在思科设备上对应编号 **700 – 799** 或更常用的命名型扩展 MAC ACL（`mac access-list extended`）==。

与工作在网络层和传输层的基本/高级 ACL 不同，二层 ACL **不解析 IP 地址和端口号，而是直接读取以太网帧头部字段**（源/目的 MAC 地址、VLAN 标签、802.1p 优先级、以太网协议类型 EtherType）进行流量识别与过滤。它最核心的工程价值在于：**管控非 IP 协议流量（如 ARP、PPPoE、LLDP）**，以及在**接入层交换机上实现同一 VLAN 内部的二层精准隔离与硬件级 QoS 分类**。
