## 概述
**访问控制列表（ACL，Access Control List）** 是==一种由按顺序排列的规则组成的权限或流量过滤清单，用于控制主体（用户、用户组、进程或网络流量）对客体（文件、目录、系统资源或网络节点）的访问==。

==主要应用场景==

- **网络设备（路由器、交换机、防火墙）**：充当报文过滤器，基于源/目的 IP、MAC 地址、协议类型、端口号或时间段等条件决定数据包是允许（`permit`）还是拒绝（`deny`），也常用于配合 NAT、QoS 和路由策略。 [[1](https://www.cnblogs.com/romin/p/15680566.html), [2](https://juejin.cn/post/7347668702039097398), [3](https://info.support.huawei.com/info-finder/encyclopedia/zh/ACL.html)]

- **操作系统与文件系统（如 Linux、Windows）**：在传统属主/属组/其他权限之外，为特定用户或用户组精细配置文件和目录的读写执行权限。 [[1](https://www.cnblogs.com/sparkdev/p/5536868.html), [2](https://learn.microsoft.com/zh-cn/windows-hardware/drivers/ifs/access-control-list)]

- **云存储与对象存储**：定义哪些账号、群组或公开范围可以对存储桶或对象执行读取、写入或管理操作


==核心工作机制==

- **顺序匹配**：网络 ACL 通常按规则编号从上到下逐条匹配，一旦命中某条规则即执行动作并停止后续匹配。

- **默认拒绝**：许多网络 ACL 在规则列表末尾隐含“拒绝所有未匹配流量”的默认策略。

- **作用方向**：网络接口上的 ACL 通常区分入站（`IN`）和出站（`OUT`）方向。


==常见网络 ACL 分类（以常见厂商为例）==

- **基本 ACL（如华为 2000–2999 / 思科标准 ACL）**：主要基于源 IP 地址进行匹配，通常建议尽量靠近目的端应用。

- **高级 ACL（如华为 3000–3999 / 思科扩展 ACL）**：支持源/目的 IP、协议、源/目的端口及时间段等多维度精细匹配，通常建议尽量靠近源端应用。

- **二层 ACL（如华为 4000–4999）**：基于源/目的 MAC 地址、以太网帧类型或 VLAN 等二层信息过滤

- **用户自定义 ACL**（5000 – 5999）：报文头偏移量 + 字符串掩码，匹配非标准协议或特定载荷特征的报文



![](Pasted%20image%2020261122155156.png)

- 通过ACL可以实现对网络中报文流的精确识别和控制，达到控制网络访问行为、防止网络攻击和提高网络带宽利用率的目的，从而切实保障网络环境的安全性和网络服务质量的可靠性。
	- ACL是由permit或deny语句组成的一系列有顺序的规则的集合；它通过匹配报文的相关字段实现对报文的分类。
	- ACL是能够匹配一个IP数据包中的源IP地址、目的IP地址、协议类型、源目的端口等元素的基础性工具；ACL还能够用于匹配路由条目。

- 主要通过流量过滤来介绍ACL。

## ACL的分类及其工作原理


![](Pasted%20image%2020261122161600.png)


- 基于ACL规则定义方式的划分，可分为：
	- 基本ACL、高级ACL、二层ACL、用户自定义ACL和用户ACL。

- 基于ACL标识方法的划分，则可分为：
	- 数字型ACL和命名型ACL。

- 注意：用户在创建ACL时可以为其指定编号，不同的编号对应不同类型的ACL。同时，为了便于记忆和识别，用户还可以创建命名型ACL，即在创建ACL时为其设置名称。命名型ACL，也可以是“名称 数字”的形式，即在定义命名型ACL时，同时指定ACL编号。如果不指定编号，系统则会自动为其分配一个数字型ACL的编号。

### 基本 ACL
基本 ACL（Basic ACL，思科体系中称为标准 ACL / Standard ACL）是数据通信中最轻量、处理开销最小的访问控制列表类型。它在华为/H3C 设备上的编号范围为 **2000 – 2999**，在思科设备上为 **1 – 99**（扩展范围 **1300 – 1999**）。

基本 ACL 最核心的特征是“只看来源，不问去处和内容”**——它仅基于 IP 报文的**源 IP 地址（以及分片标志、生效时间段等少量辅助条件）做粗粒度匹配，完全不检查目的 IP、传输层协议类型（TCP/UDP/ICMP）或端口号。

==一、 基本 ACL 的匹配要素与能力边界==

在配置一条基本 ACL 规则时，设备能够识别的报文字段非常聚焦，具体如下表所示：

|**匹配字段**|**说明与常见用法**|**典型价值**|
|---|---|---|
|**源 IP 地址 + 通配符掩码**|最核心的匹配条件。支持精确匹配单台主机（通配符 `0` 或 `0.0.0.0`）、匹配整个子网（如 `0.0.0.255`）、非连续奇偶匹配（如 `0.0.0.254`）以及匹配任意源（`any`）。|区分不同部门、网段或特定管理终端的流量。|
|**分片信息（`fragment`）**|指定该规则仅对**非首片 IP 分片报文**生效。|防止攻击者利用分片报文绕过安全策略（非首片报文不包含四层端口号）。|
|**生效时间段（`time-range`）**|关联预先定义的周期性或绝对时间范围。|实现分时段管控，例如仅在工作时间 `09:00–18:00` 放行特定网段。|
|**VPN 实例（`vpn-instance`）**|指定规则仅作用于某个特定的三层 VPN 实例（VRF）。|在多租户或 MPLS VPN 环境中隔离重叠的私网地址空间。|

**能力边界：** 如果需求涉及“禁止访问某个**特定目标服务器**”、“只禁 Web（80/443）不禁 Ping（ICMP）”或“限制特定 TCP 标志位”，基本 ACL 均无法胜任，必须切换为**高级 ACL（3000–3999）**。
