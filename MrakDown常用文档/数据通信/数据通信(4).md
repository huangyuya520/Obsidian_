
# 补：传输层


## 补：TCP


- TCP连接建立的详细过程如下：

	- 由TCP连接发起方（图中PC1），发送第一个SYN位置1的TCP报文。初始序列号a为一个随机生成的数字，因为没收到过来自PC2的任何报文，所以确认序列号为0 ；

	- 接收方（图中PC2）接收到合法的SYN报文之后，回复一个SYN和ACK置1的TCP报文。初始序列号b为一个随机生成的数字，同时因为此报文是回复给PC1的报文，所以确认序列号为a+1；

	- PC1接收到PC2发送的SYN和ACK置位的TCP报文后，回复一个ACK置位的报文，此时序列号为a+1,确认序列号为b+1。PC2收到之后，TCP双向连接建立。



### TCP的序列号与确认序列号
![](Pasted%20image%2020261020182206.png)



- 假设PC1要给PC2发送一段数据，传输过程如下：

	- 1. PC1将全部待TCP发送的数据按照字节为单位编上号。假设第一个字节的编号为“a+1”，第二个字节的序号为“a+2”，依次类推。

	- 2. PC1会把每一段数据的第一个字节的编号作为序列号（Sequence  number），然后将TCP报文发送出去。

	- 3. PC2在收到PC1发送来的TCP报文后，需要给予确认同时请求下一段数据，如何确定下一段数据呢？序列号( a+1 )+载荷长度=下一段数据的第一个字节的序号（a+1+12）

	- 4. PC1在收到PC2发送的TCP报文之后，发现确认序列号为“a+1+12” ，说明“a+1”到“a+12”这一段的数据已经被接受，需要从“a+1+12”开始发送。

- 为了提升发送效率，也可以一次性发送多段数据，由接收方统一确认。



### 滑动窗口
![](Pasted%20image%2020261020183152.png)

- 1. 在TCP三次握手建立连接时，双方都会通过Window字段告诉对方本端最大能够接受的字节数（也就是缓冲区大小）。

- 2. 连接建立成功之后，发送方会根据接受方宣告的Window大小发送相应字节数的数据。

- 3. 接受方接受到数据之后会放在缓冲区内，等待上层应用来取走缓冲的数据。若数据被上层取走，则相应的缓冲空间将被释放。

- 4. 接收方根据自身的缓存空间大小通告当前的可以接受的数据大小( Window )。

- 5. 发送方根据接收方当前的Window大小发送相应数量的数据。

## 补：DNS

DNS 采用分布式树状层级结构，主要涉及以下几类服务器： [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/DNS.html)]

- **客户端（DNS Client / Resolver）**：发起解析请求的设备或浏览器（如你的电脑、手机）。 [[1](https://www.cloudflare.com/zh-cn/learning/dns/what-is-dns/), [2](https://info.support.huawei.com/info-finder/encyclopedia/zh/DNS.html)]

- **本地域名服务器（Local DNS / 递归服务器）**：通常由运营商（ISP）、公司或公共服务商提供（如腾讯 `119.29.29.29`、阿里 `223.5.5.5`），负责接受客户端的**递归查询**并代理完成整个查找过程。 [[1](https://help.aliyun.com/zh/dns/basic-concepts-dns2-0), [2](https://developer.cloud.tencent.com/article/2554861)]

- **根域名服务器（Root Name Server）**：最高级别的 DNS 服务器，知道所有顶级域名服务器的地址。 [[1](https://www.cloudflare.com/zh-cn/learning/dns/what-is-dns/), [2](https://help.aliyun.com/zh/dns/basic-concepts-dns2-0)]


- **顶级域服务器（TLD Server）**：管理特定顶级域名（如 `.com`、`.cn`、`.org` 等）的服务器。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/DNS.html), [2](https://www.cloudflare.com/zh-cn/learning/dns/what-is-dns/)]

- **权威域名服务器（Authoritative DNS Server）**：由具体域名持有者维护，存储着该域名与最终 IP 地址的准确映射记录




==DNS 完整解析过程（以查询 `www.example.com` 为例）==

当你在浏览器输入网址并回车时，标准解析过程通常包含以下步骤：

- **查询本地缓存**：
    - 浏览器缓存 → 操作系统缓存 → 路由器缓存 → 本地 HOSTS 文件。如果找到则直接返回，流程结束。

- **向本地域名服务器发起递归查询**：
    - 如果本地没有缓存，客户端向**本地域名服务器**发送请求：“请告诉我 `www.example.com` 的 IP 是多少？” [[1](https://help.aliyun.com/zh/dns/basic-concepts-dns2-0)]

- **本地域名服务器进行迭代查询**：
    - **问根服务器**：本地域名服务器向**根域名服务器** (`.`) 发起请求。根服务器不直接返回 IP，而是回答：“我不知道具体的 IP，但你可以去问 `.com` **顶级域服务器**”。
    - **问 TLD 服务器**：本地域名服务器转向询问 `.com` 顶级域服务器。`.com` 服务器回答：“请去问 `example.com` 的**权威域名服务器**”。
    - **问权威服务器**：本地域名服务器向 `example.com` 的权威域名服务器发起请求，最终获得该域名对应的准确 IP 地址。 [[1](https://help.aliyun.com/zh/dns/basic-concepts-dns2-0)]

- **返回结果并缓存**：
    - 本地域名服务器将获取到的 IP 地址返回给客户端，供浏览器建立连接，同时在本地进行**缓存**（缓存时间由记录的 **TTL** 值决定）



==常见 DNS 记录类型==

|记录类型|用途说明|
|---|---|
|**A**|将域名指向一个 IPv4 地址|
|**AAAA**|将域名指向一个 IPv6 地址|
|**CNAME**|将域名指向另一个域名（别名）|
|**MX**|将域名指向邮件服务器地址，用于接收邮件|
|**TXT**|存储文本信息，常用于域名所有权验证和 SPF 反垃圾邮件记录|
|**NS**|指定该域名由哪台 DNS 服务器进行解析|








## 补：FTP
==核心工作机制：双通道连接==

FTP 的最大特点是**使用两条独立的 TCP 连接**来完成通信，而不是像 HTTP 那样一条连接复用： [[1](https://www.fortinet.com/cn/resources/cyberglossary/file-transfer-protocol-ftp-meaning), [2](https://support.huawei.com/enterprise/zh/doc/EDOC1100366530/8be4b698)]

- **控制连接（Control Connection）**：
    - **端口**：通常为 ==**TCP 21 端口**==。
    - **作用**：用于传输 FTP 命名、参数协商以及服务器的响应码（例如登录认证、切换目录、发送传输指令等）。
    - **生命周期**：在整个会话期间一直保持开启。 [[1](https://blog.csdn.net/weixin_44214434/article/details/128340482), [2](https://www.ruijie.com.cn/jszl/90136/)]

- **数据连接（Data Connection）**：
    - **端口**：通常为 ==**TCP 20 端口**==（主动模式下）或动态高位端口（被动模式下）。
    - **作用**：专用于实际的文件数据传输（如上传、下载文件或列出目录）。
    - **生命周期**：传输文件时临时建立，传输完毕后即关闭



==两种工作模式==

由于防火墙和 NAT（网络地址转换）的存在，FTP 设计了两种工作模式，区别在于**谁来发起数据连接**： [[1](https://www.runoob.com/np/ftp-protocol.html)]

1. ==主动模式（Active Mode / PORT 模式）==

- **流程**：
    1. ==客户端通过一个随机的大于 1024 的端口（如 N）连接到服务器的控制端口（21）。==
    2. 客户端通过控制连接发送 `PORT N` 命令，告诉服务器：“我开启了 N 端口用来传数据，请你连过来”。
    3. 服务器从自己的 **20 端口** 主动向客户端的 N 端口发起 TCP 连接。 [[1](https://blog.csdn.net/weixin_44214434/article/details/128340482), [2](https://www.runoob.com/np/ftp-protocol.html)]

- **缺点**：客户端如果处于本地防火墙或 NAT 路由器后面，服务器无法主动穿透连接到客户端的临时端口，导致传输失败。 [[1](https://www.runoob.com/np/ftp-protocol.html)]


![](Pasted%20image%2020261022141003.png)








2. ==被动模式（Passive Mode / PASV 模式）==

- **流程**：
    1. ==客户端连接到服务器的控制端口（21），并发送 `PASV` 命令。==
    2. 服务器收到命令后，随机开放一个高位端口（如 P），并通过控制连接告诉客户端：“我在 P 端口等候数据连接”。
    3. 客户端从自己的某个高位端口主动连接到服务器的 P 端口，建立数据通道。 [[1](https://www.runoob.com/np/ftp-protocol.html)]

- **优点**：由客户端发起所有连接，极易穿透防火墙和 NAT 设备，是目前**最常用**的模式

##  补：Telnet
Telnet 是一种应用层网络协议，==基于**客户端-服务器（Client-Server）** 模型，用于通过 IP 网络远程登录和管理计算机或网络设备==


==基本工作原理==

- **基于 TCP 连接**：Telnet 依靠传输层的 **TCP** 协议来传输数据，默认使用 **23号端口**。 [[1](https://www.dotcom-monitor.com/zh-hans/%E4%BD%BF%E7%94%A8%E7%BD%91%E7%BB%9C%E7%9B%91%E8%A7%86%E5%99%A8%E5%AD%A6%E4%B9%A0/%E6%9C%AF%E8%AF%AD%E8%A1%A8/%E4%BB%80%E4%B9%88%E6%98%AF-telnet%EF%BC%9F/), [2](https://www.reddit.com/r/ccna/comments/vpriqd/what_exactly_is_telnet/?tl=zh-hans), [3](https://www.cnblogs.com/zylSec/p/14707039.html)]

- **虚拟终端会话**：当客户端连接到 Telnet 服务器后，会在两者之间建立一个双向的文本通信通道，仿佛用户直接坐在远程主机前操作命令行一样。 [[1](https://www.lenovo.com/tw/zh/glossary/what-is-telnet/?srsltid=AYCX9vK1Dsgtc-SK-thPgxxQ0SK5twOYST87o8fHrE7etT4M1xBCf2bp), [2](https://blog.csdn.net/weixin_42175752/article/details/141568444)]

- **明文传输**：Telnet **不提供任何加密机制**。用户输入的账号、密码、执行的命令以及服务器的响应，全部通过**明文**在网络中传输，极易被网络抓包窃听



==工作流程==

- **建立连接**：客户端向服务端的 **23 端口**发起 TCP 三次握手，建立连接。

- **选项协商**：连接建立后，客户端与服务器通过 Telnet 命令进行“选项协商”（Negotiation），商定双方支持的终端类型、显示方式等参数。

- **身份认证**：服务器要求用户输入登录凭据（用户名和密码），验证通过后赋予相应的操作权限。

- **交互执行**：用户在客户端输入命令行，数据发送给服务器；服务器执行命令并将结果返回给客户端显示。

- **会话关闭**：当用户退出（如输入 `exit` 或 `logout`）时，断开 TCP 连接



==优缺点与现状==

- **优点**：协议简单、实现容易、几乎所有操作系统均支持，适合在封闭安全的局域网内进行基础设备调试。

- **缺点**：**严重的安全隐患**（明文传输密码和数据），一旦被中间人攻击或抓包，敏感信息会完全泄露。

- **现代替代方案**：在生产环境和公网中，Telnet 已基本被采用加密传输的 **SSH（Secure Shell）** 协议所取代

## 补：DHCP

DHCP（动态主机配置协议，Dynamic Host Configuration Protocol）是一种基于 **Client/Server（客户端/服务器）** 模式的网络协议，==使用 **UDP 协议**（服务器端口 67，客户端端口 68）==。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/DHCP.html), [2](https://www.guokeyun.com/news/technology/detail/917.html?navId=22), [3](https://zhuanlan.zhihu.com/p/338380656)]

它的核心作用是自动为网络中的设备分配 IP 地址、子网掩码、默认网关和 DNS 服务器等网络参数


==全新设备首次接入的 4 步交互过程（DORA 过程）==

当一台新设备（客户端）连接到支持 DHCP 的局域网时，它会经历以下四个经典步骤： [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/DHCP.html)]

- **发现阶段（DHCP Discover）— 广播**
    - **动作**：客户端在网络中以广播形式（目标 IP `255.255.255.255`，MAC 地址 `FF-FF-FF-FF-FF-FF`）发送 Discover 报文。
    - **目的**：寻找网络中哪台设备是 DHCP 服务器。 [[1](https://docs.oracle.com/cd/E24847_01/html/819-7058/dhcp-overview-3.html)]

- **提供阶段（DHCP Offer）— 广播或单播**
    - **动作**：收到 Discover 报文的 DHCP 服务器，从地址池中挑选一个未使用的 IP 地址，连同子网掩码、网关、DNS 等配置，通过 Offer 报文发送给客户端。
    - **说明**：如果局域网内有**多台** DHCP 服务器，客户端可能会收到多个 Offer，**通常只接受第一个收到的 Offer**。 [[1](https://juejin.cn/post/7000955621516247054), [2](https://docs.oracle.com/cd/E24847_01/html/819-7058/dhcp-overview-3.html)]

- **请求阶段（DHCP Request）— 广播**
    - **动作**：客户端选中其中一个 Offer 后，向全网广播发送 Request 报文，里面包含它所选中的 DHCP 服务器标识以及请求的 IP 地址。
    - **目的**：一方面告诉选中的服务器“我接受你的分配”；另一方面也是广播通知**其他所有** DHCP 服务器：大家可以把暂留的 IP 地址收回了。 [[1](https://juejin.cn/post/7000955621516247054)]

- **确认阶段（DHCP Acknowledgement / ACK）— 单播或广播**
    - **动作**：被选中的 DHCP 服务器收到 Request 报文后，发送一个 ACK 报文（包含最终确认的 IP 和租期信息）给客户端。
    - **结果**：客户端收到 ACK 后，将该 IP 配置到自己的网卡上，正式完成联网

==已联网设备的“二次连接”与“租约续期”==

- **重新连接（2-step 复用）**：
    - 已经获取过 IP 的设备再次开机或重新接入网络时，**无需**重复完整的 4 步，而是直接向 DHCP 服务器发送包含前一个 IP 的 `DHCP Request` 报文，服务器若核实无误则直接回 `DHCP ACK` 确认。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/DHCP.html)]

- **租约续期（Lease Renewal）**：
    - DHCP 分配的 IP 通常带有**租期（Lease）**(默认24h)。
    - **达到 50% 租期时间（T1）**：客户端会向原 DHCP 服务器发送单播 `Request` 报文请求延长租期。
    - **达到 87.5% 租期时间（T2）**：若 T1 续期失败，客户端会向全网广播 `Request` 报文，寻找任何可用的 DHCP 服务器进行续期



![](Pasted%20image%2020261022164517.png)
- 对于已分配的IP地址，若终端超过租期仍未续租，服务器端判断该终端不再需要使用该IP地址，将IP地址回收，可继续分配给其他终端。


![](55de154dacca585708f583527a4cd5db_720.jpg)






跨网段分配：DHCP 中继（DHCP Relay）

- 在大型企业或多网段网络中，DHCP 服务器通常集中部署在某个核心网段，而客户端分布在不同子网。

- 因为路由器的**三层接口会直接丢弃广播包**（Discover），所以在网关设备上需要开启 **DHCP 中继代理** 功能。中继收到客户端的广播 Discover 后，会将其转换为**单播**报文转发给指定的 DHCP 服务器，再把服务器的回复转交给客户端







## 补：NTP
NTP（Network Time Protocol，[网络时间协议](https://zh.wikipedia.org/zh-hans/%E7%B6%B2%E8%B7%AF%E6%99%82%E9%96%93%E5%8D%94%E5%AE%9A)）是==用来在计算机网络中使各种系统时间保持同步的**应用层协议**==。


==核心特点==

- **传输方式**：基于 **UDP 协议**，默认使用 **123** 端口。

- **同步精度**：在局域网（LAN）内精度可达 **1 毫秒**以内；在广域网（WAN）内通常为**几十毫秒**。

- **主要版本**：目前广泛使用的是 **NTPv4**


![](Pasted%20image%2020261026150656.png)


- 目前主流的网络设备，如：AC（Access Controller，无线控制器）、AP（Access Point，接入点）、Firewall、Router、Switch、Server等基本都作为NTP的客户端，同时其中部分还可以作为NTP服务器端。
