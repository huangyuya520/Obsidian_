
# 数据转发原理


==一、二层交换机的数据转发原理（局域网内）==

二层交换机工作在数据链路层，基于 **MAC 地址**进行数据帧的转发。 [[1](https://blog.csdn.net/weixin_44938203/article/details/120687338)]

- **MAC 地址学习**：交换机内部维护一张 **MAC 地址表**（记录“MAC地址 -> 交换机端口”的映射关系）。当某端口收到数据帧时，交换机会记录该数据帧的**源 MAC 地址**和对应的接收端口。
- **查表转发**：交换机查看数据帧的**目的 MAC 地址**：
    - **单播（已知）**：如果在 MAC 地址表里找到了匹配的端口，就只把数据帧从该端口转发出去（单播）。
    - **广播（未知）**：如果在表中找不到目的 MAC 地址，则向除源端口以外的所有其他端口发送该数据帧（泛洪/广播）。 [[1](https://blog.csdn.net/weixin_44938203/article/details/120687338)]
- **建立单播关系**：当目标主机收到广播并回复信息时，交换机会再次学习其 MAC 地址并记录，从而建立起端到端的单播通信链路。 [[1](https://blog.csdn.net/weixin_44938203/article/details/120687338)]

交换机的两种主要转发模式

- **存储转发（Store-and-Forward）**：先把整个数据帧完整接收到缓冲区，进行 **FCS（帧校验序列）** 校验，确认无误后再转发（安全但稍慢）。

- **直通转发（Cut-Through）**：只读取数据帧前6个字节的目的 MAC 地址就立即开始转发（速度极快，但不做错误校验）




==二、 三层路由器的数据转发原理（跨网段/互联网==）

三层路由器工作在网络层，基于 **IP 地址**和**路由表**进行跨网段的数据包转发。 [[1](https://zhuanlan.zhihu.com/p/555220811)]

- **封装与解封装**：当数据从一个网段发往另一个网段时，每一跳都会进行封装和解封装。路由器剥离收到的数据帧，查看内部的 **IP 数据包**。 [[1](https://blog.51cto.com/garrett/6210109)]
- **查路由表**：路由器根据数据包中的**目的 IP 地址**，查找本地的**路由表**，决定该数据包的“下一跳（Next Hop）”IP 地址或出接口。 [[1](https://blog.csdn.net/YwlPy/article/details/106875186)]
- **修改 MAC 地址并转发**：
    - 路由器通过 **ARP 协议**获取下一跳 IP 地址对应的 **MAC 地址**。
    - 将数据包重新封装成新的数据帧，把源 MAC 地址改为路由器自己的出接口 MAC 地址，把目的 MAC 地址改为**下一跳的 MAC 地址**，然后发送出去。
    - 原本数据包里的**源 IP 和目的 IP 保持不变**，但每一跳的 MAC 地址都在不断改变。

## 补：ARP
==ARP协议（地址解析协议）默认只在同一广播域（通常是同一子网）中直接作用==

==ARP 的工作原理（请求与响应）==

整个过程遵循==**广播请求、单播应答**==的模式： 

- **查缓存（ARP Cache）**：
    - 主机A先查看本地的“ARP缓存表”，看里面有没有“主机B的IP -> MAC”的映射记录。
    - 如果有，直接使用；如果没有，则发起ARP请求。


- **广播请求（ARP Request，操作码为1）**：
    - 主机A在局域网内发送一个**广播**帧（目标MAC地址为 `FF-FF-FF-FF-FF-FF`），内容类似于：“我的IP是192.168.1.1（MAC A），请问谁的IP是192.168.1.2？请把你的MAC地址告诉我”。
    - 局域网内的所有设备都会收到这个广播包。 



- **核对与单播应答（ARP Reply，操作码为2）**：
    - 其他设备收到后，发现IP不匹配，就会丢弃该请求。
    - 只有真正的目标设备（主机B）发现这个IP是自己的，它会把主机A的“IP-MAC”记录到自己的缓存中，然后向主机A发送一个**单播**应答：“我就是192.168.1.2，我的MAC地址是MAC B”。


- **存入缓存**：
    - 主机A收到B的应答后，把“主机B的IP与MAC地址的对应关系”存入自己的ARP缓存表中（通常有几分钟到20分钟不等的生存周期/TTL），下次直接查询即可。


==常见的 ARP 类型与衍生概念==

- **ARP缓存表（ARP Cache）**：设备上维护的IP到MAC的映射列表，分为**动态**（自动学习、会超时老化）和**静态**（手动配置、永久有效）。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/ARP.html), [2](https://javaguide.cn/cs-basics/network/arp.html)]
- **免费ARP（Gratuitous ARP）**：设备启动或IP改变时，自己向网络发送一个ARP请求（查询自己的IP）。用来**检测IP地址冲突**或**通知其他设备更新MAC地址**。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/ARP.html)]
- **代理ARP（Proxy ARP）**：当处于不同网段但物理连通的设备需要通信时，由路由器等网关设备代为回答ARP请求，隐藏底层物理拓扑细节。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/ARP.html)]
- **RARP（Reverse ARP）**：逆地址解析协议，功能相反，通过已知的MAC地址反向查询IP地址（常用于无盘工作站启动）




==如果在特殊组网下，主机需要跨广播域获取MAC地址，通常需要借助**代理ARP==（Proxy ARP）**： [[1](https://blog.csdn.net/sinat_38673660/article/details/107094481), [2](https://blog.csdn.net/weixin_55238862/article/details/160534372)]

- **代理ARP原理**：当一台主机向另一台广播域之外（但处于同一逻辑网段或配置了代理）的目标IP发送ARP请求时，连接两端的路由器（或三层设备）会“挺身而出”，用自己的MAC地址去回应这个ARP请求。
- 这样，发送方就会把发往目标IP的流量先发送给路由器，由路由器再进行三层转发




## 补：交换机
==交换机（Switch）是一种用于电信号或光信号转发的网络设备==，主要用于在局域网（LAN）中连接计算机、服务器、打印机、IP摄像头等各种终端设备，实现数据的高效传输与共享

==核心工作原理==

交换机主要工作在OSI模型的数据链路层（部分高级交换机支持网络层）： [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/%E4%BA%A4%E6%8D%A2%E6%9C%BA.html), [2](https://zhuanlan.zhihu.com/p/687454939)]

- **地址学习（MAC Address Learning）**：当数据帧进入某个端口时，交换机会记录该数据帧的**源MAC地址**与对应端口，存入MAC地址表。 [[1](https://www.youtube.com/watch?v=oJf6QWidHbw), [2](https://zhuanlan.zhihu.com/p/687454939)]

- **数据转发（Forwarding & Filtering）**：检查数据帧的**目的MAC地址**。如果在地址表中找到匹配项，则将数据从该目标端口单独转发出去（点对点通信）；如果未找到，则向除源端口外的所有端口进行**广播**。 [[1](https://zhuanlan.zhihu.com/p/687454939)]

- **回路与冲突避免**：通过独享通道和缓存机制，避免网络冲突，大幅提升网络传输效率









- ==二层交换机工作在数据链路层==，它对数据帧的转发是建立在MAC地址基础之上的。交换机不同的接口发送和接收数据是独立的，各接口属于不同的冲突域，因此有效地隔离了网络中的冲突域。

- 二层交换设备通过学习以太网数据帧的源MAC地址来维护MAC地址与接口的对应关系（保存MAC与接口对应关系的表称为MAC地址表），通过其目的MAC地址来查找MAC地址表决定向哪个接口转发。

## 不同网段的访问原理
不同网段的主机之间进行访问，==**核心依赖于路由器（网关）进行跨网段路由转发，并借助 ARP 协议逐跳封装硬件地址（MAC地址）**==

假设主机 A（网段 1）要访问主机 B（网段 2），其完整工作过程如下：

==一、 核心前提：判断是否在同一网段==

- **子网掩码计算**：主机 A 会将自己的 IP 地址与子网掩码进行“按位与”运算，得出自己所在的网段；同时拿目标主机 B 的 IP 地址做同样的运算。

- **得出结论**：发现两者的网段不一致（不在同一个广播域），主机 A 确定**不能直接发送**，必须将数据包交给**默认网关**（通常是路由器的本地接口）。



==二、 准备阶段：获取网关的 MAC 地址==

- **检查本地ARP缓存**：主机 A 查看自己的 ARP 缓存表，寻找默认网关的 IP 地址对应的 MAC 地址。 [[1](https://developer.aliyun.com/article/1110649), [2](https://support.huawei.com/enterprise/zh/doc/EDOC1100517643/1fe67885/understanding-arp)]

- **发送 ARP 请求（若缓存中没有）**：
    - 主机 A 在本网段内广播发送一个 ARP 请求：“谁是网关的 IP？请把你的 MAC 地址告诉我的 IP”。
    - 默认网关（路由器接口）收到该广播后，单播回复自己的 MAC 地址。
    - 主机 A 收到并记录该网关的 MAC 地址



==三、 数据包封装与发送==

主机 A 将数据包封装好后交向物理层发送： [[1](https://zhuanlan.zhihu.com/p/702753655)]

- **IP 头部**：源 IP 是 **主机 A 的 IP**，目标 IP 是 **主机 B 的 IP**（在整个传输过程中，IP 地址始终保持不变）。
- **MAC 头部（二层封装）**：源 MAC 是 **主机 A 的 MAC**，目标 MAC 填写的是**默认网关的 MAC 地址**（绝不是主机 B 的 MAC）



==四、 路由器（网关）的转发过程==

- **解封装与查表**：
    - 路由器收到该数据帧，发现目标 MAC 是自己，于是剥离二层 MAC 头部，露出里面的 IP 数据包。
    - 查看 IP 数据包的目标 IP（主机 B 的 IP），查询自己的**路由表**（Routing Table），判断该目标 IP 应该从哪一个接口转发出去。 [[1](https://www.cnblogs.com/noteTech/p/19460405), [2](https://cloud.tencent.com/developer/article/2377686)]

- **重新封装 MAC 地址**：
    - 路由器通过目标网段的 ARP 协议，获取到下一跳设备（或者是主机 B 本身）的 MAC 地址。
    - ==路由器**重新封装**数据帧：源 MAC 改为**路由器出接口的 MAC**，目标 MAC 改为**下一跳/主机 B 的 MAC**，而源 IP 和目标 IP 保持不变==。 [[1](https://cloud.tencent.com/developer/news/3490439), [2](https://www.cnblogs.com/noteTech/p/19460405)]

- **逐跳传递**：
    - 如果中间有多个路由器，这个“解封装 -> 查路由表 -> 重新封装MAC -> 发送”的过程会一跳（Hop）一跳地接力，直到抵达主机 B 所在的局域网



==五、 到达目标主机==

- 主机 B 收到最终的数据帧，发现目标 MAC 和目标 IP 都是自己。

- 主机 B 剥离数据，交给上层协议（如 TCP/UDP/HTTP）处理，随后按照原路（或路由规则）返回应答数据包
