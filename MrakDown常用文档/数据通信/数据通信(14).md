
# NAT

![](Pasted%20image%2020261122113101.png)




## 概述
**NAT** 是 **网络地址转换（Network Address Translation）** 的缩写，是一种通过修改数据包 IP 头部地址（及端口），让多个内网设备共享一个或多个公网 IP 访问互联网的技术


==主要作用==

- **缓解 IPv4 地址短缺**：局域网内的设备使用私有 IP（如 `192.168.x.x`、`10.x.x.x`），对外统一转换为公网 IP。

- **隐藏内部网络**：外部网络无法直接看到或主动连接内网设备，提升基础网络安全与隐私。

- **解决网段冲突**：在企业或云网络互联时，转换重叠的私有网段


==常见类型==

- **静态 NAT**：私有 IP 与公网 IP 一对一固定映射，常用于对外提供服务的服务器。

- **动态 NAT**：从公网 IP 池中动态分配可用 IP 给内网设备。

- ==**端口地址转换（PAT / NAPT）**==：多个内网 IP 共享同一个公网 IP，通过不同**端口号**区分连接，最常见于家用路由器。


==常见应用场景==

- **家庭与办公宽带**：手机、电脑、电视通过路由器同时上网。

- **云计算（NAT 网关）**：云主机（VPC）访问公网，或统一管理出站流量。

- **联机游戏与 NAS（NAT 类型如 NAT1 / NAT2 / NAT3）**：NAT 穿透规则会影响 P2P 联机质量与远程访问体验

## nat技术原理
NAT 网关位于内网与公网的交界处，内部维护着一张实时更新的 **NAT 转换表（或会话表）**，记录转换前后的地址与端口对应关系。


例：
![](Pasted%20image%2020261122122251.png)



结合上图中的地址转换过程，数据包的完整交互分为两个方向：

1. **出方向（内网 → 公网）**：当内部网络中的 Host A（`192.168.1.1`，源端口 `3000`）和 Host B（`192.168.1.2`，源端口 `3010`）发出访问 Internet 的数据包到达边界路由器时，设备根据 NAT 策略将报文的**源 IP 地址**统一替换为公网地址 `202.0.0.1`，同时保留或重新分配唯一的源端口号（如 `3000` 与 `3010`），并将映射关系写入 NAT 转换表，最后重新计算 IP 与 TCP/UDP 校验和后发往公网。
    
2. **入方向（公网 → 内网）**：公网服务器返回的响应报文，其目的地址为 `202.0.0.1`，目的端口分别为 `3000` 或 `3010`。NAT 网关收到回包后，依据“目的 IP + 目的端口”检索 NAT 转换表，将目的地址精准还原为 `192.168.1.1` 或 `192.168.1.2`，重新计算校验和后转发给对应的内网主机。



![](Pasted%20image%2020261122122416.png)

- 由于私有地址无法在Internet上路由转发，访问Internet的IP数据包将缺乏路由无法到达私有网络出口设备。
- 如果使用了私有地址的私有网络需要访问Internet，必须在网络出口设备配置NAT，将访问Internet的IP数据报文中的私有网络源地址转换成公有网络源地址。






### 静态nat
**静态 NAT（Static NAT）** 是一种在私有 IP 地址与公有 IP 地址之间建立**永久性一对一（1:1）固定映射**的地址转换技术。只要映射规则生效，无论该内网主机当前是否产生网络流量，其绑定的公网 IP 都会被独占保留，不会分配给其他主机使用。

在数据通信体系中，静态 NAT 具备三个最核心的技术特征：

- **严格的一对一映射**：一个私网 IP 对应一个独立的公网 IP，**不具备节省 IPv4 公网地址的能力**。
    
- **仅转换三层 IP，不转换四层端口**：报文经过网关时只修改 IP 头部中的源/目的 IP 地址，TCP/UDP 端口号保持原样不变（同时重新计算 IP 头部及传输层校验和）。
    
- **天然支持双向互访**：不仅允许内网主机以固定的公网身份主动访问外网，也允许外网主机随时通过该公网 IP 主动发起对内网主机的连接。


==工作原理与报文转换过程==

静态 NAT 不依赖临时生成的动态会话来决定映射关系，而是直接依据管理员手工配置的**静态 NAT 映射表**进行转发。以下图中的内网服务器（`192.168.1.2`）与公网地址（`1.1.1.2`）建立静态映射为例，可以直观看到报文在双向流转时的字段变化：


例：
![](Pasted%20image%2020261122122728.png)



结合上图中的地址字段，静态 NAT 在两个方向上的处理逻辑非常对称：

1. **公网主动访问内网（入方向，图中上方流程）**：
    
    - 位于 Internet 的主机 `3.3.3.3`（源端口 `1025`）向公网映射地址 `1.1.1.2`（目的端口 `80`）发起访问请求。
        
    - 报文抵达边界防火墙（FW）时，设备检索静态 NAT 映射表，命中 `1.1.1.2 ↔ 192.168.1.2` 规则，将报文的**目的 IP**改写为 `192.168.1.2`，源 IP（`3.3.3.3`）及所有端口号（`1025`、`80`）均保持不变，随后将报文转发给内网服务器。

2. **内网响应或主动访问公网（出方向，图中下方流程）**：
    
    - 内网服务器 `192.168.1.2`（源端口 `80`）发出回包发往 `3.3.3.3`（目的端口 `1025`）。
        
    - 报文到达边界设备 FW 后，设备匹配同一条静态映射规则，将报文的**源 IP**从 `192.168.1.2` 替换为 `1.1.1.2`，端口号依旧保持原样，最后发往公网主机 `3.3.3.3`。
        
    - 若内网主机 `192.168.1.2` 主动向外网发起新连接，边界设备同样会执行上述出方向替换，将其源 IP 固定伪装为 `1.1.1.2`

### 动态nat
**动态 NAT（Dynamic NAT，又称基于地址池的 No-PAT）** 是一种在私有网络与公有网络边界，通过**公网地址池（Address Pool）** 为内网主机**按需、临时分配一对一公网 IP**的地址转换技术。

与静态 NAT 的“永久固定绑定”不同，动态 NAT 不将公网 IP 写死给某一台特定主机，而是把一组公网 IP 放入共享地址池中，遵循“**先到先得、用完归还**”的原则动态调度。在数据通信体系中，它具有四个核心特征：

- **池化多对多映射，瞬时仍是一对一**：从整体规划看是“多台私网主机共享多个公网 IP”，但在任意时刻，**一个公网 IP 只能被一台内网主机独占**。
    
- **仅转换三层 IP，不转换四层端口（No-PAT）**：转换过程中只改写 IP 报头的源/目的 IP 地址并重算校验和，TCP/UDP 端口号保持原样不变。
    
- **仅支持内网主动发起连接**：映射表项是在内网流量首次触发出向转发时动态生成的，外网主机无法主动发起对内网主机的访问。
    
- **并发上限受限于地址池容量**：能够**同时**访问外网的内网主机数量，严格小于或等于地址池中可用公网 IP 的总数；它只能靠“分时复用”缓解地址压力，**无法解决高并发场景下的 IPv4 地址枯竭问题**。



==工作原理与地址池生命周期==

动态 NAT 的核心运行依赖两个组件：**ACL（访问控制列表，用于界定哪些私网网段允许转换）** 与**公网地址池（提供待分配的合法公网 IP）**。其完整工作周期包含五个阶段：

1. **ACL 匹配与触发**：内网主机（如 `192.168.1.10`）发出访问公网的报文，抵达边界 NAT 网关的出接口后，设备首先检查该源 IP 是否命中关联的 ACL `permit` 规则。
    
2. **动态分配与建表**：命中 ACL 后，网关检索公网地址池，挑选一个当前处于空闲（Idle）状态的公网 IP（如 `202.100.1.10`），将其标记为已占用，并在内存中动态生成一条 **NAT 转换表项（会话表）**，随后将报文源 IP 替换为 `202.100.1.10`（端口不变）发出。
    
3. **回包查表与还原**：公网服务器将响应报文发往 `202.100.1.10`。边界网关收到入向回包后，以目的 IP 检索 NAT 转换表，命中对应条目后将目的 IP 还原为 `192.168.1.10`，重新计算校验和并转发回内网。
    
4. **地址池耗尽处理**：若地址池中仅有 2 个公网 IP 且均处于活跃占用状态，此时第 3 台内网主机发起出网请求，由于 No-PAT 模式不支持端口复用，网关无法分配公网地址，**该主机的出向报文将被直接丢弃**（或因无法转换而被运营商丢弃），直到有其他主机释放地址。
    
5. **超时老化与回收**：每条动态 NAT 表项都关联老化定时器（Aging Timer）。当对应主机的通信结束且在超时时间内无后续报文刷新时，网关自动删除该表项，并将对应的公网 IP 归还地址池，供其他内网主机重新申领。

### NAPT/PAT
**NAPT（Network Address Port Translation，网络地址端口转换）**，==在思科体系中也称为 **PAT（Port Address Translation）** 或 **Overload**==，是一种基于**公网地址池**、同时转换报文**三层 IP 地址与四层传输层端口号**的地址转换技术。

它是目前中大型企业网、校园网及运营商（CGNAT）中最核心的上网接入方式。相比纯动态 NAT（No-PAT），NAPT 的核心技术特征体现在四个方面：

- **多对多 / 多对一高并发复用**：突破了“一个公网 IP 同一时刻只能给一台内网主机使用”的瓶颈，利用不同的四层端口号区分多台内网主机，实现海量私网终端共享少量公网地址池 IP。
    
- **三层与四层联动转换**：不仅改写 IP 报头的源/目的 IP 地址，还同步改写 TCP/UDP 报头的源/目的端口号（随后重算 IP 首部及传输层校验和）。
    
- **仅支持内网主动发起连接**：映射表项由内网出向流量动态触发创建，会话超时后自动释放回收；公网主机无法主动向内网发起新连接。
    
- **自动解决端口冲突**：当多台内网主机碰巧使用相同的私网源端口对外访问时，NAPT 网关会自动为其重新分配互不冲突的公网源端口，保证回包精准分发。




==工作原理与报文转换流程==

NAPT 依赖 **ACL（界定允许转换的私网范围）**、**公网地址池（提供可用公网 IP）** 以及网关内存中实时维护的 **Session Table（会话表 / NAT 转换表）** 协同工作。



例：
![](Pasted%20image%2020261122135823.png)



结合上图中的地址池（`1.1.1.2` ～ `1.1.1.10`）与报文转换过程，一次完整的 NAPT 交互包含以下核心机制：

1. **出方向（内网主机 → 公网服务器）**：
    
    - 位于 Trust 区域的内网主机 `192.168.1.2` 使用源端口 `1025`，向 Untrust 区域的 Web 服务器 `3.3.3.3:80` 发起 HTTP 请求。
        
    - 报文抵达边界防火墙（FW）并命中源 NAT 策略后，设备从地址池中选取一个可用公网 IP（如 `1.1.1.2`），同时动态分配一个空闲公网源端口（如 `2048`）。
        
    - 设备将转换前后的映射关系写入 **Session Table**：`192.168.1.2:1025 [1.1.1.2:2048] → 3.3.3.3:80`，随后把报文的源 IP 与源端口改写为 `1.1.1.2:2048`，重新计算 IP 与 TCP 校验和后发往公网。

2. **多主机并发与端口复用**：
    
    - 如果此时同一内网的另一台主机 `192.168.1.3` 也恰好使用源端口 `1025` 访问 `3.3.3.3:80`，网关依然可以复用同一个公网 IP `1.1.1.2`，只需为其分配不同的公网源端口（例如 `2049`），并在会话表中新增独立记录。

3. **入方向（公网服务器 → 内网主机）**：
    
    - Web 服务器 `3.3.3.3:80` 返回的响应报文发往 `1.1.1.2:2048`。
        
    - 边界设备收到回包后，以五元组（协议、目的 IP `1.1.1.2`、目的端口 `2048` 等）精准检索 Session Table，命中对应表项后将目的 IP 与目的端口还原为 `192.168.1.2:1025`，重算校验和并转发给原始主机。


![](Pasted%20image%2020261122140715.png)

- NAPT借助端口可以实现一个公有地址同时对应多个私有地址。该模式同时对IP地址和传输层端口进行转换，实现不同私有地址（不同的私有地址，不同的源端口）映射到同一个公有地址（相同的公有地址，不同的源端口）。

#### Easy IP
==**Easy IP** 是 **NAPT（网络地址端口转换）** 的一种极简特例，指边界网关无需配置独立的公网地址池，而是**直接借用设备公网出接口自身的 IP 地址**作为转换后的源地址，并结合四层传输层端口号实现多台内网主机共享上网的技术==。

“Easy IP”是华为、新华三（H3C）等国内主流数通厂商的标准术语；在思科（Cisco）体系中，同等机制通常被称为**基于接口的 PAT（Interface Overload）**。它在数据通信中具备四个核心特征：

- **免地址池配置**：省去了规划和绑定公网地址池的步骤，只需通过 ACL 界定私网范围并关联到出接口即可生效。
    
- **天然适配动态公网 IP 场景**：当企业或分支机构通过 **PPPoE 拨号、DHCP 或 4G/5G 蜂窝链路**从运营商获取临时公网 IP 时，一旦公网 IP 发生变更，Easy IP 会自动跟随出接口的新 IP 进行转换，无需人工改动 NAT 配置。
    
- **多对一高性价比复用**：与动态 NAPT 相同，同时转换三层 IP 与四层端口号（ICMP 协议则借用报头中的 Identifier 字段），仅凭出接口这 1 个公网 IP 即可支撑多台内网终端并发访问外网。
    
- **仅支持单向主动出网**：映射表项由内网出向流量动态触发生成并随超时老化回收，公网侧无法主动发起对内网主机的连接。



==工作原理与报文转换流程==

Easy IP 依赖 **ACL（匹配允许上网的私网网段）**、**公网出接口 IP** 以及设备内存中实时维护的 **NAT 映射表（会话表）** 协同工作。


例：
![](Pasted%20image%2020261122143649.png)


结合上图中的地址转换过程（假设边界设备 Untrust 侧公网出接口 IP 为 `200.1.1.100`），数据包在双向转发时的处理逻辑如下：

1. **出方向转换与建表（Trust → Untrust）**：
    
    - 内网主机 `192.168.1.1` 使用源端口 `1023`，向公网服务器 `8.8.8.8:80` 发起访问请求。
        
    - 报文抵达边界设备并命中出接口上的 ACL 规则后，设备直接提取当前出接口的公网 IP `200.1.1.100`，并动态分配一个空闲的公网源端口 `39612`。
        
    - 设备在 NAT 映射表中记录 `192.168.1.1:1023 ↔ 200.1.1.100:39612`，随后将报文的源地址改写为 `200.1.1.100:39612`，重新计算 IP 及传输层校验和后发往 Internet。

2. **多主机并发复用同一出接口 IP**：
    
    - 同一时间，另一台内网主机 `192.168.1.2:1569` 也发起公网访问。设备同样将其源 IP 替换为出接口地址 `200.1.1.100`，但分配不同的公网源端口 `39613`，并在映射表中写入第二条独立表项，实现多终端并发隔离。

3. **入方向查表与还原（Untrust → Trust）**：
    
    - 公网服务器 `8.8.8.8:80` 返回的响应报文发往 `200.1.1.100:39612`。
        
    - 边界设备收到回包后，依据“目的 IP + 目的端口”检索 NAT 映射表，精准命中对应表项，将目的地址还原为 `192.168.1.1:1023`，重新计算校验和后转发回原始主机。
