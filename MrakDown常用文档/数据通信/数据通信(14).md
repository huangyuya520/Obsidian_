
# NAT

![](Pasted%20image%2020261122113101.png)




## 概述
**NAT** 是 **网络地址转换（Network Address Translation）** 的缩写，是一种通过修改数据包 IP 头部地址（及端口），让多个内网设备共享一个或多个公网 IP 访问互联网的技术


==主要作用==

- **缓解 IPv4 地址短缺**：局域网内的设备使用私有 IP（如 `192.168.x.x`、`10.x.x.x`），对外统一转换为公网 IP。

- **隐藏内部网络**：外部网络无法直接看到或主动连接内网设备，提升基础网络安全与隐私。

- **解决网段冲突**：在企业或云网络互联时，转换重叠的私有网段


==常见类型==

- **静态 NAT**：私有 IP 与公网 IP 一对一固定映射，常用于对外提供服务的服务器。

- **动态 NAT**：从公网 IP 池中动态分配可用 IP 给内网设备。

- ==**端口地址转换（PAT / NAPT）**==：多个内网 IP 共享同一个公网 IP，通过不同**端口号**区分连接，最常见于家用路由器。


==常见应用场景==

- **家庭与办公宽带**：手机、电脑、电视通过路由器同时上网。

- **云计算（NAT 网关）**：云主机（VPC）访问公网，或统一管理出站流量。

- **联机游戏与 NAS（NAT 类型如 NAT1 / NAT2 / NAT3）**：NAT 穿透规则会影响 P2P 联机质量与远程访问体验

## nat技术原理
NAT 网关位于内网与公网的交界处，内部维护着一张实时更新的 **NAT 转换表（或会话表）**，记录转换前后的地址与端口对应关系。


例：
![](Pasted%20image%2020261122122251.png)



结合上图中的地址转换过程，数据包的完整交互分为两个方向：

1. **出方向（内网 → 公网）**：当内部网络中的 Host A（`192.168.1.1`，源端口 `3000`）和 Host B（`192.168.1.2`，源端口 `3010`）发出访问 Internet 的数据包到达边界路由器时，设备根据 NAT 策略将报文的**源 IP 地址**统一替换为公网地址 `202.0.0.1`，同时保留或重新分配唯一的源端口号（如 `3000` 与 `3010`），并将映射关系写入 NAT 转换表，最后重新计算 IP 与 TCP/UDP 校验和后发往公网。
    
2. **入方向（公网 → 内网）**：公网服务器返回的响应报文，其目的地址为 `202.0.0.1`，目的端口分别为 `3000` 或 `3010`。NAT 网关收到回包后，依据“目的 IP + 目的端口”检索 NAT 转换表，将目的地址精准还原为 `192.168.1.1` 或 `192.168.1.2`，重新计算校验和后转发给对应的内网主机。



![](Pasted%20image%2020261122122416.png)

- 由于私有地址无法在Internet上路由转发，访问Internet的IP数据包将缺乏路由无法到达私有网络出口设备。
- 如果使用了私有地址的私有网络需要访问Internet，必须在网络出口设备配置NAT，将访问Internet的IP数据报文中的私有网络源地址转换成公有网络源地址。






### 静态nat
**静态 NAT（Static NAT）** 是一种在私有 IP 地址与公有 IP 地址之间建立**永久性一对一（1:1）固定映射**的地址转换技术。只要映射规则生效，无论该内网主机当前是否产生网络流量，其绑定的公网 IP 都会被独占保留，不会分配给其他主机使用。

在数据通信体系中，静态 NAT 具备三个最核心的技术特征：

- **严格的一对一映射**：一个私网 IP 对应一个独立的公网 IP，**不具备节省 IPv4 公网地址的能力**。
    
- **仅转换三层 IP，不转换四层端口**：报文经过网关时只修改 IP 头部中的源/目的 IP 地址，TCP/UDP 端口号保持原样不变（同时重新计算 IP 头部及传输层校验和）。
    
- **天然支持双向互访**：不仅允许内网主机以固定的公网身份主动访问外网，也允许外网主机随时通过该公网 IP 主动发起对内网主机的连接。


==工作原理与报文转换过程==

静态 NAT 不依赖临时生成的动态会话来决定映射关系，而是直接依据管理员手工配置的**静态 NAT 映射表**进行转发。以下图中的内网服务器（`192.168.1.2`）与公网地址（`1.1.1.2`）建立静态映射为例，可以直观看到报文在双向流转时的字段变化：


例：
![](Pasted%20image%2020261122122728.png)



结合上图中的地址字段，静态 NAT 在两个方向上的处理逻辑非常对称：

1. **公网主动访问内网（入方向，图中上方流程）**：
    
    - 位于 Internet 的主机 `3.3.3.3`（源端口 `1025`）向公网映射地址 `1.1.1.2`（目的端口 `80`）发起访问请求。
        
    - 报文抵达边界防火墙（FW）时，设备检索静态 NAT 映射表，命中 `1.1.1.2 ↔ 192.168.1.2` 规则，将报文的**目的 IP**改写为 `192.168.1.2`，源 IP（`3.3.3.3`）及所有端口号（`1025`、`80`）均保持不变，随后将报文转发给内网服务器。

2. **内网响应或主动访问公网（出方向，图中下方流程）**：
    
    - 内网服务器 `192.168.1.2`（源端口 `80`）发出回包发往 `3.3.3.3`（目的端口 `1025`）。
        
    - 报文到达边界设备 FW 后，设备匹配同一条静态映射规则，将报文的**源 IP**从 `192.168.1.2` 替换为 `1.1.1.2`，端口号依旧保持原样，最后发往公网主机 `3.3.3.3`。
        
    - 若内网主机 `192.168.1.2` 主动向外网发起新连接，边界设备同样会执行上述出方向替换，将其源 IP 固定伪装为 `1.1.1.2`
