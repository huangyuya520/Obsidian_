
# 生成树(STP)
**生成树协议**（Spanning Tree Protocol，简称 **STP**）是==一种工作在OSI网络模型**数据链路层（第二层）** 的通信协议==


## 概述

1. ==为什么需要生成树协议？==
在企业局域网中，为了提高网络的**可靠性**和**冗余度**，通常会使用多台交换机进行双链路或环形互联。但是，以太网帧没有像IP包那样的TTL（生存时间）字段。如果网络中存在物理环路，会带来严重后果：

- ==**广播风暴**：广播帧会在环路中无休止地循环转发，瞬间占满带宽。==

- **MAC地址表剧烈震荡**：交换机从不同端口收到相同的MAC地址，导致地址表混乱。

- **多帧复制**：同一台主机收到多份重复的数据帧。

STP 的核心作用就是**在逻辑上剪裁掉冗余链路，构建出一个没有环路的树状（Tree）拓扑结构**；当主用链路发生故障时，它还能自动打开被阻塞的备份链路，实现网络恢复


==一、 为什么需要生成树：二层环路的三大致命危害==

在引入链路备份或设备冗余的二层局域网中，若未部署生成树协议，物理环路会直接导致以下问题：

1. **广播风暴（Broadcast Storm）** 交换机对广播帧、未知单播帧和组播帧（统称 **BUM 流量**）执行“泛洪（Flooding）”操作——即从除接收端口外的所有活动端口转发。在环路中，一份广播帧会被反复复制并指数级放大，瞬间耗尽链路的全部带宽和交换机的 CPU/内存资源，导致整网瘫痪。
    
2. **MAC 地址表震荡（MAC Address Table Flapping）** 同一个数据帧沿环路的不同方向先后抵达同一台交换机的不同端口。交换机根据数据帧的源 MAC 地址不断刷新 CAM 表中的“MAC—端口”映射关系，导致表项在多个端口间剧烈抖动，造成正常单播流量大规模丢包。
    
3. **多帧复制（Multiple Frame Transmission）** 同一份单播数据帧可能通过不同路径多次送达目的主机，导致接收端收到重复报文，破坏上层应用协议的正常状态机。
    

> **STP 的核心设计思想**：在**物理上保留冗余链路**的前提下，通过交换机之间交互协议报文并运行生成树算法（STA），在**逻辑上阻塞（Blocking）特定冗余端口**，将物理有环拓扑裁剪为一棵无环的树形逻辑拓扑；当活动链路发生故障时，协议自动重新计算并将原阻塞端口切换为转发状态，实现链路自愈










- 随着局域网规模的不断扩大，越来越多的交换机被用来实现主机之间的互连。如图，接入层交换机单链路上联，则存在单链路故障，也就是如果这根上联链路发生故障，交换机下联用户就断网了。另一个问题的单点故障，也就是交换机如果宕机，交换机下联用户也就断网了。

- 为了解决此类问题，交换机在互连时一般都会使用冗余链路来实现备份。冗余链路虽然增强了网络的可靠性，但是也会产生环路，而环路会带来一系列的问题，继而导致通信质量下降和通信业务中断等问题。

- 在现实中，除了冗余链路会引起环路，还有一些人为错误导致的环路。

![](Pasted%20image%2020261112143203.png)



- 问题一：广播风暴
	- 根据交换机的转发原则，如果交换机从一个端口上接收到的是一个广播帧，或者是一个目的MAC地址未知的单播帧，则会将这个帧向除源端口之外的所有其他端口转发。如果交换网络中有环路，则这个帧会被无限转发，此时便会形成广播风暴，网络中也会充斥着重复的数据帧。
	- 本例中，SW3收到了一个广播帧将其进行泛洪，SW1和SW2也会将此帧转发到除了接收此帧的其他所有端口，结果此帧又会被再次转发给SW3，这种循环会一直持续，于是便产生了广播风暴。交换机性能会因此急速下降，并会导致业务中断。

- 问题二：MAC地址表漂移
	- 交换机是根据所接收到的数据帧的源地址和接收端口生成MAC地址表项的。
	- 本例中，SW3收到一个广播帧泛洪，SW1从GE0/0/1接口接收到广播帧后学习且泛洪，形成MAC地址5489-98EE-788A与GE0/0/1的映射；SW2收到广播帧后学习且泛洪，SW1再次从GE0/0/2收到源MAC地址为5489-98EE-788A的广播帧并进行学习，5489-98EE-788A会不断地在GE0/0/1与GE0/0/2接口之间来回切换，这被称为MAC地址漂移现象。


![](Pasted%20image%2020261112143233.png)




![](20261112_151922.jpg)





- 在以太网中，二层网络的环路会带来广播风暴，MAC地址表震荡，重复数据帧等问题，为解决交换网络中的环路问题，提出了STP。
- STP通过构造一棵树来消除交换网络中的环路。
- 运行STP算法，判断网络中存在环路的地方并阻断冗余链路，将环路网络修剪成无环路的树型网络，从而避免了数据帧在环路网络中的增生和无穷循环。

![](Pasted%20image%2020261112152003.png)






- 如图，交换机上运行STP协议，会通过报文监控网络的拓扑结构，正常情况下是将SW3上的一个接口进行阻塞（Block），从而打破环路，当监控到SW1与SW3之间出现链路故障，则恢复阻塞端口进入转发状态。

## STP基本工作原理


![](20261112_143750.jpg)






==STP 拓扑收敛与四大选举机制==
STP 通过交换机之间周期性发送 **==BPDU（Bridge Protocol Data Unit，桥协议数据单元）==** 来传递拓扑信息。网络中所有交换机依据“数值越小越优”的统一规则，通过比较 BPDU 中的四个关键参数（优先级向量：`{Root BID, RPC, Sender BID, Port ID}`）完成角色选举与路径裁决：


![](Pasted%20image%2020261112143953.png)




![](Pasted%20image%2020261113154147.png)

- 在STP中，每一台交换机都有一个标示符，叫做Bridge ID或者桥ID，桥ID由16位的桥优先级（Bridge Priority）和48位的MAC地址构成。在STP网络中，桥优先级是可以配置的，取值范围是0～65535，默认值为32768,可以修改但是修改值必须为1024的倍数。优先级最高的设备（数值越小越优先）会被选举为根桥。如果优先级相同，则会比较MAC地址，MAC地址越小则越优先。
- 如图，需要在该网络中选举根桥，首先比较三台交换机的桥优先级，桥优先级都为4096，再比较三台交换机的MAC地址，谁小谁优先，最终选择SW1为根桥。




三台交换机互联形成物理三角形环路后，经过生成树计算最终收敛为逻辑无环树形结构（其中 `LSW1` 为根桥，`LSW2` 为备份根桥，`LSW3` 的 `GE 0/0/2` 端口被逻辑阻塞为预备端口 `AP`）：

1. **==选举根桥（Root Bridge）==—— 比较最小根桥 ID（==Root BID==）**
    
    - **BID 结构**：由 `2字节桥优先级（默认 32768，步长 4096） + 6字节背板 MAC 地址` 组成。
        
    - **规则**：全网 BID 最小的交换机（图中 `LSW1`）当选为整棵生成树的逻辑中心（根桥），全网有且仅有一个根桥。



![](Pasted%20image%2020261113154057.png)


- 树形的网络结构必须有树根，于是STP引入了根桥（Root Bridge）概念。
- 对于一个STP网络，根桥在全网中只有一个，它是整个网络的逻辑中心，但不一定是物理中心。根桥会根据网络拓扑的变化而动态变化。
- 网络收敛后，根桥会按照一定的时间间隔产生并向外发送配置BPDU，其他设备仅对该报文进行处理，传达拓扑变化记录，从而保证拓扑的稳定。






2. **==选举根端口（Root Port, RP==）—— 比较最小根路径开销（==RPC==）**
    
    - **规则**：每台**非根桥**必须在自身所有端口中选出**有且仅有一个**距离根桥“最近”的端口作为根端口（图中 `LSW2` 与 `LSW3` 的 `GE 0/0/1`），用于向根桥方向转发数据。
        
    - **路径开销（Path Cost）**：与接口带宽成反比（例如 IEEE 802.1t 标准下，千兆端口(GE)开销为 `20000`，万兆端口为 `2000`）。RPC 在 BPDU **入向**累加，即沿途各段链路开销之和。



![](Pasted%20image%2020261113154349.png)

- 从一个非根桥到达根桥的路径可能有多条，每一条路径都有一个总的开销值，此开销值是该路径上所有接收BPDU端口的端口开销总和（即BPDU的入方向端口），称为路径开销。非根桥通过对比多条路径的路径开销，选出到达根桥的最短路径，这条最短路径的路径开销被称为RPC，并生成无环树状网络。根桥的根路径开销是0。






3. **==选举指定端口（Designated Port, DP）==（一个冲突域选取一个指定端口）—— 比较发送者 BID（Sender BID）**
    
    - **规则**：每个**网段（物理链路）** 上必须选出**有且仅有一个**指定端口，负责向该网段转发来自根桥的 BPDU 和业务流量。根桥上的所有活动端口默认均为 DP（图中 `LSW1` 的两个端口）；在 `LSW2` 与 `LSW3` 之间的链路上，若两者 RPC 相同，则比较双方自身的 BID，`LSW2` 更优，因此 `LSW2` 的 `GE 0/0/2` 当选为 DP。

4. **==阻塞冗余端口（Blocked / Alternate Port, AP）==—— 比较端口 ID（Port ID, PID）**
    
    - **PID 结构**：由 `1字节端口优先级（默认 128，步长 16） + 1字节端口号` 组成。当上述三个条件均相同时（常见于两台交换机之间存在多条直连平行链路），先比较上游发送端口的 PID，若仍相同则比较本地接收端口的 PID。
        
    - **结果**：既不是 RP 也不是 DP 的端口（图中 `LSW3` 的 `GE 0/0/2`）进入阻塞状态（RSTP/MSTP 中称为 **AP，预备端口**），逻辑上切断环路，平时仅接收 BPDU 监测上游链路状态，不转发任何用户业务流量。
