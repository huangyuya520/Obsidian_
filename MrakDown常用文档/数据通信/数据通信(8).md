
# IPV6
**IPv6**（Internet Protocol Version 6，即“互联网协议第6版”）==是网络层协议的第二代标准协议，也是用来替代上一代[IPv4](https://zh.wikipedia.org/wiki/IPv6)的升级版本==。随着互联网设备的爆发式增长，IPv4地址面临枯竭，IPv6因此被设计并推出


==一、 核心特点与优势==

- **海量的地址空间**：IPv4采用32位地址，总数约42亿个；而IPv6采用 **128位** 二进制地址，理论上可以提供 2¹²⁸ 个地址，足够为地球上的每一粒沙子分配一个独立的IP地址。 [[1](https://net.sjtu.edu.cn/info/1237/1870.htm), [2](https://www.youtube.com/watch?v=tD_ZpW8IuIQ), [3](https://info.support.huawei.com/info-finder/encyclopedia/zh/IPv6.html)]

- **告别NAT（网络地址转换）**：由于地址极为充足，每台联网设备（手机、电脑、智能家电等）都可以拥有属于自己的独立公网IP，实现真正意义上的“万物互联”。 [[1](https://www.youtube.com/watch?v=dQ1AMXAiEJk)]

- **简化的数据包头部**：IPv6报文头结构更精简，路由器处理数据包的效率更高。

- **内置安全性**：原生支持 **IPsec**（互联网协议安全），在网络层提供了更强的加密和身份验证机制。 [[1](https://aws.amazon.com/cn/compare/the-difference-between-ipv4-and-ipv6/)]


- **自动配置能力**：支持无状态地址自动配置（SLAAC），设备接入网络后可自动生成IP地址，大幅简化网络管理。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/IPv6.html)]


- **取消了广播机制**：改用组播（Multicast）和任播（Anycast），减少了网络中的无效流量广播

## 写法
==二、 IPv6 地址的格式==

IPv4 地址使用点分十进制（如 `192.168.1.1`）；而 IPv6 地址长度为128位，通常由 **8组16位十六进制数** 构成，组与组之间用冒号（`:`）分隔。 [[1](https://docs.oracle.com/cd/E19253-01/819-7058/ipv6-overview-7/index.html), [2](https://www.h3c.com/cn/d_200805/605746_473262_0.htm)]

- **标准写法示例**：`2001:0db8:85a3:0000:0000:8a2e:0370:7334`

- ==**简写规则**：==
    - ==每组前面的“0”可以省略（例如 `0370` 可写成 `370`）。==
    - ==连续多组为“0”的可用双冒号 `::` 代替（但整个地址中双冒号只能出现一次）==

==三、 IPv4 与 IPv6 对比一览==

| 特性            | IPv4                  | IPv6              |
| ------------- | --------------------- | ----------------- |
| **地址长度**      | 32位                   | 128位              |
| **地址总数**      | 约42亿                  | 近乎无限（2¹²⁸）        |
| **表示方式**      | 点分十进制（如 `172.16.0.1`） | 冒号十六进制            |
| **IPsec安全机制** | 可选（非强制）               | 原生内置支持            |
| **地址配置**      | 手动或DHCP               | 支持自动配置（SLAAC）     |
| **广播支持**      | 支持                    | ==不支持（由组播/任播替代）== |

## ipv6地址分类

==四、 IPv6 地址体系与分类规划==

IPv6地址为128位二进制，工程上采用冒号十六进制（Colon-Hexadecimal）表示法，划分为8组，每组16位（4个十六进制字符）。


1. 记法与压缩规范（RFC 5952）

- **压缩前导零**：每组中的前导零可省略，如 `:0042:` 可简写为 `:42:`，但单一组全零须保留一个 `0`。
    
- **双冒号压缩（`::`）**：连续的一组或多组全零字段可用双冒号替代，**全地址中仅允许出现一次双冒号**，以保证反向展开的唯一确定性。
    
- _示例_：`2001:0db8:0000:0000:0000:0000:0000:0001` $\rightarrow$ `2001:db8::1`。



2. ==地址核心分类==

| **地址类别**             | **前缀定义 / 范围**                  | **工程用途与特性**                                               |
| -------------------- | ------------------------------ | --------------------------------------------------------- |
| **全球单播地址 (GUA)**     | `2000::/3` (目前主流)              | 全网可路由的公网地址，由RIR/运营商层级化分配。标准端到端子网通常规划为 `/64`。              |
| **链路本地地址 (LLA)**     | `fe80::/10`                    | 仅在单一二层广播域（本地链路）有效，**路由器绝不转发**。用于IGP邻居建立、NDP交互及默认网关指向。     |
| ==**唯一本地地址 (ULA)**== | `fc00::/7` ==(常开 `fd00::/8`)== | ==等同于IPv4的RFC 1918私网地址，用于企业内部互联，公网不可路由。==                 |
| **组播地址 (Multicast)** | `ff00::/8`                     | 标识一组接口。取代广播；分为知名组播和请求节点组播。                                |
| **任播地址 (Anycast)**   | 共享单播地址空间                       | 多个物理节点配置同一单播IP，网络通过IGP/BGP将流量路由至拓扑上“最近”的节点（广泛用于DNS与CDN）。  |
| **特殊单播地址**           | `::1/128` (环回), `::/128` (未指定) | 分别对应IPv4的 `127.0.0.1`（本地Loopback）与 `0.0.0.0`（未分配状态/默认路由）。 |

### 组播和任播

![](20261108_133606.jpg)







![](Pasted%20image%2020261108134129.png)



- 单播地址（Unicast Address）：标识一个接口，目的地址为单播地址的报文会被送到被标识的接口。在IPv6中，一个接口拥有多个IPv6地址是非常常见的现象。除了全球单播地址、唯一本地地址、链路本地地址这三种地址之外，IPv6还有一些特殊单播地址的存在：

	- 未指定地址：0:0:0:0:0:0:0:0/128 或者::/128。该地址作为某些报文的源地址，比如作为重复地址检测时发送的邻居请求报文（NS）的源地址，或者DHCPv6初始化过程中客户端所发送的请求报文的源地址。

	- 环回地址：0:0:0:0:0:0:0:1/128 或者::1/128，与IPv4中的127.0.0.1作用相同，用于本地回环，发往::/1的数据包实际上就是发给本地，可用于本地协议栈环回测试。

- 组播地址（Multicast Address）：标识多个接口，目的地址为组播地址的报文会被送到被标识的所有接口。只有加入相应组播组的设备接口才会侦听发往该组播地址的报文。

- 任播地址（Anycast Address）：任播地址标识一组网络接口（通常属于不同的节点）。目标地址是任播地址的数据包将发送给其中路由意义上最近的一个网络接口。

- ==**IPv6没有定义广播地址（Broadcast Address）**==。在IPv6网络中，所有广播的应用层场景将会被IPv6组播所取代。




## ipv6报文

- IPv6基本包头字段解释如下：
	- Version：版本号，长度为4 bit。对于IPv6，该值为6。
	- Traffic Class：流类别，长度为8 bit。等同于IPv4中的ToS字段，表示IPv6数据包的类或优先级，主要应用于QoS。
	- Flow Label：流标签，长度为20 bit。IPv6中的新增字段，用于区分实时流量，不同的流标签+源地址可以唯一确定一条数据流，中间网络设备可以根据这些信息更加高效率的区分数据流。
	- Payload Length：有效载荷长度，长度为16 bit。有效载荷是指紧跟IPv6包头的数据包的其他部分（即扩展包头和上层协议数据单元）。
	- Next Header：下一个包头，长度为8 bit。该字段定义紧跟在IPv6包头后面的第一个扩展包头（如果存在）的类型，或者上层协议数据单元中的协议类型（类似于IPv4的Protocol字段）。
	- Hop Limit：跳数限制，长度为8 bit。该字段类似于IPv4中的Time to Live字段，它定义了IP数据包所能经过的最大跳数。每经过一个路由器，该数值减去1，当该字段的值为0时，数据包将被丢弃。
	- Source Address：源地址，长度为128 bit。表示发送方的地址。
	- Destination Address：目的地址，长度为128 bit。表示接收方的地址。


![](Pasted%20image%2020261108134814.png)






- IPv4包头包含可选字段Options，内容涉及Security、Timestamp、Record route等，这些Options可以将IPv4包头长度从20 Byte扩充到60 Byte。携带这些Options的IPv4报文在转发过程中往往需要中间路由转发设备进行软件处理，对于性能是个很大的消耗，因此实际中也很少使用。

- IPv6将这些Options从IPv6基本包头中剥离，放到了扩展包头中，扩展包头被置于IPv6基本包头和上层协议数据单元之间。一个IPv6报文可以包含0个、1个或多个扩展包头，仅当需要路由器或目的节点做某些特殊处理时，才由发送方添加一个或多个扩展头。与IPv4不同，IPv6扩展头长度任意，不受40 Byte限制，这样便于日后扩充新增选项。这一特征加上选项的处理方式使得IPv6选项能得以真正的利用。但是为了提高处理选项头和传输层协议的性能，扩展包头总是8 Byte长度的整数倍。

- 当使用多个扩展包头时，前面包头的Next Header字段指明下一个扩展包头的类型，这样就形成了链状的包头列表。

- 当超过一种扩展包头被用在同一个IPv6报文里时，包头必须按照下列顺序出现：

	1. 逐跳选项包头：主要用于为在传送路径上的每跳转发指定发送参数，传送路径上的每台中间节点都要读取并处理该字段。
	2. 目的选项包头：携带了一些只有目的节点才会处理的信息。
	3. 路由包头：IPv6源节点用来强制数据包经过特定的设备。
	4. 分段包头：当报文长度超过MTU（Maximum Transmission Unit，最大传输单元）时就需要将报文分段发送，而在IPv6中，分段发送使用的是分段包头。
	5. 认证包头（AH）：该包头由IPsec使用，提供认证、数据完整性以及重放保护。
	6. 封装安全净载包头（ESP）：该包头由IPsec使用，提供认证、数据完整性以及重放保护和IPv6数据包的保密。
