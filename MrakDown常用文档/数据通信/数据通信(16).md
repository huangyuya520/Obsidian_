![](Pasted%20image%2020261123164820.png)


- 广域网与局域网的区别主要体现在以下几个方面：
	- 局域网带宽高但是传输距离短，无法满足广域网长距离传输；
	- 局域网设备通常都是交换机，广域网设备大多都是路由器；
	- 局域网属于某一个单位或者组织，广域网服务大多由ISP提供；
	- 广域网与局域网一般仅在物理层和数据链路层采用不同的协议或技术，其他层次基本没有差异；
	- 银行、政府、军队、大型公司的专用网络也属于广域网，且与Internet实现物理隔离；
	- Internet只是广域网的一种，小企业借用Internet作为广域网连接。



![](Pasted%20image%2020261123165000.png)


- 初期广域网常用的物理层标准有EIA（Electronic Industries Alliance，电子工业协会）和TIA（Telecommunications Industry Association，电信工业协会）制定的公共物理层接口标准EIA/TIA-232（即RS-232）、 ITU（International Telecommunication Union，国际电信联盟）制定的串行线路接口标准V.24和V.35，以及有关各种数字接口的物理和电气特性的G.703标准等。

- 广域网常见的数据链路层标准有：HDLC（High-level Data Link Control，高级数据链路控制）、PPP（Point-to-Point Protocol，点到点协议）、FR（Frame Relay，帧中继）、ATM异步传输模式等，其中：

	- HDLC协议是一种通用的协议，工作在数据链路层。数据报文加上头开销和尾开销后封装成HDLC帧，只支持在点到点的同步链路上的数据传输，不支持IP地址协商与认证，过于追求高可靠性，导致数据帧开销较大，传输效率较低。
	- PPP协议工作在数据链路层，主要用在支持全双工的同、异步链路上，进行点到点之间的数据传输。由于它能够提供用户认证，易于扩充，并且支持同、异步通信，因而获得广泛应用。
	- 帧中继是一种工业标准的、交换式的数据链路协议，通过使用无差错校验机制，加快了数据转发速度。
	- ATM是建立在电路交换和分组交换基础上的一种面向连接的交换技术，ATM传送信息的基本载体是53 Byte固定长度ATM信元。

# PPP协议

## 概述
PPP（Point-to-Point Protocol，点对点协议）==是计算机网络中工作在数据链路层的一种协议==

它在两个对等节点之间的点对点链路上封装和传输网络层数据包（如 IP），取代了早期的 SLIP 协议

==核心组成==

- **链路控制协议（LCP）**：负责==建立、配置==、测试和维护数据链路连接，协商 MRU（最大接收单元，默认 1500 字节）等参数。

- **网络控制协议（NCP）**：负责配置不同的==网络层协议==（如针对 IPv4 的 IPCP），分配网络层参数。

- **认证协议**：支持 **PAP**（两次握手，明文传输密码）和 **CHAP**（三次握手，质询-响应哈希认证，安全性更高）


==主要特点与常见应用==

- **特点**：支持多种网络层协议、支持身份认证、提供差错检测、兼容同步与异步串行链路，并可通过 **MPPP**（Multilink PPP）捆绑多条链路提升带宽。
- **常见应用**：宽带拨号接入（如 **PPPoE**、**PPPoA**）、企业路由器间串口/广域网连接、VPN 及部分移动/物联网通信场景。

## PPP 工作原理及流程
PPP 链路的整个生命周期严格按照状态机推进，必须逐层协商通过后才能转发 IP 数据。

==工作流程==

- **链路不可用（Dead）**：物理层尚未准备好，或处于断开状态。
- **链路建立（Establish）**：通过 **LCP** 协商链路参数，建立链路。
- **认证（Authenticate）**：根据协商结果使用 **PAP** 或 **CHAP** 验证对端身份。
- **网络层协商（Network）**：通过 **NCP** 配置网络层协议（如分配 IP 地址）。
- **链路终止（Terminate）**：数据传输完成后由 **LCP** 拆除链路





1. **链路静止（Dead）**：物理层尚未就绪（线路未接通或接口处于 Shutdown）。一旦物理层检测到载波信号（Physical UP），立即转入链路建立阶段。
    
2. **链路建立（Establish）**：双方交互 **LCP** 报文进行链路层参数协商。发送方发出 `Configure-Request`，对端根据支持情况回复：
    
    - `Configure-Ack`：所有参数均认可。
        
    - `Configure-Nak`：参数类型可识别，但数值不认可（携带建议值，如调整 MRU）。
        
    - `Configure-Reject`：无法识别某些配置项，要求对方删除后重发。
        
    - 当双方互相收到 `Configure-Ack` 后，LCP 进入 **Opened** 状态。

3. **认证阶段（Authenticate，可选）**：若 LCP 阶段协商启用了认证，则进入此阶段执行 PAP 或 CHAP。认证通过进入下一阶段；认证失败则直接跳至**链路终止**阶段。若未配置认证，则跳过此阶段。
	
4. **网络层协商（Network）**：双方交互 **NCP（如 IPCP）** 报文协商网络层参数。IPCP 同样采用 Request/Ack/Nak 机制，支持两种 IP 地址协商方式：
    
    - **静态地址协商**：双方接口均已手动配置 IP，通过 IPCP 确认对方地址合法后，自动在本地路由表中生成指向对端接口 IP 的 **32 位主机路由**（因此 PPP 链路两端 IP 即使不在同一网段也能互通）。
        
    - **动态地址分配**：客户端发送 IP 为 `0.0.0.0` 的 Request，服务端回复 `Configure-Nak` 并附带地址池中的可用 IP，客户端再用该 IP 重新请求直至 `Configure-Ack`。

5. **数据传输（Open）**：NCP 进入 Opened 状态后，双方开始正常收发 `0x0021` 封装的 IP 业务报文；同时 LCP 会周期性发送 `Echo-Request` / `Echo-Reply` 维护链路存活。
    
6. **链路终止（Terminate）**：当管理员关闭接口、认证失败、物理载波丢失或 Keepalive 超时时，发送 `Terminate-Request` 并等待 `Terminate-Ack`，释放资源后退回 **Dead** 状态。



![](20261123_173758.jpg)


- 正常PPP链路建立需要经历链路建立阶段、认证阶段和网络层协商阶段，详细过程如下：

	1. 通信双方开始建立PPP链路时，先进入到Establish阶段。
	2. 在Establish阶段，进行LCP协商：协商通信双方的MRU（Maximum Receive Unit，最大接收单元）、认证方式和魔术字（Magic Number）等选项。协商成功后进入Opened状态，表示底层链路已建立。
	3. 如果配置了认证，将进入Authenticate阶段。否则直接进入Network阶段。
	4. 在Authenticate阶段，会根据连接建立阶段协商的认证方式进行链路认证。认证方式有两种：PAP和CHAP。如果认证成功，进入Network阶段，否则进入Terminate阶段，拆除链路，LCP状态转为Down。
	5. 在Network阶段，PPP链路进行NCP协商。通过NCP协商来选择和配置一个网络层协议并进行网络层参数协商。最常见的NCP协议是IPCP，用来协商IP参数。
	6. 在Terminate阶段，如果所有的资源都被释放，通信双方将回到Dead阶段。

- PPP运行过程中，可以随时中断连接，物理链路断开、认证失败、超时定时器时间到、管理员通过配置关闭连接等动作都可能导致链路进入Terminate阶段。

# PPPoE

## 概述
**PPPoE**（Point-to-Point Protocol over Ethernet，以太网上的点对点协议）是==一种将点对点协议（PPP）封装在以太网帧中进行传输的网络协议，主要用于**宽带拨号上网**==


==核心作用与特点==

- **解决接入难题**：传统 PPP 适用于点对点链路，而以太网属于广播网络，缺乏原生的用户认证和计费能力。PPPoE 结合两者优势，在以太网上建立点对点连接。 [[1](https://blog.csdn.net/ailbj/article/details/142845700), [2](https://www.hillstonenet.com/support/T-series/2.0/cn/config_net_pppoe_intro.html), [3](https://info.support.huawei.com/info-finder/encyclopedia/zh/PPPoE.html)]

- **身份认证与计费**：支持 PAP、CHAP 等认证方式，方便运营商验证账号密码、控制接入权限并进行上网计费。 [[1](https://www.bilibili.com/video/BV1Xz4y1r7rg/), [2](https://info.support.huawei.com/info-finder/encyclopedia/zh/PPPoE.html), [3](https://www.hillstonenet.com/support/T-series/2.0/cn/config_net_pppoe_intro.html)]

- **动态分配参数**：建立连接后可自动分配 IP 地址、DNS 服务器和网关等网络配置。 [[1](https://developer.aliyun.com/article/1245046)]

- **封装开销**：由于增加了 PPPoE 头部，标准以太网 1500 字节的 MTU 通常会降为 **1492 字节**，部分网络环境需注意 MTU 适配



==工作流程==

PPPoE 的工作主要分为两个阶段： [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/PPPoE.html)]

- **发现阶段（Discovery）**：客户端与服务端通过广播和单播交互 **PADI、PADO、PADR、PADS** 报文，找到对方并分配唯一的会话 ID（Session ID）。 [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/PPPoE.html)]

- **PPP 会话阶段（Session）**：基于建立的会话进行 **LCP** 链路协商、**PAP/CHAP** 身份认证，以及 **NCP**（如 IPCP）网络层参数协商，完成后即可传输数据。



==常见应用场景==

- 家庭与企业宽带拨号上网（通常由光猫桥接后，由路由器或电脑发起 PPPoE 拨号）。

- 园区网或酒店等需要账号认证的有线接入场景。



![](Pasted%20image%2020261124105034.png)

- 运营商希望把一个站点上的多台主机连接到同一台远程接入设备，同时接入设备能够提供与拨号上网类似的访问控制和计费功能。在众多的接入技术中，把多个主机连接到接入设备的比较经济的方法就是以太网，而PPP协议可以提供良好的访问控制和计费功能，于是产生了在以太网上传输PPP报文的技术，即PPPoE。

- PPPoE利用以太网将大量主机组成网络，通过一个远端接入设备接入因特网，并运用PPP协议对接入的每个主机进行控制，具有适用范围广、安全性高、计费方便的特点。

## PPPoE工作原理


![](Pasted%20image%2020261124110344.png)


PPPoE 的完整生命周期分为**发现阶段（Discovery）**、**会话阶段（Session）** 和**会话终止阶段（Termination）**。下图展示了客户端与服务端从四步发现握手到进入 PPP 会话（含 LCP、RADIUS 联动认证、IPCP 及数据传输）的完整交互时序，可以重点观察两个阶段在职责上的衔接









### 发现阶段
1. 发现阶段（PPPoE Discovery，`EtherType = 0x8863`）

由于以太网是多路访问广播域，Client 初始时并不知道 Server 的 MAC 地址，也不存在专属通道。发现阶段通过四次交互（PADx 报文）在以太网中选定 Server 并建立唯一的逻辑会话标识：

|**交互步骤**|**报文名称**|**Code 值**|**发送方式**|**Session_ID**|**核心作用**|
|---|---|---|---|---|---|
|**第 1 步**|**PADI**（Initiation）|`0x09`|Client **广播**|`0x0000`|寻找同二层广播域内所有可用的 PPPoE Server，可携带期望的服务名（Service-Name）|
|**第 2 步**|**PADO**（Offer）|`0x07`|Server **单播**|`0x0000`|能够提供服务的 Server 响应客户端，携带自身名称（AC-Name）及支持的服务信息|
|**第 3 步**|**PADR**（Request）|`0x19`|Client **单播**|`0x0000`|Client 通常选定**最先收到 PADO** 的 Server，发送正式会话请求|
|**第 4 步**|**PADS**（Session-confirmation）|`0x65`|Server **单播**|**非零唯一值**|Server 分配唯一的 `Session_ID` 并确认，客户端收到后正式进入会话阶段|
此时，由 **`(Client MAC, Server MAC, Session_ID)`** 构成的三元组在逻辑上锁定了一条点对点隧道，同一以太网上的不同拨号用户互不干扰。



![](Pasted%20image%2020261124114252.png)



1. PPPoE客户端在本地以太网中广播一个PADI报文，此PADI报文中包含了客户端需要的服务信息。
	- PADI报文的目的MAC地址是一个广播地址，Code字段为0x09，Session ID字段为0x0000。
	- 所有PPPoE服务器端收到PADI报文之后，会将报文中所请求的服务与自己能够提供的服务进行比较。

2. 如果服务器端可以提供客户端请求的服务，就会回复一个PADO报文。
	- PADO报文的目的地址是发送PADI报文的客户端MAC地址，Code字段为0x07，Session ID字段为0x0000。

3. 客户端可能会收到多个PADO报文，此时将选择最先收到的PADO报文对应的PPPoE服务器端，并发送一个PADR报文给这个服务器端。
	- PADR报文的目的地址是选中的服务器端的MAC地址，Code字段为0x19，Session ID字段为0x0000。

4. PPPoE服务器端收到PADR报文后，会生成一个唯一的Session ID来标识和PPPoE客户端的会话，并发送PADS报文。
	- PADS报文的目的地址是PPPoE客户端的MAC地址，Code字段为0x65，Session ID字段是PPPoE服务器端为本PPPoE会话产生的Session ID。

- 会话建立成功后，PPPoE客户端和服务器端进入PPPoE会话阶段。







### 会话阶段
进入会话阶段后，PPPoE 头部的 `Code` 字段固定为 `0x00`，所有通信均采用单播方式并携带已分配的 `Session_ID`。此阶段完全复用了标准 PPP 协议机制：

1. **LCP 协商**：协商链路参数，最关键的是将 **MRU 协商至不超过 1492 字节**，同时确定认证方式（生产环境首选 CHAP）和魔术字。
    
2. **身份认证**：Client 与 Server 完成 PAP 或 CHAP 认证。如上图所示，在运营商现网中，PPPoE Server 往往不直接存储海量用户密码，而是充当 NAS（网络接入服务器），将凭据封装为 `RADIUS Access-Request` 发送至后台 AAA 服务器校验，收到 `RADIUS Access-Accept` 后向客户端返回认证成功并下发带宽限速策略。
    
3. **IPCP / IPv6CP 协商**：Server 从地址池中动态为 Client 分配 IPv4 地址、网关与 DNS（双栈网络下同时通过 IPv6CP 与 DHCPv6-PD 分配地址前缀）。
    
4. **数据传输与保活**：开始封装 `0x0021`（IPv4）或 `0x0057`（IPv6）业务报文进行转发，同时双方周期性交互 LCP `Echo-Request` / `Echo-Reply` 检测链路存活。





- PPPoE会话阶段可分为两部分：PPP协商阶段和PPP报文传输阶段。
- PPPoE Session上的PPP协商和普通的PPP协商方式一致，分为LCP、认证、NCP三个阶段。
	- LCP阶段主要完成建立、配置和检测数据链路连接。
	- LCP协商成功后，开始进行认证，认证协议类型由LCP协商结果决定。
	- 认证成功后，PPP进入NCP阶段，NCP是一个协议族，用于配置不同的网络层协议，常用的是IP控制协议（IPCP），它负责配置用户的IP地址和DNS服务器地址等。

- PPPoE Session的PPP协商成功后，就可以承载PPP数据报文。在这一阶段传输的数据包中必须包含在发现阶段确定的Session ID并保持不变。


![](Pasted%20image%2020261124114453.png)







### 会话终止阶段
在会话建立后的任意时刻，无论是用户主动断开、管理员踢线还是账号欠费下线，Client 或 Server 任意一方均可直接单播发送 PADT（PPPoE Active Discovery Terminate，`Code = 0xA7`）报文，携带当前的 `Session_ID`。对端收到 PADT 后立即释放该会话资源，终止 PPP 通信；此外，链路也可以通过发送 LCP `Terminate-Request` 优雅拆除



- 在PADT报文中，目的MAC地址为单播地址，Session ID为希望关闭的连接的Session ID。一旦收到一个PADT报文之后，连接随即关闭。

## MPLS
**MPLS（Multi-Protocol Label Switching，多协议标签交换）**。MPLS 位于 OSI 模型的二层（数据链路层）与三层（网络层）之间，常被称为“**2.5 层协议**”


MPLS 标签转发的核心设计思想是“边缘路由、核心交换”：数据包仅在进入和离开 MPLS 骨干网的边缘设备上解析 IP 报文头，而在骨干网内部，路由器不再逐跳执行复杂的 IP 路由表最长前缀匹配，而是直接依据固定长度的短标签（Label）进行高速查表转发

## Segment Routing（分段路由）
SR（Segment Routing，分段路由）**是一种基于**源路由（Source Routing）**理念的新一代广域网转发架构。它的核心思想是将网络路径切分成若干有序的“段（Segment）”，在报文进入网络的**头节点（源节点）直接封装好一份完整的“指令列表（Segment List）”；沿途的中间节点无需预先维护复杂的隧道状态，只需像快递分拣一样按指令逐段执行转发即可。
