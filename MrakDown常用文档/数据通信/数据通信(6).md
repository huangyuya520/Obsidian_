
# IP路由选择

**路由（Routing）** 是指==在计算机网络中，将数据包从源地址经过互联的网络设备传输到目标地址的最佳路径选择过程==


==一、路由的核心功能==

- **路径选择**：依据内部维护的[路由表](https://www.cloudflare.com/zh-cn/learning/network-layer/what-is-routing/)，按照特定规则和算法决定数据包的下一步去向。

- **数据转发**：接收来自源节点或上一个节点的数据包，并将其高速转发到下一个节点或最终目的地。

- **网关连接**：连接不同的局域网（LAN）与广域网（WAN），充当不同网络之间的互联网关。

- **地址分配与管理**：在家庭或企业网络中，通过 DHCP 为接入的设备分配IP地址，并常伴随防火墙及NAT（网络地址转换）功能






- 网关以及中间节点（路由器）根据收到的IP报文其目的地址选择一条合适的路径，并将报文转发到下一个路由器。在路径中的最后一跳路由器二层寻址将报文转发给目的主机。这个过程被称为路由转发。

- 中间节点选择路径所依赖的表项为称为路由表。

- 路由条目包含明确的出接口以及下一跳，这两项信息指导IP报文转发到相应的下一跳设备上。

## 路由表
**路由表（Routing Table，又称路由择域信息库 RIB）**==是路由器或联网计算机中存储的一张电子表格或数据库，用于记录网络路径信息并指导数据包的转发方向==。它的作用类似于交通导航地图，决定了IP数据包从源地址到目的地址的最优传输路径。



==一、 路由表的核心构成要素==

==一张标准的路由表主要包含以下关键信息：==

- **目的网络地址（Destination / Network）**：数据包想要去往的目标网段或主机IP。

- **子网掩码（Netmask）**：与目的地址结合，用于判断IP地址中哪些位是网络位、哪些位是主机位。

- **下一跳（Next Hop）**：数据包在去往目标网络时，下一个应该发送到的路由器接口IP地址或设备。

- **出接口（Interface）**：数据包从当前路由器的哪一个物理或逻辑接口发送出去。

- **度量值 / 优先级（Metric / Administrative Distance）**：用来衡量某条路径的“好坏”或成本（如跳数、带宽、延迟等），==数值越小通常优先级越高==



==二、 路由的来源分类==

路由表中的条目通常通过以下几种方式生成： [[1](https://info.support.huawei.com/info-finder/encyclopedia/zh/IP%E8%B7%AF%E7%94%B1.html)]

- **直连路由（Directly Connected）**：路由器直接相连的网段，由系统自动生成。

- **静态路由（Static）**：由网络管理员手动配置，适用于结构简单、变化较少的网络。

- **动态路由（Dynamic）**：通过动态路由协议（如 OSPF、BGP、RIP、IS-IS 等）由路由器之间自动交互、计算并生成


==三、 核心工作与选路原则==

当路由器收到一个IP数据包时，会根据以下规则进行匹配和转发：

- **最长匹配原则（Longest Match Rule）**：当路由表中有多个条目都能匹配目标IP时，路由器会选择**子网掩码最长（即前缀最长、最精确）** 的那条路由进行转发。 [[1](https://support.huaweicloud.com/usermanual-vpc/vpc_route01_0001.html), [2](https://info.support.huawei.com/info-finder/encyclopedia/zh/IP%E8%B7%AF%E7%94%B1.html)]

- **缺省路由（Default Route / 0.0.0.0/0）**：如果所有精确路由都没有匹配上，最后会匹配缺省路由（默认网关），将数据包发往上一级路由器或公网；若连缺省路由也没有，则丢弃数据包并返回ICMP差错报文

- 路由表由路由条目组成，但不代表路由表中保存了所有路由，路由表中只会保存“最优的”路由。

### 直连路由
直连路由（Directly Connected Route）是指==路由器接口所直接连接的网段路由，由链路层协议自动发现并生成==



==核心特点==

- **自动生成**：只要路由器接口处于**启用（Up）** 状态并配置了合法的 IP 地址，系统就会自动将该网段添加到路由表中。

- **免维护**：不需要网络管理员手动配置，也不需要运行动态路由协议进行计算。

- **高优先级**：在常见网络设备（如华为、华三、思科等）中，直连路由的默认管理距离或优先级通常最高（通常为 0），这意味着同等条件下优先匹配直连路由。

- **即插即用**：连接在同一物理网段或链路上的设备可以直接通信，无需额外的路由配置










- 当匹配中直连路由进行转发时，此时路由器会查看ARP表项，将报文直接转到目的地址，此时该路由器为路由转发的最后一跳路由器。

- 直连路由的下一跳地址并不是其他设备上的接口地址，因为该路由的目的网段为接口所在网段，本接口就是最后一跳，不需要再转发给下一跳，所以在路由表中的下一跳地址就是接口自身地址。

- 使用直连路由进行路由转发时，转发的动作不是交给下一跳，而是查询ARP表项，根据ARP表项封装报文，将报文发送到目的IP。

## 选取路由的规则

### 最长掩码匹配原则
**最长掩码匹配原则**（也称为**最长前缀匹配原则**，英文：Longest Prefix Match, LPM）==是路由器在查找路由表时最核心的选路规则==


1. ==核心思想==

当一个IP数据包到达路由器时，路由器会拿该数据包的**目的IP地址**与本地路由表中的各个**网段条目**进行比对。如果同时有多个路由条目都能匹配上这个目的地址，路由器会**选择子网掩码最长（即网络前缀最长、匹配的二进制位数最多）的那条路由**进行数据转发。 [[1](https://www.cnblogs.com/mefj/p/14543955.html), [2](https://blog.csdn.net/djefe/article/details/118296907), [3](https://baike.baidu.com/item/%E6%9C%80%E9%95%BF%E6%8E%A9%E7%A0%81%E5%8C%B9%E9%85%8D/7291440), [4](https://www.thinkmo.com.cn/it/hot_article/Tutorials/699.html)]

简单来说：**“匹配得越精细、越具体，就选哪一条”**。

## 静态路由概念
静态路由（Static Routing）是指==由网络管理员手动配置和维护的路由信息，而不是由路由器通过动态路由协议（如 OSPF、BGP 等）自动交换和计算出来的==

==一、 核心特点==

- **手工配置：** 路由表项必须由管理员逐条输入和设定。

- **固定不变：** 路径是静态的，不会随网络拓扑结构的改变而自动调整；若链路中断，静态路由不会自动切换，除非管理员进行人工干预或配置浮动静态路由（备用路径）。

- **资源占用少：** 不需要占用路由器的 CPU 资源去计算路由，也不消耗网络带宽来传输路由更新信息。

- **安全性高：** 因为是人为指定，黑客较难通过伪造动态路由信息来窃取流量




==二、 优缺点对比==

|优点|缺点|
|---|---|
|**节省资源**：不占用 CPU 计算能力，带宽开销小。|**扩展性差**：网络规模一大，配置和维护的工作量极重。|
|**安全可控**：路径完全由管理员掌控，流向清晰。|**无法自愈**：网络拓扑发生故障时，不能自动感知和切换路线。|
|**原理简单**：适合小型、结构简单的网络环境。|**易出错**：手工输入 IP 地址或下一跳时容易产生人为失误。|


==三、 适用场景==

- **小型网络：** 只有几台或十几台设备连接的简单网络，配置静态路由最快最稳。

- **边缘网络 / 末端网络：** 只有一个出口连接到外部网络（如企业连接到运营商的默认路由），通常配置一条**默认路由**即可。

- **特定安全需求的场景：** 需要严格限制数据包流经特定路径，不希望通过动态协议扩散路由

## 动态路由概念
**动态路由**（Dynamic Routing）是==路由器通过运行动态路由协议，在网络中自动交换路由信息、动态建立并实时调整路由表的技术==


==一、 核心特点==

- **自动适应变化**：当网络拓扑发生改变（如链路中断、新节点加入）时，路由器能自动感知并选择新的最优路径（也称自适应路由）。

- **减轻管理负担**：无需网络管理员手动逐一配置和维护庞大的路由表，特别适合中大型复杂网络。

- **资源消耗较高**：会占用一定的**网络带宽**、CPU和内存资源用于协议报文的交互与计算



==二、 与静态路由的区别==

|维度|静态路由 (Static Routing)|动态路由 (Dynamic Routing)|
|---|---|---|
|**配置方式**|管理员手动配置|路由器通过协议自动生成|
|**拓扑适应力**|差（链路故障需人工修改）|强（自动切换备用路径）|
|**适用场景**|小型、结构简单的网络|中大型、多节点、结构复杂的网络|
|**资源占用**|极低（几乎不占用带宽和算力）|较高（需周期性交换报文）|



==三、常见动态路由协议==

动态路由协议按应用范围和算法可分为：

- **内部网关协议（IGP，用于自治系统内部）**：
    - **RIP**（Routing Information Protocol）：基于==距离向量算法==，以“跳数”为度量标准，最大跳数为15（16表示不可达）。
    - **OSPF**（Open Shortest Path First）：基于==链路状态算法==，使用Dijkstra最短路径优先算法，收敛快、无环路，企业网最常用。
    - **EIGRP**：思科专有/开放的高级距离向量协议。 [[1](https://www.cnblogs.com/yunjisuanchengzhanglu/p/16634826.html)]

- **外部网关协议（EGP，用于自治系统之间）**：
    - **BGP**（Border Gateway Protocol）：边界网关协议，是互联网实现各大运营商/数据中心之间互联的核心协议。




![](Pasted%20image%2020261103155458.png)



- 静态路由的缺点是不能自动适应网络拓扑的变化，需要人工干预。

- 动态路由协议有自己的路由算法，能够自动适应网络拓扑的变化，适用于具有一定数量三层设备的网络。




![](Pasted%20image%2020261103155620.png)


- 根据路由信息传递的内容、计算路由的算法，可以将动态路由协议分为两大类
	- 距离矢量协议（Distance-Vector Protocol）
		- RIP
	- 链路状态协议（Link-State Protocol）
		- OSPF
		- IS-IS
	- BGP使用一种基于距离矢量算法修改后的算法，该算法被称为路径适量（Path Vector）算法。因此在某些场合下，BGP也被称为路径矢量路由协议。
	- 
- 根据工作范围不同，又可以分为
	- 内部网关协议IGP（Interior Gateway Protocol）:在一个自治系统内部运行。RIP、OSPF、ISIS为常见的IGP协议。
	- 外部网关协议EGP（Exterior Gateway Protocol）：运行于不同自治系统之间。BGP是目前最常用的EGP协议。





## 静态路由的高级特性


### 路由负载(等价路由)
**路由负载均衡**（也常称为**路由负载分担**）是指==当网络中去往同一个目的地存在多条转发路径时，将网络流量合理地分配、分摊到多条路径上进行传输的技术==

1. ==核心作用==

- **提升网络吞吐量**：把原本单条链路承受的流量分散到多条链路上，叠加总带宽。

- **增强可靠性（冗余备份）**：当其中一条路径发生故障时，流量可以快速切换到其他可用路径上，减少业务中断。

- **优化资源利用**：避免某一条链路长期处于超负荷状态，而其他链路闲置





2. ==常见实现方式==

- **等价多路径路由（ECMP, Equal-Cost Multi-Path）**：  
    当去往同一个目的地存在多条**开销（Cost）完全相同**的路由时，路由器会将流量均匀地分摊到这些路径上。常见的动态路由协议如 OSPF、IS-IS、BGP 等都支持 ECMP



- ==**基于流（Per-Flow）或基于包（Per-Packet）的分担**：==

	- **按流分担**：根据源IP、目标IP、端口号等进行哈希（Hash），保证同一条会话（如一个TCP连接）的报文走同一条路，防止报文乱序。
	- **按包分担**：逐个报文轮流从不同路径发送，可能导致严重的报文到达顺序混乱。


- **策略路由 / 链路聚合 / 多拨**：  
在企业网或家用多宽带场景中（如 OpenWrt 多拨），通过配置自定义策略将不同来源或不同应用类型的流量导向特定链路。

### 主备路由(浮动路由)
**主备路由**（Active-Standby Routing）是==一种网络高可用性（High Availability, HA）设计方案==

它通过配置两条或多条到达同一目的地的路径，并分出主用线路（Active）和备用线路（Standby），确保当主用线路发生故障时，流量能自动切换到备用线路上，保障业务不中断




==一、 核心工作原理==

主备路由的本质是通过控制**路由优先级**或**状态协议**，让路由器在正常情况下只走优先级高的“主路径”；当主路径失效时，才启用“备路径”。 [[1](https://help.aliyun.com/zh/cen/use-cases/configure-active-and-standby-static-routes-for-vbrs-in-the-same-region-by-using-route-maps), [2](https://blog.csdn.net/rwbrwy/article/details/125617189)]

- **静态路由优先级法**
    - 手动配置两条到达目标网段的静态路由。
    - 通过调整优先级（Preference / Administrative Distance）或度量值（Metric）：把主用路由的优先级设高（数值更小），备用路由的优先级设低（数值更大）。
    - 路由器默认优先选择优先级高的链路转发流量。 [[1](https://support.huawei.com/enterprise/zh/doc/EDOC1000069491/743f6e24), [2](https://help.aliyun.com/zh/cen/use-cases/configure-active-and-standby-static-routes-for-vbrs-in-the-same-region-by-using-route-maps)]

- **动态路由与冗余协议法（如 VRRP、BGP、NQA/BFD联动）**
    - **VRRP（虚拟路由器冗余协议）**：将多台物理路由器虚拟成一台“虚拟路由器”，分为 `Master`（主）和 `Backup`（备）角色。Master 负责实际转发数据，Backup 时刻监听 Master 的状态；一旦 Master 故障，Backup 迅速接管。
    - **链路状态检测联动（NQA / BFM / EFM OAM）**：纯静态路由有时无法感知物理接口未拔出但底层链路中断的情况，因此通常会绑定 **NQA** 或 **BFD** 等链路检测机制，实现毫秒/秒级自动切换。
    - **BGP/OSPF 协议调优**：通过调整 BGP Local Preference（本地优先级）或 AS-Path 等参数实现主备或主从分流。



==二、 常见应用场景==

- **企业多出口网络**：公司同时接入了电信和联通两条宽带，以电信为主、联通为备，防止某家运营商断网导致办公瘫痪。

- **专线与云上组网（IDC 上云）**：本地数据中心（IDC）通过物理专线连接云厂商（如阿里云、腾讯云、华为云），主用一条高带宽专线，备用一条 VPN 或低速专线，实现灾备。

- **网关设备冗余**：核心交换机或出口网关采用双机热备部署，防止单台硬件设备损坏




==三、 主备路由的优缺点==

- **优点**：
    - **高可靠性**：大幅降低因单点故障或单条线路中断导致的业务停机风险。
    - **逻辑清晰**：配置与排查相对简单，特别是静态主备路由。 [[1](https://www.scribd.com/presentation/602127593/AF-v8-0-51-%E9%AB%98%E5%8F%AF%E7%94%A8%E6%80%A7-%E4%B8%BB%E5%A4%87%E9%83%A8%E7%BD%B2), [2](https://cloud.tencent.com/developer/news/1344754)]

- **缺点**：
    - **资源浪费**：备用链路在正常情况下处于闲置或低利用率状态，带宽没有得到完全发挥

### 默认路由(万能路由，缺省路由)
**默认路由**（Default Route，也称**缺省路由**或**默认网关**）是==一种特殊的**静态路由**==。

当路由器收到一个 IP 数据包，并查询了完整的路由表，发现目的地址**没有匹配到任何具体的路由条目**时，路由器就会把这个包统一交给默认路由来处理


1. ==核心特点==

- ==**兜底角色**：它相当于网络的“备用通道”或“最后防线”。如果没有默认路由，找不到目标网段的数据包会被直接丢弃。==

- **IPv4 表示方式**：在 IPv4 中，默认路由的目标网络通常写作 `0.0.0.0`，子网掩码为 `0.0.0.0`（即 `0.0.0.0/0`），意为“任意未知网络”。

- **本质是静态路由**：它本质上属于静态路由的一种特殊形式，通过指定一个下一跳地址或出口接口来转发所有未知流量。



2. ==常见应用场景==

- **末梢网络（Stub Network）**：比如小型办公室、家庭网络，内网设备访问外部互联网时，所有通往外网的流量都发往运营商的路由器，这时家庭路由器通常会配置一条指向宽带光猫或上级网关的默认路由。 [[1](https://www.cnblogs.com/xig112635/p/15122389.html), [2](https://kaoshi.educity.cn/rk/c8u5gvpc3w.html)]

- **简化路由表**：如果路由器需要连接大量外部网络（例如整个互联网有几十万条路由），不可能把所有明细路由都写进小型的本地路由器里，一条默认路由就能解决大部分往外网的转发需求。

- 对于一个大规模的网络来说，路由器或其他具备路由功能的设备势必需要维护大量的路由表项，为了维护臃肿的路由表，这些设备就不得不耗费大量的资源。同时，由于路由表的规模变大，会导致路由器在查表转发时效率降低。因此在保证网络中的路由器到各网段都具备IP可达性的同时，需要减小设备的路由表规模。一个网络如果具备科学的IP编址，并且进行合理的规划，是可以利用多种手段减小设备路由表规模的。一个非常常见而又有效的办法就是使用路由汇总（Route Summarization）。路由汇总又被称为路由聚合（Route Aggregation），是将一组有规律的路由汇聚成一条路由，从而达到减小路由表规模以及优化设备资源利用率的目的，我们把汇聚之前的这组路由称为精细路由或明细路由，把汇聚之后的这条路由称为汇总路由或聚合路由。


- RTA上为了能够前往远端地址，需要为每一个远端网段配置一条明细路由。去往10.1.1.0/24、10.1.2.0/24、10.1.3.0/24…拥有相同下一跳。将拥有相同下一跳，一组有规律的路由汇总成一条路由，这叫做路由汇总。

- 路由汇总可以有效减少路由表项大小。





### 路由递归
**路由递归**（也称**路由迭代**）是指==路由器在查找路由表时，为了找到一个数据包的**直连下一跳**地址和对应的**出接口**，需要对非直连的下一跳进行**反复查表计算**的过程==

1. ==为什么需要路由递归？==

路由器在转发数据包时，必须知道将数据包从哪一个物理接口发出去，以及这个接口直接相连的下一跳 IP 地址是什么。 [[1](https://blog.csdn.net/m0_62017216/article/details/130532369)]

- **直连路由**：下一跳与路由器本身在同一个网段，一步就能查到出接口和下一跳，不需要递归。

- **非直连路由（如静态路由）**：管理员配置了一条静态路由，只指定了远端的目的网段和非直连的下一跳（例如：去往 `10.0.0.0/24` 的下一跳是 `20.0.0.1`）。但 `20.0.0.1` 跟路由器并不是直接相连的。

- 这时，路由器必须再次去查路由表：“`20.0.0.1` 这台设备我怎么走才能到达？”，直到查出一条**直连**的下一跳和出接口为止。这个“查户口”式的套娃查找过程，就是路由递归

3. 主要作用与特点

- **简化配置**：在复杂的网络拓扑（如 BGP、VPN 或大型静态路由环境）中，使用递归路由可以大大减少管理员的配置工作量。

- **适应拓扑变化**：当底层直连链路发生变化时，只要底层的直连路由更新，上层的递归路由会自动重新迭代，寻找到达目的的新路径。

- **主要应用场景**：常见于**静态路由**配置以及 BGP 等协议中。
