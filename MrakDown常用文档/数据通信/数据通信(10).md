
# WLAN


## WLAN工作原理(胖AP架构)

![](Pasted%20image%2020261110111243.png)

- AC+FIT AP组网架构中，是通过AC对AP进行统一的管理，因此所有的配置都是在AC上进行的。




### AP上线
在 FIT AP + AC 集中式架构的数通体系中，AP 上线（AP Onboarding）是指 FIT AP 从通电上电开始，通过有线网络自动寻找无线控制器（AC）、建立通信隧道、完成鉴权与版本同步，并最终获取业务配置开始向外发射射频信号的完整控制平面协商流程

#### 阶段一：AP 获取 IP 地址

FIT AP 启动后，首先必须在有线侧获取可用的管理 IP 地址，以便与 AC 进行三层 IP 通信。

1. **获取方式**：
    
    - **DHCP 动态分配（主流工程实践）**：AP 默认开启 DHCP 客户端，向接入交换机发送 `DHCP Discover` 报文，由核心/汇聚交换机或独立 DHCP 服务器分配管理网段 IP。
        
    - **静态预配置（特殊场景）**：通过 Console 口或本地 Web 预先为 AP 烧录静态 IP、子网掩码与默认网关。

2. **报文交互细节**：
    
    - AP 连接的接入交换机端口通常设置为 Trunk，PVID 设为管理 VLAN（如 VLAN 10），此时发往 AP 的 DHCP 响应报文会被剥离 VLAN 标签，AP 处于 Untagged 环境中获取 IP。

#### 阶段二：AC 发现机制与选主（Discovery）

==获取 IP 后，AP 进入 CAPWAP **Discovery** 状态，主动寻找网络中的 AC 控制器==。


1. 发现机制分类

AP 按照本地策略依次或并行触发以下发现方式：

- **静态单播发现**：AP 内部预存了 AC 的静态 IP 地址列表，直接向目标 AC 发送单播 `Discovery Request`。
    
- **广播/组播动态发现（二层网络）**：
    
    - AP 向受限广播地址 `255.255.255.255` 发送目标 UDP 端口为 **5246** 的 `Discovery Request` 报文。
        
    - 仅适用于 AP 与 AC 处于同一二层广播域（同一 VLAN）的扁平网络。若跨三层路由器，广播报文默认被丢弃。

- **DHCP Option 43 动态发现（跨三层网络主流方案）**：
    
    - 在跨网段组网中，DHCP 服务器在给 AP 回复 `DHCP Offer / ACK` 时，在 **Option 43** 字段中附带 AC 的管理 IP 地址。
        
    - AP 解析 Option 43 提取出 AC 的 IP 地址，随后直接发起跨网段的单播 `Discovery Request`。

- **DNS 域名解析动态发现**：
    
    - DHCP 服务器通过 Option 15 下发域名后缀（如 `corp.local`），AP 自动拼接预设主机名（如 `wlan-ac.corp.local`），向本地 DNS 服务器发起 A 记录查询，获取解析到的 AC IP 地址。常用于分支机构跨广域网/公网连接总部 AC。
        


2. AC 选主机制

当 AP 收到多个 AC 回复的 `Discovery Response` 报文时，触发选主逻辑：

1. **预配置优先级（AP 静态指定的主备 AC）**：优先选择被指定为 Active 的主 AC。
    
2. **AC 负载权重（Load Balancing）**：比较各 AC 当前纳管的 AP 数量及空闲容量，选择负载最低的 AC。
    
3. **IP 地址大小**：若无其他优先级策略，优先选择 IP 地址数值较小的 AC





#### 阶段三：CAPWAP 隧道建立与认证（Join）

==选定目标 AC 后，AP 向该 AC 发送 `Join Request` 报文，进入 **Join** 状态==



1. **身份认证与准入鉴权**：
    
    - AC 收到请求后，提取报文中 AP 的 **MAC 地址** 与 **序列号（SN）**。
        
    - **白名单认证（MAC/SN 认证）**：若 AC 配置了严格准入，仅允许预先在 AC 上离线录入的 AP 接入；未授权设备被丢弃并触发非法 AP 告警。
        
    - **免认证模式（Auto-Enrollment）**：实验室或调试环境下，AC 自动信任接入的所有物理 AP。

2. **DTLS 加密控制信道（可选）**：
    
    - 建立安全传输层协议（DTLS）隧道，确保后续下发的射频配置、密钥信息在有线链路中不可被窃听与伪造



![](Pasted%20image%2020261110124245.png)

- CAPWAP隧道可以实现：
	- AP与AC间的状态维护；
	- AC对AP进行管理和业务配置下发；
	- 业务数据经过CAPWAP隧道集中到AC上转发。
- AP发现AC阶段：
	- 静态方式：AP上预先配置了AC的静态IP地址列表。AP上线时，AP分别发送Discovery Request单播报文到所有预配置列表对应IP地址的AC。然后AP通过接收到AC返回的Discovery Response报文，选择一个AC开始建立CAPWAP隧道。
	- 动态方式：分为DHCP方式、DNS方式和广播方式，其中本章主要介绍DHCP方式和广播方式。
